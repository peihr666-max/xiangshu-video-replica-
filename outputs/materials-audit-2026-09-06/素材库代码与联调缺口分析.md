# 素材库代码与联调缺口分析

审查日期：2026-09-06。范围：当前 Studio 素材库的图片、视频、音频，以及上传、预览、创作引用、任务结果回流。人物库、爆款库仅作为关联来源；文案库不自动扩入本轮范围。

代码基线：`codex/frontend-v1.4`，HEAD `e930909`，加审查时已有的未提交工作区修改。第 1–8 节记录初始审查快照；第 9 节记录随后实施与复验结果。源码/自动化验证不代表部署或生产验收。

> 2026-09-06 实施状态：初审发现的统一素材 API、通用上传、服务端分页、按 ID 恢复、口播 owner/type 权限、本人结果读取、创作引用、结果状态区分、重命名/分组/隐藏、搜索/来源筛选及下载已补齐。口播创作页已接通本地 MP3 直传。新 H3 成片会下载并归档到应用当前存储，归档成功后才登记资产和结算；失败保留供应商结果地址并进入有限次数的归档重试。项目素材与成片的 180 天自动过期规则已从代码策略移除，改为永久保存。腾讯云主账号控制台已删除生产桶中的两条历史规则，整页刷新后规则表为 0 条，真实生命周期变更达到 `REAL_CHAIN_VERIFIED`。应用 API 凭据仍返回 `403 AccessDenied`，后续自动管理生命周期前仍需补权限。

## 1. 结论

素材库已有页面、部分真实资产展示、媒体播放器与创作选择器；后端也已有 assets、存储、鉴权、项目视频上传及任务结果接口。但是，统一素材列表、通用上传、素材管理和持久回流尚未形成闭环。当前不能按“只差配置 API 地址或凭据”安排联调。

完成程度应按层区分：

| 层级 | 当前判断 |
|---|---|
| 页面与基础交互 | 已有主体；缺上传操作、图片/视频用于创作动作、搜索和管理功能 |
| 底层媒体能力 | 有可复用实现；参考视频上传有特定业务限制 |
| 素材库业务 API | 缺统一列表、通用上传、重命名/移除等契约 |
| 创作消费 | 选择器能写草稿；音频正式来源缺失，独立视频创作提交仍未接通 |
| 刷新与结果恢复 | 云草稿已接通，但素材引用回填和结果列表恢复不足 |
| 权限衔接 | 复现普通用户自己的口播成片读取失败，以及口播接收外来/错误类型资产 |
| 端到端完成 | 尚未证明；本次仅源码、OpenAPI、专项测试和隔离复现 |

## 3. 正式素材数据的真实来源

`loadStudioData` 目前不是调用一个素材库接口，而是客户端拼接若干业务来源。

| 来源 | 加载范围与限制 | 证据 |
|---|---|---|
| 项目参考视频 | 截取 24 个项目；只为前 8 个有参考视频的项目读取预览 URL | `client/src/studio/live.ts:51,155` |
| 人物基础图 | 截取 8 人，主要加入五视图合成图 | `live.ts:237` |
| 人物场景照 | 访问人物相关页面或选中人物后加载；每人最多 12 个场景，每场景选一张 | `live.ts:634`；`StudioWorkspace.tsx:329` |
| H3 任务结果 | 任务详情按需读取首个可用结果；初始素材列表不聚合全部结果 | `live.ts:62,438`；`MainPages.tsx:791` |
| 口播任务结果 | 任务有 `resultId`，预览时走通用资产下载 URL | `live.ts:65`；存在第 5 节的权限缺口 |
| 音频 | 正式资产构造路径没有 `kind: "audio"`；审核示例有音频 | `live.ts`；`fixtures.ts:115` |

因此，页面“共 N 条”只代表当前已加载集合，不能解释为用户全部素材数。翻页也不能突破上述截取范围。

云草稿现在已经支持自动保存和恢复，旧审计中“草稿只有内存”的结论不再适用。但保存 `audioId`、`referenceIds` 等 ID，并不会自动恢复这些资产的名称、类型、预览地址和有效状态。当前恢复后没有通用的按 ID 补取机制；引用超出加载范围、临时结果或音频时，仍可能有 ID 而找不到素材。证据：`StudioWorkspace.tsx:188,205,413`；`live.ts:537`。

## 4. 后端可以复用什么

以下端点已通过当前应用 OpenAPI 导出核实：

| 端点/能力 | 可以复用的部分 | 必须保留的业务边界 |
|---|---|---|
| `GET /api/assets/{asset_id}` | 单资产读取 | 返回基础文件字段；没有统一素材列表/标题/操作能力契约 |
| `POST /api/assets/{asset_id}/download-url` | 授权预览与下载地址 | 新的无项目素材类型需要匹配 owner 权限 |
| `POST /api/assets/{asset_id}/cached-url` | 人物图片缓存 | 不是通用媒体管理接口 |
| `POST /api/assets/upload-intent` → PUT → `POST /api/assets/{asset_id}/complete` | 上传意图、存储写入、完成确认、错误与审计机制 | 强制 project_id，固定 reference_video，MP4/MOV、最大 50 MB、4–15 秒；不能照搬到通用音频/图片 |
| `GET /api/generation-batches` | 分页获取生成任务及结果来源 | 必须同时理解资产结果与 DIRECT 结果 |
| `GET /api/generation-tasks/{task_id}/preview-url` | 当前 H3 直出结果预览 | 供应商结果链接不等于平台长期托管资产 |
| `GET /api/oral/tasks`、`GET /api/oral/tasks/{task_id}` | 口播任务与结果 ID | 列表只有 limit；读取单任务会刷新状态，可能产生写操作 |
| `POST /api/oral/tasks` | 音频或文案口播消费入口 | 音频上传来源和资产权限/类型校验尚需补齐 |
| `GET/PUT/DELETE /api/studio/drafts/{draft_kind}` | 草稿持久化 | 不等于素材文件或素材索引持久化 |

存储继续复用现有 `StorageAdapter`、COS 和内部本地模式；资源访问继续复用现有鉴权及客户 session/fencing 体系，无需为素材库新建另一套文件存储或登录机制。

OpenAPI 当前没有通用素材列表、素材重命名、素材删除、独立音频上传接口。已有项目删除和任务隐藏都有自己的语义，不能直接拿来接素材卡片删除。

## 5. 联调前需优先处理的问题

### P0：口播输入资产归属与类型校验不完整

`oral.py:68` 的 `_asset` 只查 ID，不接收 actor；`create_oral_task` 的 AUDIO 分支在 `oral.py:264` 只检查资产存在。人物和分身属于当前用户，不代表音频也属于该用户。分身/声音克隆入口同样采用这条资产读取路径（`oral.py:108,155`）。

隔离复现结果：通用权限检查拒绝的另一用户项目音频，仍被 AUDIO 口播创建逻辑接收；视频资产也能作为 AUDIO 输入接收。本次把真正提交替换为 mock，只证明领域校验会放行，未调用真实供应商。

修复出口：用户 A 的素材对用户 B 的详情、下载、引用、克隆和口播提交均拒绝；音频入口拒绝实际类型错误、未完成或失效资产。

### P0：普通用户自己的口播成片无法通过通用资产权限

口播归档写入 `project_id=NULL, kind=oral_video, created_by_user_id=owner`（`oral.py:465`）。而 `permissions.py:277` 对无项目资产主要沿人物授权关系判断，没有对应口播 owner 分支。

隔离数据库已复现：普通用户读取自己创建的这种口播结果时，`require_asset_access` 返回 404。前端口播预览正使用通用下载 URL 路径，因此这会阻断预览与素材库复用。

修复出口：按口播任务与当前账户验证所属关系，允许本人读取；另一用户仍得到不可枚举的拒绝结果。管理员测试通过不能替代普通客户测试。

### P1：当前 H3 直出结果与平台素材 ID 没有统一契约

`generation.py:4677` 的 DIRECT 路径明确保存 `provider_result_url`，设置 `result_asset_id=NULL`。前端临时命名为 `direct-task-{task_id}`（`live.ts:97`），它不是 assets 表 ID。

统一列表若只查 assets 会漏当前成片；将该临时 ID 当作 asset_id 提交消费接口也不成立。`generation.py:5288` 的 `has_results` 仍只检查 result_asset_id，亦需对齐 DIRECT 语义。

目前前端给 DIRECT 结果 `saved:false`，素材卡片却把所有 false 显示成“处理中”（`ContentPages.tsx:648,766`），会把已完成但未托管的结果错误显示为仍在处理。

建议保留现有直出交付决策，先让素材索引区分“平台文件”与“任务直链结果”，分别保留稳定来源 ID、播放方式、实际状态与可用操作。若产品另要求长期托管，再独立确定保存流程；本轮不擅自恢复全量 COS 归档。

### P1：引用恢复、选择规则与状态不完整

选择器主要按类型和人物过滤，没有统一的真实就绪/可用动作校验（`StudioWorkspace.tsx:1061`）。不能简单用 `saved` 做 gate，因为可播放直出成片与未完成上传的语义不同。

需补：草稿引用按 ID 回填；链接失效重签；不可用素材明确提示；普通图片与人物照片按用途选取；素材库到创作页和任务“更换素材”的返回目标完整保留。通用音频未关联人物时，使用它也应避免无意清空当前已选人物。

### 客户模式与播放器的待验证项

- 口播 refresh 和单任务 GET 可能更新任务或归档资产，目前使用普通 Database；需补客户会话被顶替/失效后的事务内 fencing 检查。证据：`oral_routes.py:116,175,251`。
- 通用签名对象代理完整读取 bytes、返回 attachment，未见 Range 支持；应实测视频/音频拖动播放、大文件与 URL 过期，不把存在 URL 直接视为播放器验收完成。证据：`media_routes.py:355`。

## 6. 达到联调闭环需要的工作包

下表为建议，不是已冻结的新任务编号或文件映射。

| 顺序 | 工作内容 | 完成出口 |
|---|---|---|
| 1 | 统一素材数据契约和权限；修复第 5 节两个 P0 | 明确稳定 ID、媒体类型、来源、owner、项目/人物/任务关联、状态、文件信息、预览方式和可用动作；本人可用、他人不可用 |
| 2 | 统一读取列表、详情、按 ID 回填、服务端分页 | 用户可读全部可见素材；刷新、重登、跨页后不因前端截取而丢记录；空态和错误态清晰 |
| 3 | 通用图片/音频/视频上传 | 选择文件→校验→进度→完成→记录入列表→刷新仍可见；失败/取消可恢复；独立素材不强绑虚构项目 |
| 4 | 创作引用与返回 | 素材页提供按类型的“用于…”动作；传真实 ID；草稿恢复能找回素材；音频进入已有口播接口；错误类型被两端拒绝 |
| 5 | 结果回流与状态映射 | 新 H3 结果归档为平台资产；历史 DIRECT 结果继续兼容展示；不再依赖手工预览追加 |
| 6 | 基础管理 | 重命名、下载、搜索、移除；明确从库隐藏和物理删除边界；被项目/人物/任务引用时有保护和反馈 |
| 7 | 浏览器及客户模式联调 | API、存储、预览、草稿恢复、越权拒绝、会话失效、失败重试的证据齐全 |

开始第一轮联调只需先完成工作包 1–3，可用隔离本地存储验证“上传→列表→预览→刷新”。不必等待真实付费生成。

完成整个素材库使用闭环需要工作包 4–7。独立文生/图生/参考生视频的真实提交属于消费端另一项缺口（`StudioWorkspace.tsx:868`），不能因素材可选就标记整条生成流程已完成；可先接已存在的项目流程和音频口播流程。

最小闭环中搜索与服务端分页应形成明确契约；批量管理、自定义标签/目录、收藏、真实音频波形等增强功能没有必要挡住首轮上传联调，也不能默认加入本轮开发范围。

## 7. 联调环境与验收用例

前端开发服务配置为 `127.0.0.1:5173`；API 默认 `127.0.0.1:8000`，可由 `VITE_API_BASE_URL` 覆盖（`client/vite.config.ts`、`client/src/api.ts:35`）。后端已有 5173 和 Tauri 的 CORS origins（`server/app/main.py:275`）。本次核实的是配置代码，没有证明当前进程和实际凭据已可用。

应使用正式登录后的工作区或 `/customer` 客户入口验证；DEV `/review/v1.4` 故意使用审核数据，不调用业务 API，不能作为联调证据。

验收至少包含：

1. 图片、音频、通用视频各上传一份，完成后得到真实 ID、元数据和可播放地址。
2. 文件超限、类型伪装、上传中断、重复完成、存储不可用时，有明确错误与恢复路径。
3. 刷新、退出重登后仍能看到记录；超过一页后列表可继续加载，不受项目/人物截取上限影响。
4. 图片进入对应创作字段；音频进入 AUDIO 口播；视频作为正确的参考来源。回到原页面后引用正确。
5. 草稿引用存在但不在首页数据中时，仍能按 ID 恢复；已移除或不可用素材明确报错。
6. 新 H3 归档成片、历史 DIRECT 成片和口播归档成片均能展示；不同批次的全部结果不会被压成一个。
7. 用户 B 无法读取、签名、引用或提交用户 A 的资产；普通 owner 能读自己的口播成片。
8. 客户会话被顶替或失效后，素材写入/状态刷新不能继续成功；只读角色不能进行写操作。
9. 链接过期可恢复；视频/音频播放、拖动与下载在浏览器和实际桌面环境分别验收。
10. 素材移除不破坏仍在使用的项目/人物/任务快照，不通过素材操作删除账务历史。

## 9. 实施更新与当前边界
