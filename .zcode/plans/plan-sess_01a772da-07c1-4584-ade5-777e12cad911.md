## 模块 ①视频复刻（分支 `feat/studio-replica-flow`，2 步）
现状：ReplicaPage 是壳（分镜占位、"进入分镜工作区"跳成熟工作区）。目标：studio 内走完复刻流程，Prompt 为一等输出。

**Step 1 来源与拆解**：
- 上传参考视频（把工作台直传提取为 live.ts 共享函数：createProject→upload-intent→upload→complete）或选择已有项目；修正 draft.projectId/sourceId 断点（含收编工作区遗留的 identityId 修复）。
- "启动 AI 拆解"（POST `/api/projects/{id}/analysis-tasks`，api 函数现成）+ 轮询任务态 → 完成后加载分镜（GET shot-cards/latest）→ 分镜卡列表（时间/景别/主体/动作/台词）只读确认。

**Step 2 Prompt 输出与送生成**：
- "生成拆解 Prompt"：POST prompts/compile → PromptMarkdown 展示（复用现成组件）+ 复制 + 保存到"我的提示词"（saved-prompts 端点现成）。
- "送生成"：项目已有确认首帧 → 直接建批（createGenerationBatch，复刻流原语义）；无首帧 → 引导去人物替换页。报价复用 price-quote + 确认弹窗接上"视频复刻"分支。
- 测试：上传/选项目、拆解启动+轮询、分镜渲染、Prompt 编译展示/保存、建批与无首帧引导。

## 模块 ②人物替换（分支 `feat/studio-replacement-flow`，1-2 步）
现状：ReplacementPage 纯占位、frameConfirmed 无置 true 路径。目标：studio 内完成"提首帧 → 选 IP → 置换首帧 → 确认可用"。

**Step 1 置换流程化**：
- 选项目（需已拆解的单人视频项目；未拆解给引导）→ 源画面提取与确认（复用 SourceFrameSelection 组件或按其端点轻封装：POST source-frames/extract → 轮询 → confirm）。
- IP 与五视图参考：人物版本/参考选择（CharacterSelection + CharacterReferenceSelection 组件或轻封装，含 recommendation 端点）。
- 生成置换首帧（POST first-frame-tasks + 轮询 active-or-latest，30 分钟等待语义沿用）→ 候选卡展示（含质检标注，未过质检确认需 allow_unverified 语义透出）→ confirm。
- 确认成功 `patchDraft({ firstFrameId: 选中资产, frameConfirmed: true })`（补置 true 路径）；「用于文/图生视频」跳 i2v（`first_frame` kind 已在 C2 白名单；本地存储时透出 COS 要求文案）。
- 组件复用策略：SourceFrameSelection / CharacterReferenceSelection / FirstFrameSelection 均被 AnalysisWorkspace 与 ProjectDetailFlow 两处复用（已解耦的叶子组件），优先直接嵌入 studio 页（LiveWorkspacePanel 已有嵌旧组件先例）；props 耦合过重的才轻封装。
- 测试：项目加载与引导态、提取/确认源画面、生成+轮询+确认、frameConfirmed 置位、跳视频生成带首帧。

## 每模块固定流程
1. 从共享线切分支 → 测试先行实现 → 专项验证（vitest/biome/tsc）。
2. **代码评审**：派 code-reviewer 审模块 diff，逐条实质修复。
3. 全量门禁（`npm run check`，PG fixture 起）→ **merge 回共享线（--no-ff）**。
4. 共享工作区有并行会话在途编辑：门禁被其在途文件打红时如实区分归属并标注，不代收口。

## 收尾
两模块合流后：更新任务拆解文档与设计实施记录、更新记忆；模块状态回填（复刻/替换 ✅，含各自边界说明）。
