## 阶段三 [P0]：性能核心（需迁移设计，触碰 Alembic 红线）

> ⚠️ 本阶段涉及数据库迁移。按 AGENTS.md 红线"已发布 revision 只可追加修复，不得篡改"，须**新增 revision**（如 `090_*`），不得修改 001/045/046。

### T3.1 时间戳列类型迁移（TEXT → timestamptz）
- **问题**：`locked_until`/`next_poll_at` 在 15 处迁移中为 `sa.Text()`（001_core.py:130-132、045:47、046:33），认领 SQL 做 `locked_until::timestamptz <= now()`（generation.py:5004,5006、image_tasks.py:603,637），CAST 使 B-tree 索引 `(status, locked_until, ...)` 无法用于时间过滤。**全仓 21 文件 85 处 CAST**。
- **约束**：`text::timestamptz` 是 STABLE（依赖会话 TimeZone），**不能建表达式索引**——只能走列类型迁移。
- **动作**：新增 revision 把 `locked_until`/`next_poll_at`（generation_tasks/first_frame_tasks/analysis_tasks 等）改为 `timestamptz`，数据回填（`USING locked_until::timestamptz`，迁移时一次性，会话时区固定 UTC）；认领 SQL 去掉 CAST；与 T37 探针侧协调（探针已显式转 timestamptz，迁移后探针可简化）。
- **验收**：`EXPLAIN ANALYZE` 确认认领查询走 `idx_generation_tasks_lease` 索引（无 Seq Scan）；worker 空载 DB QPS 前后对比；T27 队列压测回归（10k 任务恰好一次、零死锁）。
- **风险**：高。涉及多表列类型变更 + 数据回填 + 索引重建；须先在 staging 验证；迁移文件名冻结红线。

### T3.2 Worker 空闲指数退避
- **问题**：generation_worker.py:1902 `--idle-seconds` 默认 `1.0`，无任务时每秒执行全量认领/过期扫描，是 T3.1 的频率乘数。
- **动作**：空闲改指数退避（1s→5s→15s 封顶）或 LISTEN/NOTIFY 唤醒；保留 `--idle-seconds` 作为退避基数。
- **验收**：worker 空载 CPU/DB QPS 显著下降；任务到达后唤醒延迟 ≤ 退避上限。

### T3.3 audit-logs 加过滤/分页 + 索引
- **问题**：rbac_routes.py:1180-1186 `SELECT ... FROM audit_logs ORDER BY created_at, id` 无 WHERE、无 LIMIT，全表扫描 + 全量排序；042 索引前缀 `(action, occurred_at, id)` 不匹配。
- **动作**：强制时间范围/分页参数；新增 revision 建 `(created_at, id)` 索引。
- **验收**：`EXPLAIN` 走索引；大表下响应时间有界；审计页功能不变（默认时间窗）。

**阶段三验收门**：迁移升降级全链验证（T06 模式）；T27 队列压测回归；`EXPLAIN ANALYZE` 证据；staging 验证后方可标 AUTOMATED_VERIFIED+。
