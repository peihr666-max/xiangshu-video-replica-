## 1. 排查范围与方法

- **前端**：`client/src/AdminApp.tsx`（含登录门、恢复密码、设密三个认证 phase）+ `client/src/admin/**`（22 个页面/区块文件 + `ui/` 组件族）。
- **后端**：`server/app/control_auth.py`（控制面身份适配）、`server/app/control_routes.py`（账务/设置控制面）、`server/app/admin_*_routes.py`（11 个路由族：auth/activation/audit/customer/dashboard/device/profit/rate/runtime/session/write_contract）。
- **方法**：按"页面 → 路由族 → 认证/RBAC 链"逐层走查，重点核对前端交互假设与后端安全语义是否一致。

## 3. 问题清单（按优先级）

### P0 — 本任务修复：管理端产线包缺失整份基础样式表

**现象与证据**（基线 a093f61 实测重建 `dist-admin`）：管理端产物 CSS 仅 16.57 kB，全部来自各页面的补充样式（economics/admin-audit/admin-sessions/admin-activation/admin-customer-detail 五个 css）；基础样式表 `client/src/styles.css`（6456+ 行，含 `.admin-shell` 壳层布局、`.admin-panel`/`.admin-form`、全局 `input`/`button` 规则、`settings-error`/`wallet-notice` 提示横幅、`--admin-*` 全部设计令牌定义）**只被客户壳 `App.tsx` 一处导入**。产物比对：

| 断言 | 管理包 `dist-admin/assets/*.css` | 客户包 `dist/assets/*.css` |
| --- | --- | --- |
| `.admin-shell{` 基础定义 | **0 次** | 2 次 |
| `--admin-bg` 令牌定义 | **0 次** | 有 |
| `--admin-text`/`--admin-line-soft`/`--admin-muted`/`--admin-gold` 定义 | **0 次** | 有 |

页面级 `admin-activation.css`、`admin-customer-detail.css` 引用的 `var(--admin-text)` 等变量在管理包中**未定义**——边框、文字颜色全部落空。即 CW-019 拆分双入口（2026-09-10 合入）后，管理后台在产线（nginx alias dist-admin）与本地 dev（/admin 重写同一入口链）都以"半裸样式"渲染：壳层背景、侧栏布局、表单控件、错误横幅样式全部缺失，登录页首当其冲。CW-019 的验收断言是"客户包不含管理代码"（排除向），没有"管理包含自身基础样式"（包含向）断言，回归因此漏网。

**修复**：管理端挂载文件 `admin-main.tsx` 显式 `import "./styles.css";`，并在 `entryContract.test.ts` 加源码层契约测试钉住（防再回归）。不影响客户包（styles.css 本就在客户依赖图内），不违反"客户制品不含管理代码"红线。

### P1 — 本任务修复

1. **登录提交无加载态、无防重复提交**（前端 × 后端限流的真实联动问题）。
   `AdminApp.tsx` 的 `signInWithPassword` 是裸 async：双击"登录后台"会并发发起两次登录请求。后端按 **IP + 账号双维度**计数每次尝试（`admin_auth_routes._spend_admin_password_budget`），双击等于白烧两份预算；在限流阈值本来就不高的管理端场景，管理员可能在不知情中把自己锁在门外（429）。行业通行做法是提交中禁用按钮并给加载文案。
2. **`RATE_LIMITED`（429）与 `ADMIN_SESSION_CONTEXT_CHANGED`（401）无中文映射**。
   `api.admin.ts` 的 `CODE_MESSAGES` 未收录这两个码：限流时管理员看到的是服务端英文原文（"Too many administrator sign-in attempts. Try again later."），上下文变化时同理。客户版 UI 全中文是既定要求（与供应商名称红线同类的文案纪律）。`adminActivationErrorMessage` 已支持 `overrides` 参数，可零服务端改动在前端补映射。
3. **登录界面贫弱**：无品牌呈现（仅一行文字标题）、错误横幅渲染在远离表单的页面顶部、无密码可见性切换、无自动聚焦、恢复密码/设密表单同构问题。作为管理端的第一印象页与高频入口，与后台其余页面的精致度落差明显。

### P2 — 登记在案，不在本任务范围

4. **会话上下文绑定对办公网络的友好性**：后端对 IP/UA 变化零容忍（变化即吊销）。出口 IP 漂移的办公网络下可能表现为"频繁被登出"。这是安全语义取舍，放宽与否属安全决策，需用户拍板；本任务仅在前端明示该机制。
5. **客户项目列表前端截断**（`listProjects` 无分页参数、后端无分页端点，前端 `slice(0,24)`）——CW-018 已如实登记，属客户端后端分页独立任务，管理端生成记录页已有分页不受影响。
6. **恢复凭据输入**仅以 placeholder 提示 `ASX1.…` 格式，无粘贴前后空格的显式反馈（代码里已有 `.trim()`，仅缺提示层）。
7. **recovery / password-setup 表单**无自动聚焦，逐表单补齐属于打磨项，本任务一并覆盖登录表单，其余两个表单随卡片布局顺带补齐。

### 观察项（不构成问题）

- 审计员只读在前端 `readOnly` 与后端 `get_admin_writer` 双侧强制，口径一致。
- 路由 intent 走白名单（`adminIntents`），未命中回退总览，无注入面。
- 登录成功后按当前 hash 恢复目标模块，深链体验正确。

## 4. 登录界面改造方案（参考同行优秀做法）

参考对象：Stripe Dashboard、Vercel、Linear、阿里云 RAM 控制台等运营/管理后台登录页的共性做法：

1. **独立登录门（gate）布局**：认证阶段不再复用工作台的 `admin-shell` 页头，改为整屏居中的登录卡——左侧品牌价值区（品牌标 + 产品名 + 安全语义说明），右侧表单；窄屏折叠为单列。沿用后台既有深色 + 金色设计令牌（`--admin-*`），不引入第三套视觉体系。
2. **表单细节**：
   - 密码可见性切换（`aria-pressed` 标注状态）；
   - 提交中禁用按钮 + "正在登录…"文案（修复 P1-1）；
   - 错误内联渲染在表单卡内，保留 `role="alert"`（修复 P1-3，读屏即时播报语义不回退）；
   - 自动聚焦第一个输入框；`autocomplete` 语义保留（`username` / `current-password` / `new-password` / `off`）。
3. **错误全量中文化**（修复 P1-2）：在 `AdminApp` 调用 `adminActivationErrorMessage` 时以 `overrides` 补 `RATE_LIMITED`、`ADMIN_SESSION_CONTEXT_CHANGED` 两个码；不动 `api.admin.ts` 的全局映射表，避免影响其他页面已锁定的测试与文案。
4. **安全语义明示**：登录卡明示"会话绑定当前浏览器与网络环境，环境变化需重新登录"，对齐后端 context-binding 行为，减少 P2-4 场景下的困惑；恢复凭据说明文案保留既有措辞（一次性、不能作为日常登录方式）。
