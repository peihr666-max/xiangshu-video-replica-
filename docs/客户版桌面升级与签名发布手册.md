# 客户版桌面升级与签名发布手册（CW-024）

本手册承接 CW-011「唯一客户构建和安装升级契约」，由 CW-024 落地并配套合同测试
`server/tests/test_cw024_signed_release_upgrade_contracts.py`（先红后绿）。

边界声明：本手册及对应实现的目标层级为 `AUTOMATED_VERIFIED`——**真实签名实机
验收（签名安装/升级/重装/失败恢复实机验证）归 CW-046**，**真实存量旧数据切换
归 CW-051**。本手册不声明实机升级或生产发布已完成。

## 1. 唯一制品与渠道标注

- 客户发行物只有一条渠道：`signed-release`（经 `npm run release:customer` 产出，
  见 §5）。制品目录含 `release-manifest.json`，记录**版本、平台、签名与 SHA**。
- CI（`.github/workflows/ci.yml` windows-nsis job）构建的安装包是无签名的合同
  测试制品：归档目录为 `customer-cloud-internal-test-unsigned`，并写入机器可读
  渠道标签 `RELEASE-CHANNEL.txt`（内容 `internal-test-unsigned`）。
  **未签名包只能标内部测试，禁止向客户分发。**
- workflow 内不允许出现任何签名材料（合同测试断言
  `TAURI_SIGNING_PRIVATE_KEY`/`certificateThumbprint`/`signtool` 零出现）；
  签名输入只经 §5 的临时 overlay 进入构建，构建后即删。

## 2. 受支持版本与旧安装路径矩阵

CW-003 冻结的受支持版本：**0.1.12 / 0.1.13 / 0.1.15 / 0.1.16**（0.1.14 跳过无发布）。
按 git 史实（`81f153a`/`d9a5576`/`bc0248e`/`80a8e40`/`59e10ed`/`1fb997a`），
各版本均为 NSIS `currentUser` 安装，实际产生**两条**旧安装路径：

| 旧版代次 | 覆盖版本 | 旧安装目录（per-user） | 备份目录 |
| --- | --- | --- | --- |
| 生成 1（原名） | 0.1.12 / 0.1.13 / 0.1.15 / 0.1.16（#92 发布） | `%LOCALAPPDATA%\短视频复刻工作台` | `%LOCALAPPDATA%\短视频复刻客户云工作台\legacy-backup\短视频复刻工作台` |
| 生成 2（W1 品牌替换，1fb997a） | 0.1.16（品牌替换版） | `%LOCALAPPDATA%\众墅之家` | `%LOCALAPPDATA%\短视频复刻客户云工作台\legacy-backup\众墅之家` |

客户云工作台自身安装于 `%LOCALAPPDATA%\短视频复刻客户云工作台`；其升级走 Tauri
常规覆盖流程（`allowDowngrades: false`），不经过旧版迁移钩子。

## 3. 升级行为矩阵（安装钩子合同）

安装钩子 `client/src-tauri/customer-installer-hooks.nsh` 对**每一条**旧安装路径
独立执行以下顺序（任一步失败即中止，且不产生不可恢复状态）：

| # | 步骤 | 失败行为 |
| --- | --- | --- |
| 1 | 存在性检测（`uninstall.exe`） | 不存在→跳过该路径 |
| 2 | 运行实例守卫：优先对旧版主程序（`<旧版名>.exe`）做写模式打开（运行中的可执行映像被 Windows 锁定，写打开即失败），主程序不存在时回退探测 `uninstall.exe` | 弹窗「旧版正在运行或文件被占用」→ **Abort，零改动** |
| 3 | 完整归档：`CopyFiles` 整个旧安装目录 → 备份目录 | 弹窗「备份失败」→ **Abort，旧版未被改动** |
| 4 | 归档校验：备份目录内 `uninstall.exe` 必须存在 | 校验失败→ **Abort，旧版未被改动** |
| 5 | 写 `LEGACY-BACKUP-MANIFEST.txt`（旧版标识/来源路径/覆盖版本/归档者） | 写失败→ **Abort，旧版未被改动** |
| 6 | 静默卸载旧版（`ExecWait` + 退出码校验） | 执行错误或退出码非 0 → **Abort，保留可读备份**（见 §4 恢复） |

验收底线对应关系：所有实际支持路径有覆盖（§2）；未经已验证归档不先卸载（步骤
3–5 先于步骤 6）；失败可恢复旧客户或保留可读数据（§4）；支持版本不重复占设备
（两条路径全部处理后才会继续安装）。

## 4. 回滚与恢复

适用场景：步骤 6 卸载失败中止后，用户要求恢复旧版；或客户云工作台安装成功但
需回退到旧版。

1. 确认备份存在：`%LOCALAPPDATA%\短视频复刻客户云工作台\legacy-backup\<旧版名>\`
   内含完整旧安装文件与 `LEGACY-BACKUP-MANIFEST.txt`（记录来源路径与覆盖版本）。
2. 恢复旧版：将备份目录内容复制回原安装目录，例如
   `xcopy /E /H /Y "%LOCALAPPDATA%\短视频复刻客户云工作台\legacy-backup\短视频复刻工作台" "%LOCALAPPDATA%\短视频复刻工作台\"`
   （众墅之家代次同理）。
3. 恢复后可直接运行旧版 `uninstall.exe` 重新走一次受控卸载，或重新运行客户云
   安装程序（钩子会重新执行 §3 完整流程）。
4. 两条旧路径互相独立：某一路径失败不影响另一路径的处理；已成功归档的路径
   数据始终可读。

## 5. 唯一签名发布流程

前置条件（全部满足才可能出制品）：

- Windows 发布机，证书（含私钥）已装入用户/机器证书存储，拿到其
  Authenticode thumbprint；
- 已批准的真实云端 HTTPS origin（客户 API 地址）；
- 发布机可访问时间戳服务（默认 `http://timestamp.digicert.com`，可用
  `-TimestampUrl` 覆盖）。

执行：

```powershell
$env:VIDEO_REPLICA_RELEASE_SIGN_THUMBPRINT = "<证书指纹>"
$env:VITE_API_BASE_URL = "https://<已批准的云端 origin>"
# 可选：签名主体校验，防止挂错证书
$env:VIDEO_REPLICA_RELEASE_EXPECTED_SIGNER = "<证书主体须包含的子串>"
npm run release:customer
```

脚本行为（`scripts/release/build-customer-signed-release.ps1`，fail-closed）：

1. 缺 `VIDEO_REPLICA_RELEASE_SIGN_THUMBPRINT` 或 `VITE_API_BASE_URL` → 直接
   throw，**不出任何制品**；
2. 版本一致性门：`tauri.conf.json`/`package.json`/`client/package.json`/
   `package-lock.json`（根与 packages.client）/`Cargo.toml`/`pyproject.toml`
   六处版本必须全等；
3. 经 `require:customer-api-base` 校验 origin 可路由且非回环；
4. 以临时 overlay 注入 `certificateThumbprint`/`digestAlgorithm`/`timestampUrl`
   构建（**不含**无签名构建旗标），构建后 overlay 即删；
5. `Get-AuthenticodeSignature` 校验产物签名状态必须为 `Valid`（可按
   `VIDEO_REPLICA_RELEASE_EXPECTED_SIGNER` 校验签名主体），否则中止且**不产出
   未签名发行物**；
6. 产出 `dist-release/customer-cloud/<版本>/`：安装包 + `SHA256SUMS.txt` +
   `release-manifest.json`（`channel=signed-release`、version、
   `platform=windows-x86_64`、artifact、sha256、signature{status/subject/
   thumbprint/timestampUrl}、generatedAt）。

## 6. 凭据与数据保护边界

- CW-003 冻结的凭据命名空间：Windows 侧为 DPAPI 加密信封（app data 下，
  `customer_credentials.rs`）+ identifier 注册表镜像；`device-instance-id` 为
  稳定标识（非凭据，`clear_all` 不删除）。
- 上述命名空间全部位于旧安装目录**之外**；安装钩子只处理
  `%LOCALAPPDATA%` 下的旧安装目录本身，不触碰 `$APPDATA` 与注册表，凭据不丢。
- 旧版业务数据（本地库/素材）随安装目录整体归档（§3 步骤 3），保持可读；
  **真实旧数据切换（迁移进客户云）归 CW-051**，本任务不迁移、不改写。
