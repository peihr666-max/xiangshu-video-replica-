# 人物 IP 与数字人口播落地方案 V1

> 更新日期：2026-09-06  
> 适用范围：人物库、IP 定位、五视图、场景形象、声音克隆、口播分身、数字人口播成片。

## 1. 结论

当前项目已经不是“只有界面没有后端”，人物库的主干、人物 IP 档案、照片分身、声音克隆和数字人口播都已有后端领域模型和 API。但“代码存在”不等于“真实供应商链路已验收”：当前本机没有配置数字人供应商密钥，因此只能确认到 `AUTOMATED_VERIFIED`，不能标记 `REAL_CHAIN_VERIFIED` 或 `PRODUCTION_GO`。

建议将人物库定义为同一个“人物数字身份根”：

1. 上传一张本人或已授权图片，创建人物身份。
2. 生成一张五视图拼合图，作为基准形象。
3. 根据不同场景和服装生成新的场景五视图，但不创建新人物。
4. 在同一人物下维护 IP 定位、声音版本和数字人分身。
5. 用“人物 + 场景形象 + 口播分身 + 声音/完整音频 + 文案”生成成片。

## 2. 五视图产品口径

对用户只展示“一张五视图拼合图”：

- 正面全身
- 45 度全身
- 侧面全身
- 正面近景
- 45 度近景

后端仍保留 7 个标准化内部资产：`FRONT_FULL`、`FRONT_HALF`、`FRONT_FACE`、`LEFT_45`、`LEFT_SIDE`、`RIGHT_45`、`RIGHT_SIDE`。右侧视图由左侧视图镜像兼容生成，是旧项目选角、首帧和视频生成链的内部合同，不应为了前台文案简化而破坏。

### 4.2 后端已有、前端尚未完整用起来

| API | 未闭环点 |
|---|---|
| `POST /api/oral/avatars` 的 `source_kind=VIDEO` | 缺“上传人物视频 → 获得 asset_id → 提交分身”前端链 |
| `GET /api/oral/tasks/{task_id}` | 该接口会向供应商刷新并归档结果，但任务中心目前主要只读列表，缺自动轮询/手动刷新与成片播放闭环 |

### 4.3 尚缺的业务接口

1. 声音样本直传/录音接口（upload-intent + complete）。
2. 人物视频直传/完成接口，用于视频分身。
3. 声音授权同意存证接口，包括同意文本版本、时间、操作人和样本摘要。
4. 声音试听样例生成和“确认使用”接口。当前后端在供应商返回 READY 后自动确认，与最终产品流程不一致。
5. 口播任务取消、可重试错误、归档重试和成片预览/下载的完整接口组。
6. 口播任务钱包 `RESERVE/SETTLE/RELEASE` 结算接口或服务层。当前只有估算价格快照，尚未真正扣费。
7. IP 定位生成建议和“IP 档案 → 文案 Prompt”的明确合同。

## 5. 当前最大的真链路缺口

### P0：不补就不能对外说“数字人已接通”

1. 配置真实数字人供应商密钥，跑通照片分身、声音克隆、TTS 成片、音频驱动成片四条真链。
2. 补人物视频和声音样本直传。
3. 补声音授权、试听、人工确认；禁止 READY 自动变成“用户已确认”。
4. 让任务中心调用单任务刷新接口，展示成片、失败原因和重试动作。
5. 口播任务纳入钱包扣费和退回。

### P1：影响内容质量与可运营性

1. 把 IP 定位作为结构化参数注入文案改写：`role`、`service_scope`、`target_audience`、`expression_style`。
2. 建立 IP 定位版本和文案版本的快照关系，避免后续修改 IP 导致历史成片无法复现。
3. 建立分身/声音/场景图的默认版本、停用、删除、使用中禁删规则。
4. 补操作日志和指标：供应商提交耗时、排队耗时、制作耗时、失败码、归档耗时、扣费结果。

### P2：上线门禁

1. PostgreSQL 与多实例 Worker 下验证 fencing、幂等和重复回调/查询。
2. 真账号、真实人像/声音授权的端到端 UAT。
3. 成片完整下载、解码、时长、声画同步、口型和人物一致性验收。
4. 供应商超时、余额不足、限流、任务丢失和归档失败演练。

## 6. 建议落地顺序

### 增量 A：资产入口和合规（2–3 人日）

- 新增人物视频、声音样本 upload-intent/complete。
- 前端增加拖拽、录音、时长/格式校验和上传进度。
- 新增授权同意记录，声音 READY 与用户 CONFIRMED 分开。
- 验收：未授权、跨账号、类型不匹配、上传未完成均无法提交克隆。

### 增量 B：真实分身和声音（2–3 人日，供应商开通时间另计）

- 照片分身、视频分身、声音克隆各跑 3 组真实样本。
- 固化供应商返回码映射、超时和拉取间隔。
- 生成声音 demo，用户试听后手动确认。
- 验收：每次真实调用留存请求号、任务号尾号、时间、状态和可播放资产，不保存密钥。

### 增量 C：成片任务、任务中心和计费（3–4 人日）

- 任务中心轮询单任务状态，成功后展示预览/下载。
- 补取消、重试、归档重试和可恢复错误。
- 提交前预留额度，成功结算，确定未扣费后释放；不能用“本地任务失败”猜测供应商未扣费。
- 验收：重复点击只有一笔任务和一笔有效结算。

### 增量 D：IP 驱动内容与上线验收（2–3 人日）

- 文案任务固化 `ip_profile_snapshot`，把人物身份、服务范围、目标人群和表达风格注入 Prompt。
- 以真实人物完成“IP 定位 → 文案 → 声音 → 分身 → 成片 → 归档 → 扣费” UAT。
- 形成可追溯证据包后才提升至 `REAL_CHAIN_VERIFIED`。

## 7. 工期口径

### 7.1 开发工期

`oral-ip-agents-research` 的复审版计划给出的基准是：

- 稳定化阶段：单人 7–10 个工作日；2 名后端 + 1 名前端可压缩至 5–7 个工作日。
- 真实链路阶段：10–15 个工作日，供应商审批/账号风控时间单独计算。
- 原始项目对数字人供应商的从零对接估算为 1–2 周。

本仓已经有分身/声音/口播领域层和前端骨架，因此剩余开发建议按 **9–13 人日** 排期：

- 1 名全栈 + 1 名测试：约 7–10 个工作日。
- 2 名后端 + 1 名前端 + 1 名测试：约 4–6 个工作日。
- 密钥申请、充值、账号审核和真实人像/声音授权不包含在上述代码时间内。

### 7.2 产品运行耗时，不是开发工期

参考 `oral-ip-agents-research/docs/06-最终开发文档.md`：

- 声音样本支持口径：5 秒–5 分钟，具体受供应商限制。
- 声音克隆用户体感目标：10 分钟内。
- 60 秒数字人渲染准入目标：P95 不高于 3.5 分钟，但必须用真实供应商 Spike 实测，不能直接当作已达成指标。
- 整条成片处理目标：P50 不高于 5 分钟，排队时间单独计量。

## 8. 实现技法

1. **人物身份是根，资产只是版本。** 五视图、场景形象、分身和声音都绑定 `identity_id`，不用文件名或供应商 ID 做业务主键。
2. **供应商中立适配器。** 业务层只使用“分身、声音、口播任务”，不把供应商名和任务 ID 暴露给用户。
3. **异步状态机。** 任务统一使用 `PENDING/QUEUED → RUNNING → READY/SUCCEEDED/FAILED`，前端不凭超时猜测成功。
4. **幂等与计费分离。** 用 `idempotency_key` 防重复提交；余额预留、供应商扣费确认和最终结算是独立状态，不一步写死。
5. **素材访问在后端判断。** 所有克隆和成片提交都必须通过 `require_asset_access`，前端过滤仅用于体验，不是安全边界。
6. **合规与技术状态分离。** `READY` 只表示技术克隆完成，`CONFIRMED` 表示用户试听并同意使用，两者不可自动等价。
7. **资产图删除。** 删除人物前检查进行中任务和项目引用；删除后同步清理数据库行和存储对象，清理失败写审计。
8. **证据分级。** 将“代码存在”、“自动测试通过”、“预发真调用”、“真实成片验收”和“生产可放行”分开记录。

## 9. 本轮验收停止条件

当且仅当以下条件都有证据时，才可宣称数字人真链路完成：

- 真实图片分身、视频分身、声音克隆任务均返回可用资产。
- TTS 和完整音频两种成片模式均可生成、归档、播放和下载。
- 任务失败、供应商超时、归档失败、余额不足的补偿行为经过验证。
- 跨账户人物、素材、分身、声音和成片均不可读取或提交。
- 声音授权存证和用户试听确认已落库。
- 钱包只结算一次，失败任务可根据真实扣费状态退回或对账。
