# 人物 IP 与数字人口播落地方案 V1

> 更新日期：2026-09-07
>
> 适用范围：人物库、IP 定位、五视图、场景形象、声音克隆、数字人分身、口播成片、任务中心和钱包计费。
>
> 状态口径：本文严格区分代码实现、自动化验证、真实供应商验证和生产放行。

## 1. 当前结论

人物库已经形成一条完整的代码主链：

1. 用户上传一张本人或已获授权的图片，创建唯一人物身份。
2. 系统异步生成并向用户展示一张五视图拼合图。
3. 同一人物可按场景和服装生成新的场景形象，不重复创建人物。
4. 人物下维护结构化 IP 定位、数字人分身、克隆声音和授权记录。
5. IP 定位以不可变快照进入文案改写，历史任务不受后续档案修改影响。
6. 文案或完整音频可驱动数字人口播任务，任务进入统一任务中心并接入钱包预留、结算、释放与人工对账。

当前可以确认到 `AUTOMATED_VERIFIED`。尚未配置并获准使用真实图片模型、Hifly 数字人账号和生产 COS，因此不能标记 `REAL_CHAIN_VERIFIED` 或 `PRODUCTION_GO`。

## 2. 五视图产品口径

产品前台只展示“一张五视图拼合图”：

- 正面全身
- 45 度全身
- 侧面全身
- 正面近景
- 45 度近景

后端继续保留 7 个标准化内部资产：`FRONT_FULL`、`FRONT_HALF`、`FRONT_FACE`、`LEFT_45`、`LEFT_SIDE`、`RIGHT_45`、`RIGHT_SIDE`。右侧视图由左侧视图镜像兼容生成，用于旧项目选角、首帧和视频生成合同；前端的“五视图”表达与后端的“七个兼容资产”并不冲突。

## 5. 仍未完成或不应误报完成的部分

### P0：真实上线前必须完成

1. **真实供应商 UAT**：照片分身、视频分身、声音克隆、TTS、完整音频五条链至少各跑 3 组授权样本。
2. **真实图片模型 UAT**：一图五视图、重生、场景形象验证人物一致性、手指/服装/背景缺陷和失败重试。
3. **生产 COS 验证**：上传、归档、签名播放、完整下载、生命周期和跨账户拒绝。
4. **付费与异常演练**：余额不足、限流、提交超时、提交结果不确定、供应商已扣费但本地失败、归档失败和人工对账。
5. **真实角色验收**：普通用户、管理员、审计员分别验证可见性、操作权限、授权边界和账务证据。

### P1：运营与规模化增强

1. 当前实现的是 generation/oral 的**共享原子硬并发上限和同用户单活跃门禁**，尚未实现跨任务类型的完整公平轮转。
2. 尚缺分身/声音的默认版本、停用、删除、使用中禁删等完整生命周期管理接口和 UI。
3. IP 定位目前是人工结构化编辑并驱动文案；“AI 自动提出 IP 定位建议、竞品差异化、栏目规划”尚未实现。
4. 关键指标还需产品化：排队耗时、供应商提交/制作/归档耗时、失败码分布、扣费状态、人工对账 SLA。
5. 当前是有界 HTTP 轮询；任务量扩大后可再评估 SSE/WebSocket，但不应在真实负载数据前预先增加复杂度。

### P2：发布与持续质量

1. 建立真实样本回归集：人物一致性、声音相似度、口型、声画同步、字幕安全区和视频完整解码。
2. 建立供应商能力/价格/限流配置表和降级策略，避免业务代码硬编码供应商差异。
3. 把真实链路证据纳入发布门禁，并区分 `CODE_PRESENT → AUTOMATED_VERIFIED → STAGING_VERIFIED → REAL_CHAIN_VERIFIED → PRODUCTION_GO`。

## 6. 已执行的落地顺序

### 增量 A：资产入口和合规

- 复用统一素材上传，而不是为声音和视频再造上传接口。
- 补视频/音频格式、大小、声音时长和上传进度。
- 增加授权记录，绑定人物、素材、摘要、用途、文本版本、操作人和时间。
- 克隆专用权限独立于通用素材查看权限。

状态：代码与自动测试完成。

### 增量 B：耐久分身和声音

- 分身/声音创建先落库，Worker 再调用供应商，避免请求超时造成孤儿付费任务。
- 加入 owner-scoped 幂等键和 canonical request hash。
- 声音 READY 与用户 CONFIRMED 分离；只允许确认真实归档 demo。
- 历史无授权分身/声音不能继续生成。

状态：代码与自动测试完成；真实供应商尚未验收。

### 增量 C：口播任务、任务中心和计费

- 普通生成与口播任务统一展示和轮询。
- 补取消、失败重试、只归档重试、预览和下载。
- 提交前预留，成功归档后结算；只有确认未提交/未扣费才释放。
- 提交不确定或扣费不确定进入人工关注，禁止自动盲重试或猜测退款。
- 提交不确定时释放调度槽位，但继续冻结账务预留，避免既堵死用户又误退款。
- SQLite/PG 共用容量与同用户门禁，PG 并发通过共享容量锁原子控制。

状态：代码、专项自动测试、独立 P0/P1 复审和全仓门禁完成。

### 增量 D：IP 驱动文案

- 文案任务固化人物 IP 快照、档案 hash 和独立 profile revision。
- Prompt 使用固定 system 规则，人物档案作为不可信 user 数据注入。
- Worker 只读任务快照，不读取会变化的当前人物档案。
- 同幂等键但不同人物/内容返回冲突，损坏快照明确报完整性错误。

状态：代码与独立 P0/P1 复审完成。

### 下一步 E：真实链路验收

需要用户提供或明确授权使用测试环境的图片模型、Hifly、COS 和充值额度后执行。建议次序：

1. 一图五视图与场景图。
2. 照片分身和视频分身。
3. 声音克隆、demo 试听和确认。
4. TTS 与完整音频成片。
5. 失败补偿、钱包结算和人工对账。
6. 真实角色 UAT 和证据包。

## 7. 时间与验收指标

参考 `oral-ip-agents-research`：

- 通用产品规格允许声音样本 5 秒–5 分钟；当前仓按已选链路收紧为 5–180 秒，后续只有供应商真测确认后才放宽。
- 声音克隆体感目标为 10 分钟内。
- 60 秒数字人渲染准入目标为 P95 不高于 3.5 分钟，但原研究明确标注“待真实 Spike 验证”，不能作为当前已达成性能。
- 完整成片目标为 P50 不高于 5 分钟，排队时间必须单独计算。
- 原始项目从零对接数字人供应商估算 1–2 周；本仓代码主链已补齐后，建议真实 UAT 与异常演练预留 3–5 个工作日，供应商审批、风控和充值时间另计。

## 8. 关键实现技法

1. **人物身份是聚合根。** 五视图、场景图、分身、声音、IP 档案和历史任务都绑定 `identity_id`，供应商 ID 只作为外部引用。
2. **前台一张图，后台保兼容资产。** 用户只理解五视图拼图；后台保留七类标准资产，兼容旧选角和视频链。
3. **不可变业务快照。** 文案任务记录 IP 档案快照、hash 和 revision；历史内容可复现，人物档案后改不污染旧任务。
4. **短事务 + 耐久 Worker。** 先落任务，提交供应商和下载归档在事务外进行，再用 CAS 写结果，避免长事务和重复付费。
5. **把“不确定”作为一等状态。** 超时不等于未提交，任务进入 `SUBMISSION_UNCERTAIN`；调度槽可以释放，但只有凭证确认后才能重新提交、结算或释放账务预留。
6. **计费与任务状态分离。** 任务失败不自动等于退款；账务使用预留、结算、释放和供应商扣费状态四个维度判断。
7. **租约和 attempt 隔离。** Worker 用租约、尝试号、随机 token 和独立对象键；失去租约的 Worker 只能清理自己的对象。
8. **统一容量锁顺序。** PG 领取顺序为容量行、用户游标/活跃检查、任务 CAS；SQLite 在同一写事务内完成检查和领取。
9. **合规状态独立。** 技术 READY、授权有效、用户 CONFIRMED 分开存储和校验，任一缺失都不能进入成片。
10. **证据由服务端绑定。** 人工对账绑定 operation id、处理结论、原因、证据资产和服务端读取的 SHA，禁止客户端自报 hash。
11. **删除优先于抽象。** 上传、资产、钱包、任务中心尽量复用现有模块；没有引入新 ORM、队列框架或前端状态库。
12. **测试对准事故模型。** 除 happy path 外，重点覆盖重复点击、跨账号、租约丢失、双连接并发、提交不确定、归档失败和重复结算。

## 9. 真实链路停止条件

只有以下证据全部存在，才可宣称数字人链路完成：

- 真实图片生成成功并通过人物一致性与五视图质量验收。
- 真实照片分身、视频分身、声音克隆均返回可用、可归档资产。
- TTS 和完整音频两种模式均可生成、播放、下载并通过完整解码。
- 声音授权、真实 demo 和用户确认均已落库且可审计。
- 供应商超时、限流、余额不足、提交不确定、归档失败均按预期补偿。
- 跨账户人物、素材、分身、声音、任务和结果均不可越权读取或提交。
- 钱包只有一次有效预留和终态账务；不确定扣费不会自动误退。
- 每次真实调用留存请求时间、供应商任务号、状态轨迹、资产摘要和验收结果，但不保存任何真实密钥。
