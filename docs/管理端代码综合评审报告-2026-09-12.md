## 1. 架构分析

### 前端（React 19 + TS + Vite 双入口）
- **优点**：入口合同双层钉住（源码 entryContract.test.ts + 产物 verify 脚本）；hash 路由 + intent 白名单轻量干净；写操作统一走 `adminWrite`（CSRF+幂等键+confirm+reason）；`ui/` 组件族与 `vocabulary.ts` 单一词典收敛文案/状态/金额；薄容器（TabBar 组合）+ 功能页分层；注释保留评审决策。
- **短板**：`api.admin.ts` 1648 行混装约 10 个业务域（应按域拆分、类型接 generated/api.ts）；与 `api.ts` 存在两套平行 `requestControl` 且 **401 语义分叉**（api.ts 版派发 SESSION_EXPIRED_EVENT 自动退登录门，api.admin.ts 版不派发 → 仅 3 个页面手工处理会话过期，其余页面操作员被卡在页面上）；分→元格式化在 4 个页面复制绕开词典；迟到响应隔离（requestId 守卫）只在部分页面存在。

### 后端（FastAPI + psycopg3 + PG）
- **优点**：AdminReader/AdminWriter RBAC 边界清晰；`admin_write_contract` 幂等快照（唯一键 + 请求指纹 + 同事务审计）是全库最扎实的设计；SQL 全量参数化；限流走 PG 原子 UPSERT；`pg_transaction` 门面带超时护栏；服务层 FOR UPDATE 状态机（session_epoch + fenced 事务）做到了会话撤销真·立即生效。
- **短板**：分页样板 ≥8 份手抄且边界漂移（limit 下限 0 vs 1、上限 100/200/366）；`_http` 错误 helper 三种行为（是否打 metric）；503 fail-closed 覆盖不齐；LIKE 通配符转义一半做一半不做；`control_routes.list_generation_records` 460 行巨型函数（六源归并 + 内存分页，深翻页丢条目）；时钟混用（应用时钟 vs 事务时钟）。

## 2. 关键发现

### P0（1 项，已人工复核）

- **[P0] 客户会话"强制下线"功能在产线必失败**。前端 `revokeCustomerSession` 只带 `Idempotency-Key` 不带 CSRF 头（`api.admin.ts:1204-1222`），而服务端路由走 `AdminWriter` → 对 POST 强制 CSRF（`admin_session_routes.py:41-47` → `get_admin_actor` 的 `_WRITE_METHODS` 分支）→ 每次调用必得 403 `ADMIN_CSRF_REQUIRED`。`SessionsPage.test.tsx` 全部 mock fetch，故测试全绿也测不出。修复：改走 `adminWrite` 通道或手工补 `X-Admin-CSRF`（约 5 行 + 一个真实 403 回归测试）。这是"契约写了但没人机械执行"的典型事故——建议给 `requestControl` 加 lint/运行时断言：非 GET 且无 CSRF 头直接抛错。

### P1（3 项）

1. **[P1] customers.csv 公式注入**：`admin_customer_routes.py:1071-1075` 原样 `writerow` 用户可控 username，而同库已有消毒器 `_spreadsheet_safe_cell`（`control_routes.py:1712-1715`）未复用——运营在 Excel 打开即触发。同文件 profit 两个导出同样未消毒（单元格为数字/日期，风险低）。
2. **[P1] 退款业务无闭环**：调账只接受 `1 <= credits` 正向加秒（`admin_customer_routes.py:416-419`），`REFUND_APPROVAL`/`LEDGER_CORRECTION` 枚举存在却无法扣减；前端仍提供 REFUND 选项（`SessionsPage.tsx:26-32`）——运营选了也退不了款。
3. **[P1] 会话过期处理分叉**（见架构短板）：8+ 个页面会话过期后只刷错误横幅不回登录门，操作员以为是自己操作错了。

### P2（精选 10 项，全量见评审过程记录）

- 审计中心三处盲区：管理员强制下线只写 `customer_session_events` 不进 audit UNION（`admin_audit_routes.py:66-134`）；"查看激活码明文"筛选值 `CODE_REVEAL` 与实际事件名 `admin.activation_code.revealed` 不匹配（恒为空）；批次创建不写审计。
- 口径不一致误导运营：dashboard 与 profit 页"今日收入"分辨率归档口径不同（`admin_dashboard_routes.py:170-175` vs `admin_profit_routes.py:294-298`）；对账 todo 与 reconciliation 计数口径微差。
- RBAC 不一致：钱包/流水 CSV 导出是 ControlUser（客户生产下 auditor 可导全量流水），customers.csv 却要 AdminWriter（auditor 403）。
- 资金导出不带筛选：页面上的账号/渠道/日期筛选对 CSV 导出无效（`control_routes.py:1340-1358`）。
- 费率页承诺"二次确认"但 `save()` 无 ConfirmDialog（`RatesManager.tsx:283-288` vs `104-140`）。
- `reveal_activation_code` 手工复刻幂等信封已与共享实现语义漂移（`admin_activation_routes.py:889-1029`）。
- rate 调价读旧价→UPDATE 无行锁（`admin_rate_routes.py:190-214`，审计旧值可跳版本）；runtime 设置 upsert 非原子（`admin_runtime_routes.py:196-213`，并发首写 500）。
- 前端死代码/双真相源：`CustomersPage.tsx:162` 别名 + 永假分支、`AdminActivationSection.tsx:349` 重复推导 readOnly、`platformLabel` 与词典分叉（ios/android 显示英文码）。
- 测试缺口：`PaymentSettingsSection`（涉密钥写）无专属测试、无 auditor 只读用例；`AnalyticsPage/AuditCenterPage/FundsPage/SystemSettingsPage` 无测试文件。
- a11y：TabBar 无方向键导航/tabpanel 关联、ConfirmDialog 无焦点圈闭、`aria-expanded="false"` 写死。

### P3（汇总 15+ 项）

`const [pageSize] = useState(20)` 伪状态反模式 ×4；Pagination 的 hasMore 无 total 模式零调用；UTC/Shanghai 日界差一天（`ProfitOverview.tsx:16-20`）+ 默认售价硬编码；手写 dialog 无 Esc/遮罩关闭；`_inclusive_created_to` 双份；`sqlite3.Row` 残留注解（`control_routes.py:1606`）；跨路由借 logger（`admin_customer_routes.py:598`）；`_locked_code_status` f-string 拼列名（内部常量，建议白名单化）；FOR UPDATE 下 UPDATE 无 `AND status=预期` 纵深兜底；分页样板 8 份；批处理 COUNT 全 UNION 重算（审计表涨大后最慢读）。
