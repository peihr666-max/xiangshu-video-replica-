# WP1-WP3 人物重构与动作分段工作清单

- 开发分支：`codex/wp1-wp3-character-pipeline`
- 目标：基础人物身份稳定、项目造型自动适配、完整人物首帧重构、单个 H3 任务内多动作时间段。
- 发布边界：后端 API、Worker 与桌面前端均有改动，完成验证后必须同时部署服务器并重新打包 Windows 客户端。
- 成本边界：本期不把一个 12 秒视频拆成多个独立付费 H3 任务；首帧整身质检失败最多自动重做两轮，H3 不做静默付费重试。

## WP1：项目级人物造型自动匹配

### 工作任务

- [x] 保留现有基础人物身份层；多视图和原始照片只负责回答“是谁”。
- [x] 根据最新视频拆解、所选源帧时间点、对应场景、人物身份和动作，自动推导项目造型。
- [x] 项目造型至少包含场景类别、人物身份、服装说明、自动选择理由和输入指纹。
- [x] 将项目造型写入 `project_character_appearance` 版本，不新增数据库表。
- [x] 首帧异步任务的请求 hash 冻结分析版本和造型指纹；输入变化时旧任务失败关闭，不复用错误结果。
- [x] 相同分析、人物和造型指纹优先复用已有项目造型版本。
- [x] 桌面端只读展示“本项目人物造型”，不恢复四个下拉框或强制人工确认。
- [x] 用户选择人物场景造型后，以该版本的五视图作为身份、服装、鞋履与配饰依据；源视频画面只决定构图、姿态和背景。
- [x] 场景造型五视图生成后自动检查身份、服装、场景、视图数量、人体、文字与额外人物，最多三轮，无管理员审核。

### 验收标准

- 商务、施工、餐饮、运动、户外、生活类场景能得到不同的无品牌服装策略。
- 同一人物用于不同项目时，身份不变，项目服装可以变化。
- 离开项目页后任务继续由 Worker 执行；返回后能通过 latest task 恢复。
- A 账号不能通过列表或直接 ID 读取 B 账号的项目造型及首帧。
- 相同输入不重复创建项目造型版本；分析或人物变化后旧首帧必须 stale。

## WP2：完整人物首帧重构与 H3 一致性

### 工作任务

- [x] 把首帧目标从“身份替换/换脸”升级为 `full_person_replace.v1`。
- [x] 完整人物契约覆盖头脸、发型、颈部、肤色、身形、上下装、鞋履、手部、遮挡边缘与反射区域。
- [x] 源帧负责构图、机位、姿态、动作和场景；基础人物参考负责身份；项目造型负责服装与场景适配。
- [x] 将 `reconstruction_mode`、`character_contract`、项目造型版本写入首帧候选快照。
- [x] 编译 H3 Prompt 时透传首帧人物契约，并在视频生成请求快照中继续冻结。
- [x] H3 Prompt 明确禁止回退为局部换脸、原身体/原服装或身份漂移。
- [x] 当前版本收口为单人视频：新拆解结果逐时间段记录 `person_count`，任一时间段出现两人及以上时在付费图像生成前阻断。
- [x] 旧拆解结果没有人数数据时，生成前再对已选源画面做一次语义人数检查；源画面不是恰好一人时阻断。
- [x] 每张首帧候选自动比较源画面、人物参考图和项目造型，检查身份、整身重构、服装、姿态、构图、场景、人体结构、文字和“仅换头/保留原身体”。
- [x] 首帧候选不合格时只重做不合格数量，最多三轮；仍不合格返回 `FIRST_FRAME_QUALITY_REJECTED`，不得进入 H3。
- [x] 候选快照保存质检结论、问题码、实际通过轮次和模型证据；桌面端只展示通过候选及“整身人物质检通过”状态。
- [x] 源画面按视频全时长 10%/30%/50%/70%/90% 提取五个候选，并综合技术分与人物可见性、脸部清晰度、无遮挡、姿态和运动模糊语义评分。
- [x] 语义评分服务不可用时不自动确认候选，桌面端要求用户查看后手动确认。
- [ ] 多人视频的目标人物编号/框选和跨时间段跟踪留到独立 R2V 工作包；当前版本明确拒绝多人视频。
- [x] H3 成片在 5%/25%/50%/75%/95% 五个时间点自动抽帧，检查身份、服装、动作连续性、人体、额外人物与严重闪烁。
- [x] 视觉失败以 `VISUAL_QUALITY_FAILED` 归档预览并进入 `NEEDS_ATTENTION`；再次付费必须由用户明确触发。
- [x] 视觉质检暂不可用时保留已知 Provider 任务和冻结额度，通过归档重试或对账只重试质检，不再次调用付费 H3。

### 单人范围决策

- 当前数据模型一个项目只绑定一个主角色，本期只接受全片任一时刻最多一名真实人物的参考视频。
- 无人物的产品/环境时间段允许保留；人物时间段不得多人同框。
- 真正支持多人需要新增“源视频人物轨迹 → 目标人物资产”的逐人映射并切换 H3 参考生视频；这是独立工作包。

### 声音决策

- 当前 H3 图生视频请求只有文字 Prompt 与首帧，没有 `voice_id`、参考音频或音色性别参数。
- 当前音频质检只验证 MP4 是否存在音轨，不验证男声/女声、音色身份或逐字口播。
- 因此男角色换成女角色后，当前版本不能保证自动变成稳定女声。
- 若业务要求声音跟人物匹配，应新增独立声音链：人物声音策略 → 授权音色/预设 TTS → 口播合成 → 音轨替换/混音 → 口型同步与性别质检。
- 默认建议使用有授权的预设男女音色；声音克隆必须独立取得授权，不能从视频中默认克隆。

### 验收标准

- Provider 最终 Prompt 必须含完整人物重构约束，不能只有“替换人物/脸”。
- 首帧、H3 Prompt、生成请求三个快照能追溯同一个人物契约和项目造型版本。
- 多人视频和多人源画面必须在首帧付费生成前阻断，错误码和中文原因必须可恢复显示。
- 每个发布候选都必须有自动质检 `passed=true`，不允许未质检或仅换头结果进入确认和 H3。
- 视觉质检失败可见、可运营处理，不改变真实付费提交事实。
- 若声音模块未上线，界面和发布说明必须明确“不保证音色随人物性别变化”。

## WP3：12 秒视频动作时间段拆解

### 工作任务

- [x] 保留顶层 `shots` 兼容字段，但把业务语义改为“可执行时间段”。
- [x] 新增可选 `segment_kind=SHOT_CUT|ACTION_BEAT` 与 `boundary_reason`。
- [x] 分析提示词要求 8 秒以上视频优先输出 2-5 段；单一连续镜头也按动作、手势、位移、运镜和表达重点拆段。
- [x] 服务端强制时间轴从 0 开始、连续无空洞、不重叠且覆盖完整视频。
- [x] 口播映射跳过无口播动作段，避免动作段吞掉下一句台词。
- [x] H3 继续使用一个付费任务，把多个时间段统一编译到同一个 Prompt。
- [x] 前端将“镜头与口播”改为“动作时间段与口播”，显示动作段/切镜标识。
- [ ] 用真实 12 秒单镜头样本验证供应商稳定输出 2-5 段；该验证会调用真实分析 Provider，需单独留证。

### 验收标准

- 12 秒连续镜头只要存在动作或语义变化，就输出 2-5 个连续时间段。
- 第一段从 0 秒开始，最后一段结束时间等于 ffprobe 实测时长；相邻段无重叠、无空洞。
- 无台词动作段的 `spoken_text` 和脚本映射保持为空，不挪走后续台词。
- H3 Prompt 含每段时间码、动作、人物位移、手势和运镜，不增加独立付费任务数量。
- 历史没有新字段的 `shots` 仍可读取、编辑和编译。

## 公共主项与检查标准

| 主项 | 工作内容 | 检查标准 |
|---|---|---|
| 异步恢复 | 分析、人物图、首帧、视频都由持久任务执行 | 切页/重开详情后 PENDING、RUNNING、SUCCEEDED、FAILED、SUBMISSION_UNCERTAIN 均能恢复 |
| 权限隔离 | 项目、人物、造型、任务与资产按账号授权 | A/B 双账号列表与直接 ID 交叉访问全部拒绝 |
| 幂等复用 | 请求 hash 冻结全部业务输入 | 相同请求复用；分析、源帧、人物或造型变化后生成新任务 |
| 版本血缘 | 分析 → 造型 → 首帧 → Prompt → H3 请求可追溯 | 任一成片能反查全部版本 ID、模板版本和人物契约 |
| 单人门禁 | 分析逐段人数 + 选中源画面二次检查 | 任一时间段多人或源画面非恰好一人时，付费生成前阻断 |
| 声音诚实性 | 未接独立音色链前不承诺性别匹配 | 发布说明和 UI 不显示“已自动换女声”等错误承诺 |
| 播放与结果 | 结果归档、签名 URL、MIME、时长可用 | 完成态可播放，非 `0:00 / 0:00`，链接过期可重新签名 |
| 质量与成本 | 场景五视图、首帧、成片分层质检；H3 不静默重试 | 图像三轮仍失败即阻断；成片五帧质检失败可预览；任何 H3 再次付费必须由用户明确触发 |

## 发布与部署清单

### 是否需要服务器部署

需要。WP1-WP3 修改了 `analysis.py`、`first_frames.py`、`image_tasks.py`、`generation.py` 和 Worker 消费逻辑；只重新打桌面包不能让线上生成逻辑生效。

### 发布顺序

1. 在本分支完成专项测试、Ruff、格式、mypy、前端 TypeScript、Biome 与 Vitest。
2. 合并前执行一次全仓 `npm run check`，不调用真实付费 Provider。
3. 构建服务端候选版本；本期视觉稳定性改动不新增数据库迁移。
4. 先滚动部署 API，再滚动部署 Worker，确保二者使用同一代码版本。
5. 发布 Web 静态前端，并重新构建 Windows NSIS 安装包。
6. 预发用单人通过、多人阻断、男换女整身首帧、12 秒连续镜头四类样本验收。
7. 生产切换后检查任务恢复、版本快照、Worker 日志、播放、权限隔离和错误率。

### 生产门禁

- 自动化门禁全绿。
- 不存在未提交但应上线的业务文件。
- API 与 Worker 镜像/提交号一致。
- 桌面安装包版本号、SHA-256 与服务端兼容范围已记录。
- 真实 Provider 冒烟必须单独授权并限制为受控样本，禁止批量重复调用。
