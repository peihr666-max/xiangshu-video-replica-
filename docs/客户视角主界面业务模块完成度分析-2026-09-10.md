# 客户视角 · 主界面业务模块完成度分析报告

> 版本：V1（2026-09-10）
> 视角：客户登录后从主界面能看到、能操作的业务功能模块
> 口径：以主界面信息架构为骨架，逐模块评估"客户实际能用到什么程度"，而非代码文件是否存在
> 证据来源：前端主界面导航与页面组件（`client/src/studio/`）、后端能力探测与业务链路（`server/app/`）、任务账本（`docs/客户版任务清单-V3.md`）、源码审计（`outputs/customer-cloud-convergence-analysis-2026-09-08/`）

## 一、这份报告回答什么问题

上一版分析从"代码模块 + 任务账本证据层级"切入，回答的是"工程完成度"。本报告换一个视角：**一个真实客户拿到产品、打开主界面，他想做的那几件事——把爆款视频复刻一条、把视频里的人换成自己的 IP、直接生成一条视频、让数字人念口播、发出去——每一件现在能做到什么程度，哪里会卡住。**

因此本报告的完成度不看代码行数，而看客户动作能否闭环。

### 客户可用度分级

| 等级 | 含义 | 客户体验 |
|---|---|---|
| **L4 生产可用** | 真实链路已验证，客户可完整无阻断使用 | 放心用 |
| **L3 功能可用** | 界面 + 后端 + 自动化验证齐全，真实云端/付费链路待接 | 测试环境能完整走通，生产待开闸 |
| **L2 部分可用** | 核心能走通，但存在能力门禁或局部功能暂缓 | 能用一部分，部分按钮"敬请期待" |
| **L1 受阻** | 关键缺口导致客户无法完成该模块核心动作 | 看得到、点不动，或结果不对 |
| **L0 未开放** | 仅草稿/占位/内部可见 | 客户实际用不上 |

## 三、创作类模块（客户核心价值链）

### 3.1 视频复刻 —— L3 功能可用

- **客户动作**：上传/选择一条参考爆款视频 → AI 拆解分镜 → 选人物与首帧 → 编排 Prompt → 提交批次 → 得到复刻成片。
- **界面**：`client/src/studio/CreationPages.tsx:838-1761`（约 924 行，四个创作通道里最重的一个），流程完整。
- **后端**：`server/app/generation.py`（7191 行）承载分镜批次编排、`generation_routes.py`（956 行）出入口、`generation_worker.py`（1762 行）跑交付；成片走 H3 Provider 直链（`archive_status=DIRECT`），不下载转存。
- **完成度依据**：账本核心 T 任务已完成（`[x]`），用户公平队列（每用户默认并发 1）与 Worker 崩溃恢复已在真实 PG16 fixture 上自动化验证。
- **客户可感知缺口**：真实付费 Provider（H3）的验收任务 EXT-03/04/05/06 仍 `[ ]` 未开始，真实生成链路归 T40（`[ ]`）。**含义：功能在测试/内部环境能完整跑通，但"客户花真钱生成真成片"这条链路尚未在真实环境验证。**

### 3.2 人物置换 —— L3 功能可用

- **客户动作**：选参考分镜 → 用自己的 IP 人物替换画面中的人 → 确认首帧版本 → 生成置换成片。
- **界面**：`client/src/studio/CreationPages.tsx:1762-2470`（约 709 行）。草稿结构里专门有 `firstFrameSelectionVersionId` 字段承接"人物置换流程交接的已确认首帧版本"（`client/src/studio/types.ts:209-210`）。
- **后端**：`first_frames.py`（2636 行）首帧、`character_identity.py`（1905 行）人物身份、`source_frames.py`（1085 行）源帧。
- **完成度依据**：人物库重构与首帧链路（WP1-WP3、一键生成、行内改名）账本 `[x]`。
- **客户可感知缺口**：与视频复刻共享同一套生成后端，故真实付费 Provider 门禁同样适用。

### 3.3 视频生成 —— L2 部分可用（含明确能力门禁）

- **客户动作**：不依赖参考视频，直接由文字/图片/参考素材生成视频。分四个子能力：文生视频（t2v）、图生视频（i2v）、参考生视频（r2v）、尾帧（last_frame）。
- **界面**：`client/src/studio/CreationPages.tsx:2471-2967`（约 497 行）。
- **后端能力探测**：`server/app/independent.py:95-104` 决定各子能力是否开放：

  | 子能力 | 开关值 | 客户实际状态 |
  |---|---|---|
  | 图生视频 i2v | `i2v_enabled = True` | **始终可用** |
  | 文生视频 t2v | `t2v_enabled = extended` | 受"扩展模式开关"控制 |
  | 参考生视频 r2v | `r2v_enabled = extended` | 受"扩展模式开关"控制 |
  | 尾帧 last_frame | `last_frame_enabled = extended` | 受"扩展模式开关"控制 |

- **客户可感知缺口（一手证据）**：扩展模式未开时，界面直接提示——
  - "该模式需要完成供应商核对后开放，敬请期待。"（`StudioWorkspace.tsx:876-877`）
  - "参考生视频当前未开放，请等待能力开启后再提交。"（`CreationPages.tsx:2763`）
  - "尾帧需要完成供应商核对后开放，敬请期待。"（`StudioWorkspace.tsx:1395`）
  - **含义：视频生成里客户目前只能稳定用"图生视频"，另外三个子能力被"供应商核对（Provider 验收 EXT）未完成"这道门禁挡住。** 这是客户会直接撞到的"敬请期待"。

### 3.4 数字人口播 —— L2 部分可用（账本进行中）

- **客户动作**：给人物 IP 配一段口播文案（或上传已有音频）→ 生成数字人口播成片。分文本驱动与音频驱动两条。
- **界面**：`client/src/studio/CreationPages.tsx:2968` 起（`OralPage`），导航含"数字人口播 · 用已有音频生成"子通道（`state.ts:19-20`）。
- **后端**：`oral.py`（1407 行）、`oral_worker.py`（1015 行）、`script_from_audio.py`（731 行）音频转文案、`asr.py`（402 行）语音识别。口播成片"按平台资产直取签名地址，无生成批次"（`live.ts:232`）。
- **完成度依据**：账本 **T46 `[~]` 进行中**——人物库到数字人口播全链路已打通。
- **客户可感知缺口**：T46 明确登记两项未决——CL-13"网感后期模板"待决策、CL-11 真实链路归 T40。**含义：口播能生成，但"更像真人的后期网感模板"尚未定型，真实链路未验证。**

### 3.5 爆款视频 —— L3 功能可用（新收编模块）

- **客户动作**：浏览抖音/视频号爆款榜单 → 看详情数据 → 选中作为复刻/文案的源头。
- **界面**：`ContentPages.tsx:630`（`ViralPage` 榜单）、`:1355`（`ViralDetailPage` 详情）。数据结构含平台规范化字段（`platformKey: douyin/wechat_channels`、点赞/收藏/分享/评论、`playUrl` 等，`types.ts:111-123`）。
- **后端**：`viral_routes.py`（674 行）、`viral_tikhub.py`（外部数据源）、`viral_statistics.py`、`viral_store.py`、`viral_refresh.py`、`viral_media.py`、`viral_link.py`。
- **完成度依据**：该模块是 2026-09-09 收编进主线的新模块（drift #102），`test_viral_refresh.py` 已并入 PG 硬门并 5 passed（CW-007 整合复验）。
- **客户可感知缺口**：依赖 TikHub 外部数据源，真实数据源联调与稳定性需在生产环境确认；作为新收编模块，尚无独立的真实链路验证记录。

### 3.6 文案工坊 —— L3 功能可用

- **客户动作**：从爆款/上传视频提取文案 → AI 改写 → 多版本管理与确认终稿。
- **界面**：`CreationPages.tsx:163-837`（`CopyPage`，约 675 行）。草稿含 `script`（原文/改写文/版本号/确认态）与 `scriptEdited` 本地编辑标记（`types.ts:187-217`）。

- **客户可感知缺口**：改写质量依赖大模型 Provider，真实 Provider 稳定性归 EXT 验收。

## 五、分发类模块（客户价值链末端，缺口集中）

### 5.1 发布管理 —— L1 受阻（正式发布暂缓未启用）

- **客户动作（期望）**：把生成的成片一键发布到抖音/视频号。
- **界面实况**：`ContentPages.tsx:2374`（`PublishPage`）标题下明确写着——**"可整理当前会话草稿；平台授权与正式发布暂缓未启用"**（`:2457`）。"待发布""已发布"计数在非审核模式直接显示"暂缓"（`:2467-2470`）。
- **后端实况**：保存草稿的 `savePublishDraft` 只更新前端会话状态（`patchState`，`:2441-2447`），**不调用任何后端发布接口**。
- **客户可感知缺口**：**客户能整理发布草稿（标题/描述/标签/封面），但无法真正发布到平台。** 平台授权（OAuth）与正式发布通道尚未接入。这是分发环节最直接的阻断项，对应审计缺口 F5 与账本 REL 系列发布任务（`[ ]` 未开始）。

### 5.2 数据看板 —— L2 部分可用

- **客户动作**：查看自己成片的播放/互动等聚合数据（7 天/30 天双窗口）。
- **界面**：`AnalyticsPage.tsx:149`（`AnalyticsPage`）。数据结构 `analytics7`/`analytics30`，注释明确"加载失败为 null，看板页回退'尚未就绪'空态"（`types.ts:176-179`）。
- **后端**：`/api/studio/analytics` 聚合、`ops_metrics.py`（611 行）。
- **客户可感知缺口**：看板框架完整，但真实平台数据回流依赖发布链路（发布未启用则无真实分发数据）；审计 F5 记录侧栏"真实环境积分显示'—'"。**含义：看板能展示结构与内部统计，但客户端到端的真实运营数据尚未接通。**

## 八、结论

1. **客户主界面的"骨架和肉"基本长齐了。** 13 个业务模块没有一个空白页，从爆款浏览、文案、复刻、置换、生成、口播到人物库、素材库、任务中心，界面与后端链路都实质存在，多数达 L3（功能可用）——**在测试/内部环境，客户能完整走通"找爆款 → 做内容 → 管资产 → 看任务"这条主链。**

2. **卡住客户的是"价值链两端"和"真钱真链路"。** 一端是**钱包**（L1，接线错误导致看不清余额、充不了值），另一端是**发布**（L1，只能存草稿、发不出去）；中间贯穿的是**真实付费 Provider 未验收**（视频生成三个子能力"敬请期待"、复刻/置换/口播的真实成片未在真实环境验证）。这三件事决定了客户能否"付费 → 生成真片 → 发出去 → 看数据"完整闭环。

3. **完成度呈"中间厚、两端薄"的哑铃形。** 创作与资产类模块（价值链中段）完成度最高（多为 L3）；分发与账户类（价值链末端 + 付费入口）完成度最低（L1-L2）。这与任务账本一致：功能开发类 T 任务大量 `[x]`，而真实链路（T40）、发布（REL）、钱包收敛（CW-016）、Provider 验收（EXT）集体停在 `[ ]`/`[~]`。

4. **若要对客户可用地"上线一条最小闭环"，最短路径是修三处：** ① 修钱包接线（CW-016）让客户能看余额、能充值；② 完成至少一个付费 Provider 验收（EXT）+ 真实链路（T40）让"图生视频/视频复刻"能出真片；③ 接发布通道（REL）或先明确"发布暂缓"为产品预期，避免客户做到最后一步发不出去。在此之前，产品更适合定位为"内测/受控客户可用"，而非"公开自助可用"。
