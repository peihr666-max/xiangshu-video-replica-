# T45 安全纵深防御发布说明

## 发布顺序与兼容窗口

1. 先发布包含 T45 提示和完整激活码输入能力的桌面客户端，再发布服务端。
2. 同一台设备重装后，不再允许只凭设备指纹空码恢复；用户必须输入原完整激活码，
   服务端同时校验设备指纹。校验成功后直接恢复，不需要管理员审核。
3. 新设备或第二台设备仍走设备配对流程，由首台设备批准；这不是管理员审核流程。
4. 老客户端若仍调用空码恢复，会收到统一的激活失败响应。兼容窗口内客服只能提示
   “升级客户端并输入完整激活码”，不得索取完整激活码、设备 token 或 session token。
5. simple 人物流程继续采用系统自动批准并直接生成/发布，审计快照标识
   `SYSTEM_AUTO_PUBLISH`，不伪造管理员 reviewer。

## 用户可感知变化

- 激活码被挂起或撤销后，登录/切换的幂等重放不再返回旧 token。
- 设备切换后，旧设备重放旧登录结果会被拒绝，不再显示“登录成功但请求均 401”。
- 激活码重置必须携带 `Idempotency-Key`；同 key 的丢包重试返回同一新码。
- 签名素材链接绑定用户、资产和会话代际；退出、切换、资产删除后旧链接失效。
- 客户上传和钱包接口不再返回存储桶拓扑或内部价目字段。
- 已关闭的 ZPay 订单若发生迟到支付，回调会幂等入账，避免支付成功却永久不入账；
  订单状态、notify 摘要与账本可用于对账，金额不一致仍
  严格拒绝。

## 管理与审计策略

- 管理员不能给自己调账或修改自己的客户价格；拒绝事件写入
  `security.admin_self_service_denied` 审计。
- auditor 保留跨账户资产元数据读取能力，用于合规核查；每次读取写入
  `auditor.asset_metadata.read`，不因此获得客户写入、导出或原始存储拓扑权限。
- 激活码明文揭示的幂等重放写入独立的 `admin.activation_code.revealed_replay` 审计。
- 管理会话达到空闲上限，或来源 IP/User-Agent 摘要变化时，旧 cookie 被撤销并要求
  重新登录。

## 上线前强制检查

在生产主机按《客户版部署与灰度手册》运行：

```bash
python scripts/customer_release_preflight.py \
  --env-file /etc/video-replica/customer.env \
  --service-user video-replica
```

未输出 `T45_PREFLIGHT_OK`、PG16 专项未通过、真实 ZPay/COS/Provider 未完成同一 SHA
联测，或桌面客户端尚未先升级时，一律 No-Go。
