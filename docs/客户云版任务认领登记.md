## 2. 每次认领与交接记录字段

| 字段 | 记录要求 |
| --- | --- |
| 任务与范围 | 正式编号或明确维护ID，不接管其他任务 |
| Owner / Reviewer | 实际执行者和评审来源；未知标待核对，不编造 |
| 实时查重 | 时间、main SHA、同编号分支、开放/近期合并PR、worktree、用户在制说明 |
| 前置证据 | 各前置合入SHA、适用验收、签认阶段条件；未满足登记WAITING原因，不创建实现分支 |
| 文件与接口 | 主改文件、共享文件Owner、API/DTO/迁移head交接点 |
| 分支与worktree | 最新origin/main来源SHA、唯一分支、绝对路径、host/会话、共享claim |
| 测试资源 | PG实例/卷/端口/固定库、进程、不可隔离资源的串行时间窗 |
| 提交评审 | head SHA、PR URL、验证结果、未测试项、评论处理 |
| 合并清理 | merged确认、squash SHA、main检查、归档位置、进程退出、路径核验、remove结果 |

占用生命周期为CLAIMED → ACTIVE → REVIEW → MERGED → CLEANED。尚未领取的等待原因另记WAITING，不代表已建分支。后续修复也先查重，再从最新main建立独立任务分支与worktree。

同仓认领目录必须原子创建，已存在就停止重复领取；跨设备仍由集成人串行确认并尽早推送认领记录/Draft PR。登记和本机锁不能单独证明跨设备无人开发；过期记录不自动抢占，原Owner明确交接并核对成果后才释放。
