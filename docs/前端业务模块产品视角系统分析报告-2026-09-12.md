## 2. P0 发现（需要优先立项）

### P0-1 客户生产制品缺失全局样式表（影响全部账户屏与深创作流）

**事实链（已用生产构建产物验证）：**
- `client/src/styles.css`（9042 行，含全局 reset、`.customer-access-*`、`.stage-block`/`.shot-table`/`.workspace-tabs`/`.task-records` 等全部老组件样式）**唯一引入方是 `src/App.tsx:23`**——而 App.tsx 是内部遗留壳，仅被测试引用、不进任何生产制品（`entryContract.test.ts:19,33` 断言）。
- 客户入口图（index.html → main.tsx → RootApp → customer/* + studio/*）无任何模块引入 styles.css；`index.html` 也没有 `<link>`。
- 运行时验证（dev 与生产同构图）：页面加载的全部样式表中 **0 条** `customer-access` 规则；激活页品牌 Logo 以 SVG 原始尺寸渲染为 **1264×1264px**，H1 表单起点 y≈1321——820px 高的首屏内只有一张巨型图标。
- 生产构建（`npm run build`）产物 `dist/assets/index-*.css` 中：`customer-access` 0 命中、`stage-block` 0、`shot-table` 0、`workspace-tabs` 0、`task-records` 0。即**激活/登录/设备配对三屏和经 LiveWorkspacePanel 打开的深创作流（项目列表、拆解工作台、人物库管理、任务记录）在客户生产包里都是无样式 HTML**；有样式的只有 studio 新页面、客户钱包/充值面板（自带 css）与生成控件（generation-controls/prompt-markdown css）。
- git 归因：`git log -S 'import "./styles.css"'` 在 main.tsx/RootApp.tsx 的全部历史无命中；CW-019（0d08608）父提交的 RootApp 已无 App 引用、vite 单入口——即该缺失至少在 CW-019 之前已存在，非本次引入。
- 推测原因：团队视觉验收走 `/review/v1.4`（dev-only，studio 页有样式），客户制品的真实渲染从未被人工走查。

**本次已修（部分）：** `studio.css` 顶部补了 `html, body` 重置（margin 0、深色底）——修掉了客户壳的 8px 白缝与侧栏/主区错位感（§7-2）。其余（激活三屏样式、老组件样式进客户包）**需要专门任务**：建议把 `.customer-access-*` 与老组件样式从 styles.css 拆分进客户合法 css（或在构建期拆包），并在 `verify_customer_bundle.mjs` 增加双向断言（必须含 `.customer-access` 规则 / 不得含 `.admin-` 规则）。注意不能直接把 styles.css 整体挂进客户图——其中包含 `.admin-*` 类，会违反 CW-019 客户制品排除管理域标识的契约。

### P0-2 会话切换失败是死胡同
`switchSession` 失败只写 hook 内 error 并保留 conflict 态（`useCustomerSession.ts:547-550`），而 binding-conflict 屏只渲染 SessionConflictDialog，该对话框没有 error 入参（`SessionConflictDialog.tsx:11-23`）；LoginPage 又只在无 conflict 时显示 error（`LoginPage.tsx:47`）。用户点"切换到本设备"失败后没有任何反馈。规格 FE-03 要求 409 交互进入确定 UI 状态，此为违反项。

### P0-3 工作台内会话失效回调可能静默无效
RootApp 把 CustomerWorkspace 的 `onSessionExpired` 接到 `session.restartAfterExpiry`（`RootApp.tsx:149`），但 reducer 的 `restart-login` 只在 session-expired/session-replaced 屏生效，从 workspace 屏是 no-op（`customer-state.ts:110-113`）。若本地 token 缺失且 transport 未发 401 生命周期事件，界面停留在 workspace，个人中心永远"正在读取账号信息"，无跳转无提示。

## 4. 业务流程走查要点

### 4.1 账户生命周期
- 激活：分类错误文案（PAIRING_APPROVAL_REQUIRED/限流/幂等冲突）完备；**缺"设备槽已满"文案**（只能落到服务端原文，客户不知道该去配对还是解绑）【中】；**激活成功无规格 C§4.1 要求的面值/到账过渡提示**（直接进工作台；新码 0 额度故影响有限）【中】。
- 配对：202 等待屏轮询健壮（幂等键防丢、指数退避、过期即停）；但"返回修改"不撤销服务端请求，主设备会看到重复待确认卡【中】。
- 登录/冲突：409 → 冲突弹窗（脱敏设备名+租约到期+二次确认），符合 FE-03；但见 P0-2。
- 心跳/租约：30s 心跳 + 手动续约 + 倒计时；**倒计时不自走**（渲染时算一次，依赖 30s 心跳刷新，心跳失败时冻结）【中】；**手动续约失败静默**【中】；**租约过期后解绑按钮被禁用**——最需要下线陌生设备的时刻反而不能操作，与页脚"发现陌生设备请立即下线"自相矛盾【中】。
- 设备管理"绑定第二台设备"用原生 `<a href>` 做页内导航（`DeviceManagementPage.tsx:89`），Tauri 桌面壳里是整页重载风险【高】。

### 4.2 创作主链路（产品层面最核心的四个坑）
1. **付费生成一旦提交不可取消/停止**，删除批次明示不取消不退费（`TaskRecordsPanel.tsx:451-457`）【高】。
2. **余额不足无前置校验、无充值引导**：生成界面不显示余额，失败只有一行错误，充值入口在钱包页/个人中心远离流程【高】。
3. **口播稿/Prompt 无自动保存**：镜头卡有 800ms 防抖自动保存，长文案编辑却是纯 React state，刷新/崩溃即丢（`useGenerationDrafts.ts:95-106`）【高】。
4. **一键流水线一个点击完成"锁定 Prompt+建批（扣费）"**，N=1 时无工具条付费提醒、无二次确认，误触即扣费【中】（对照组：再次生成/整批重生成有"原因+勾选付费确认"双门）。
另：动线 A 无就绪度引导（只有禁用按钮+一句话，与动线 B 的缺失清单体验不对等）【中】；拆解等待无进度不可取消（轮询上限 20 分钟）【中】；人物五视图进度条是**本地模拟进度**（每 3 秒插值，非真实进度，`SimpleCharacterUpload.tsx:61-77`）【中】；计费单位三处口径不一（内部"条"/流程"秒"/客户"秒数额度"）【中】；上传失败无断点续传，50MB 弱网风险【中】。

### 4.3 钱包与充值
- CW-016 回归锁有效：有客户会话必挂 CustomerWalletPanel（"秒/额度"），内部 WalletPanel（"内部价/条"）仅无会话时回落（`LiveWorkspacePanel.test.tsx:86-91` 锁注释）✓。
- **两套充值入口预设金额不一致**（面板 [50,100,200,500,1000] vs 弹窗 [100,200,500,1000]）【低】；支付用 `window.open`/form `_blank`，Tauri WebView 需确认 shell-open 桥接【中】；充值二维码轮询 2s **无次数上限**（挂机即永久打点）【中】。

### 4.4 发布与数据看板
- 发布管理"正式发布"按钮 `aria-label="正式发布（接口未接通）"`（`ContentPages.tsx:2653`）——诚实未接通，符合 CW-018 登记 ✓；上线前需接通真实发布器。
- 数据看板空态/重试/stale 提示齐全；刷新失败仅 stale 标记无错误详情【低】。

## 8. 布局规范基线（本次确立，后续页面遵循）

- 工作台类页面：**行锁定等高网格**——同一行卡片顶边/底边强制对齐（`grid-template-areas` + stretch），空白留在卡片内部；不做自由错开的双柱。
- 空态三件套：原因一句话 + 下一步 CTA + 视觉锚点；空态卡片高度 ≥ 有数据时的 50%，禁止塌陷。
- 内容量封顶：列表卡固定 slice 上限 + 卡片底部"查看全部"出口，行高不被数据量撑爆。
- 全局：卡片标题一律在卡片内部；≤1100px 单列降级（活动/快捷并列）已有断点，保持。
- 验收口径：任意数据组合下同行卡片顶/底边差 ≤2px；无高度 <160px 的塌陷空态卡。
