```python
def storage_for_asset(conn: BusinessConnection, storage_uri: str) -> StorageAdapter:
    """Resolve the adapter named by a persisted asset URI, including its bucket."""
    reference = storage_object_ref_from_uri(storage_uri)
    if reference.provider == "local":
        local_storage = LocalStorageAdapter(root=local_storage_root(), bucket=reference.bucket)
        require_storage_match(local_storage, reference)
        return local_storage                                    # ← L167-170 历史 local URI 只读追溯
    if reference.provider != "cos":
        raise HTTPException(503, {"code": "STORAGE_PROVIDER_UNAVAILABLE"})
    try:
        config = SettingsRepository(conn).load_provider_config(reference.provider)
    except SettingsUnavailableError as exc:
        raise HTTPException(503, {"code": "STORAGE_SETTINGS_UNAVAILABLE"}) from exc
    if config.get("bucket") != reference.bucket:
        raise HTTPException(409, {"code": "STORAGE_BUCKET_MISMATCH"})
    try:
        cloud_storage = create_storage_adapter(cloud_storage_config_from_settings(reference.provider, config))
    except ValueError as exc:
        raise HTTPException(503, {"code": "STORAGE_SETTINGS_UNAVAILABLE"}) from exc
    require_storage_match(cloud_storage, reference)
    return cloud_storage
```

## 5. 实施决策（已定稿，直接执行）

### 5.1 「正式服务」的判定口径（**本任务最重要的决策**）

规格说「关闭**全部正式服务**本地持久存储回退」，但没定义「正式服务」。仓库里现成的判定有三套：`is_customer_production()`（`bootstrap.py:92`）、`resolve_database_config()`（`db_pg.py:122`，CW-025 刚落地的全环境闸门）、`runtime_settings.active_storage_provider`（运维可改）。

**定稿：以 `runtime_settings.active_storage_provider` 为主闸门，`is_customer_production()` 为兜底闸门。** 理由：

1. `active_storage_provider` 是**业务真源**（存在数据库里，API/Worker 多实例共享），`is_customer_production()` 是**进程环境变量**（每个实例各自读）。多实例生产下，只有数据库里的设置能保证所有实例口径一致 —— 这正是规格「跨实例测试」的诉求。
2. `rbac_routes.py:179` 的 `_customer_character_cache_storage()` **已经用了这个口径**（`runtime.get("active_storage_provider") != "cos"` → `StorageBackendUnavailable`）。沿用它 = 规格「复用现有」，且全仓口径统一。
3. `bootstrap.py:559` 的启动期 readiness 也用了同一口径。请求期与启动期同口径，才不会出现「启动过了、请求落本地」。
4. `is_customer_production()` 作兜底：即使 `active_storage_provider` 因数据异常读不到，客户生产也绝不落本地。

**不引入任何新环境变量**（CW-025 刚刚把全环境判定收敛到 `VIDEO_REPLICA_DATABASE_URL` + `VIDEO_REPLICA_CUSTOMER_PRODUCTION`，再加新变量是反向操作）。

### 5.2 `get_media_storage()` 的新逻辑（定稿，逐分支）

替换 `media_routes.py:147-160`，保持函数签名与依赖注入形态不变（`conn: BusinessReadConn` → `StorageAdapter`）：

```python
def get_media_storage(conn: BusinessReadConn) -> StorageAdapter:
    """业务主存储：源参考视频（拆解需要 HTTPS URL）、人物图片、多视角图与首帧。

    CW-031：正式服务（active_storage_provider="cos" 或客户生产）只允许云端存储，
    缺配置/配置不完整一律 503，绝不回退本地持久盘。内部 P0 单机车道
    （active_storage_provider="local" 且非客户生产，见 gate1_bootstrap.py）
    保留本地适配器——那是桌面单机场景的既定架构，不是"正式服务"。
    """
    from app.bootstrap import is_customer_production      # 局部 import，避免循环依赖（§8 坑 2）
    try:
        repo = SettingsRepository(conn)
        runtime = repo.read_runtime_settings()
        provider = str(runtime.get("active_storage_provider") or "")
        customer_production = is_customer_production()
    except (SettingsUnavailableError, StorageBackendUnavailable, ValueError) as exc:
        raise HTTPException(503, {"code": "STORAGE_SETTINGS_UNAVAILABLE"}) from exc

    if provider == "cos" or customer_production:
        # 正式服务：COS 是唯一合法的持久存储后端，缺配置 = 明确失败，不回退。
        try:
            config = repo.load_provider_config("cos")
        except (SettingsUnavailableError, StorageBackendUnavailable, ValueError) as exc:
            raise HTTPException(503, {"code": "STORAGE_SETTINGS_UNAVAILABLE"}) from exc
        if not config:
            logger.error("Formal service storage is unconfigured (provider=%s)", provider or "<unset>")
            raise HTTPException(503, {"code": "STORAGE_PROVIDER_FORBIDDEN"})
        try:
            return create_storage_adapter(cloud_storage_config_from_settings("cos", config))
        except (StorageBackendUnavailable, ValueError) as exc:
            raise HTTPException(503, {"code": "STORAGE_SETTINGS_UNAVAILABLE"}) from exc

    if provider == "local":
        # 内部 P0 单机车道（桌面场景）。走到这里说明 customer_production 为假。
        logger.warning("Local persistent storage is only valid on the internal P0 single-machine lane")
        try:
            return create_local_storage_from_environment()
        except StorageBackendUnavailable as exc:
            raise HTTPException(503, {"code": "STORAGE_SETTINGS_UNAVAILABLE"}) from exc

    raise HTTPException(503, {"code": "STORAGE_PROVIDER_UNAVAILABLE"})
```

要点：
- **新增错误码 `STORAGE_PROVIDER_FORBIDDEN`(503)**：语义 = 「正式服务要求 COS，但 COS 未配置」。区别于既有的 `STORAGE_SETTINGS_UNAVAILABLE`（设置读不出来/不完整）与 `STORAGE_PROVIDER_UNAVAILABLE`（provider 值非法）。三个码都要在 §5.5 的资产权限矩阵里登记。
- `logger.error` / `logger.warning` **只记 provider 值，绝不记 bucket / ak / sk / DSN / 完整配置**（对齐 `bootstrap.py:571` 只记 `type(exc).__name__` 与 `test_storage.py:483` 的脱敏审计范式）。
- `provider == "cos" or customer_production`：客户生产即使 `active_storage_provider` 被改成 `local` 也走 COS 分支 → 兜底闸门生效。
- **不改** `router`、`LOCAL_API_BASE_URL` 等常量、`storage_for_asset()`（另在 §5.3 处置）。

**本地持久文件新增数 = 0 的断言手法（定稿）**：
```python
def _persistent_file_snapshot(root: Path) -> set[str]:
    """正式服务下不得新增任何本地持久文件；缓存目录 (.cache/storage-cache) 不计入。"""
    if not root.exists():
        return set()
    return {
        str(p.relative_to(root))
        for p in root.rglob("*")
        if p.is_file() and ".cache" not in p.relative_to(root).parts
    }
# before = _persistent_file_snapshot(root); … 触发 COS 故障 …; after = …
assert after - before == set(), f"COS failure must not write local persistent files: {after - before}"
```
