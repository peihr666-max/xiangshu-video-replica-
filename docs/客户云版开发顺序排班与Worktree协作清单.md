## 3. 每次开工前必须检查占用并认领

### 3.1 五项检查，缺一不可

1. 更新远程引用：执行git fetch origin --prune，记录origin/main SHA。只更新引用，不在别人开发目录执行pull/reset/checkout。
2. 阅读任务账本§18、本任务证据、本文、认领登记；检查是否已实现、在制、待评审或条件未触发。若用户已说明在制，即使尚无远程提交，也按占用处理。
3. 检查全部本地/远程同编号分支、git worktree list --porcelain、各相关worktree的git status；同时检查同编号开放PR/Draft PR及近期合并PR的head/merge SHA。PR查询可用GitHub连接器、gh或GitHub API；请求失败不等于不存在PR。
4. 检查前置是否已进入最新main、相应验收是否具备；核对共享文件/函数、接口、迁移head、PG实例/库/端口及进程归属。没有文本冲突也可能存在业务语义冲突。
5. 由集成人串行确认认领结果，再复查一次并取得本机共享认领目录。已有占用/PR/不明WIP时，不创建第二个实现；按既有授权继续原任务或选择另一个已就绪任务。Owner/Reviewer/路径信息不完整时先查真实来源，不编造负责人，也不因记录陈旧自动接管。

### 3.2 两层认领，防止两个会话同时开同一任务

- **跨设备：** 使用远端PR/分支和认领登记交叉检查，由指定集成人串行领取和交接。每任务只对应一个在制主分支；认领后尽早推送带认领记录的本任务分支或Draft PR，使其他设备可发现。不把“刚才扫描为空”当作永久许可。
- **同仓worktree：** 在git rev-parse --path-format=absolute --git-common-dir返回目录下使用codex-task-claims/CW-NNN/。用PowerShell New-Item -ItemType Directory -ErrorAction Stop创建任务目录，**不得使用-Force**；目录已存在即停止重复领取，读取claim.json检查Owner。
- claim.json至少记录：任务编号、Owner/Reviewer或待复核来源、host、会话ID、worktree绝对路径、分支、base SHA、领取时间、文件边界和测试资源。这里只放占用元数据，不放密钥。
- 创建worktree失败时保留失败记录并由原Owner核对后处理；不能因超时/长时间无更新自动释放认领。
- 同仓本机目录锁不跨独立clone/设备，因此不能代替远端检查和串行认领。此机制是开发执行规程，并非已经安装了自动监控器或跨机器锁服务。

认领记录采用CLAIMED→ACTIVE→REVIEW→MERGED→CLEANED。这些是占用生命周期，不是CODE_PRESENT/AUTOMATED_VERIFIED等业务证据等级。

## 4. 新任务必须创建独立 worktree，来源只能是 main

完成§3后，更新远程引用并记录main SHA，然后执行相当于以下操作：

    git fetch origin --prune
    git rev-parse origin/main
    git worktree add -b feat/customer-v3-cwNNN-description <独立绝对路径> origin/main

NNN和description必须替换为真实任务编号和含义，路径不能直接照抄占位符。建议本机路径为仓库上级目录下.worktrees/CW-NNN-description，便于与原项目目录区分；同任务继续开发时使用已登记的原worktree，不另造第二个新任务。

- 创建前确认目标路径不存在、没有同编号在制分支/PR，分支名未被占用；不自动删除旧目录腾位置。
- 创建后记录worktree list、分支、base SHA和状态，再把后续命令的工作目录固定到此worktree。
- 每个**新分支**都从最新origin/main创建，包括修复、文档维护等新任务；没有任务号的文档维护使用明确维护ID和docs/或chore/分支，不自造业务CW编号。
- 禁止从feature分支、另一个worktree的工作区快照或未合并依赖分支创建。前置未合入main时登记WAITING，先处理不依赖该前置的已授权工作。
- 既有任务在主目录中的未提交改动先按Owner交接保护，不为实施新规则直接搬移/清空。新规则适用于新任务，不能破坏用户正在开发的055等任务。
- PG端口、实例/卷和测试库须按任务隔离；固定库名的套件可能忽略仅改库名的DSN，先验证隔离。无法隔离时共享PG全量串行；不能仅因worktree不同就同时跑全量。
- 公共文件由明确Owner写入；各任务提供自己的证据，集成人在对应PR内更新正式账本并解决真实状态冲突，不简单取[x]并集。

- [ ] 纯文档维护做改动文档的链接/依赖/命令/秘密检查；不以它冒充业务验证。当前main要求的全量CI门禁仍执行，不改CI或跳过required checks使本任务通过。CI正在其他PR调整时以已合入main及当前PR实际要求为准。

- [ ] git fetch后核对git log origin/main..HEAD和git diff origin/main...HEAD，只包含本任务；显式git add本任务文件，不用git add .把不明文件带入。
- [ ] 提交说明包含中文开发记录，标题沿用任务英文摘要惯例（CW-NNN: summary；历史T任务沿用原命名）。git push -u origin <本任务分支>，一个PR只承载一个任务。
- [ ] 本地检查后可以创建Draft PR触发CI；PR正文写清问题与行为、前置/文件边界、验证结果、证据层级、未测试项和回退方式。完成所需验证后再转正式评审，未完成检查不写“全绿”。
- [ ] 按当前要求取得secret/Linux质量/Windows NSIS等三门禁及独立评审；评审意见实质处理。合并前重新确认base、head和有效检查，不能用旧SHA通过代替当前结果。
- [ ] 合并由用户或已有明确合并授权的执行者通过正常PR squash merge完成。用户要求“提交远程/合并后清理”不等于自动授权绕过评审或直接推main。无需为本次已授权的普通任务提交/push重复索要许可。
- [ ] 认领更新为REVIEW，登记PR URL与head SHA；CI失败就修复本任务，main失败则暂停后续合并。真实付费、生产数据/COS、发码、灰度、公网发布仍按原授权边界。

如果GitHub连接器失效，先使用已有授权的git凭据/CLI/API完成同仓操作；凭据只能在进程中使用，不能打印或写入代码/文档。仍不能完成时登记实际阻塞和已推送状态，不虚报PR或合并结果。

## 6. 合并后核验，再清理本地 worktree

**只有PR已合并、合并结果进入origin/main且所需验证具备，才可以清理；仅提交、push、PR关闭或任务说“完成”都不够。**

清理前必须逐项检查：

- [ ] GitHub PR merged=true，记录PR URL、最终head SHA和squash merge SHA；fetch后验证merge SHA是origin/main祖先。Squash后原分支tip不必是main祖先，不能仅用git branch --merged判定。
- [ ] main对应所需门禁通过，任务成果与证据可以从远端恢复。后来main变化时，核对相关整合结果，不把取消/失败的旧运行当作通过。
- [ ] 在目标worktree内检查git status --porcelain --untracked-files=all，确认无未提交/未跟踪成果；另检查ignored文件。依赖缓存可重建，.env、截图、导出物、证据日志或用户文件须明确归档，不能被目录删除带走。
- [ ] 本任务开发服务/测试/辅助进程已经停止；只处理登记的PID、端口和容器，不停别的任务，不删除共享数据库/卷。
- [ ] 认领记录已包含远程PR/merge SHA、归档位置、清理Owner；现有任务已停用该目录，没有其他执行者继续写入。
- [ ] 将目标Resolve-Path为绝对路径，确认它是git worktree list登记的本任务目录，位于约定.worktrees根内，且不是原项目目录、Git公共目录或其他任务目录。
- [ ] 从worktree外执行git worktree remove <已核对的绝对路径>。命令失败就检查原因，不加--force，不用Remove-Item -Recurse/rmdir绕过Git保护。
- [ ] 再检查worktree list和路径状态，归档并释放本机认领，更新执行登记为CLEANED。跨设备占用解除由集成人同步，不能只删本地锁就宣称全局已释放。

**默认保留本地分支和远程分支。** 用户本次允许删除的是合并后的worktree目录；分支/回滚引用是另一对象，不顺手删除。没有合并或检查尚未通过，保持REVIEW/MERGED待核验并保留目录。

## 7. 每次任务必须交付的最小记录

| 时点 | 必须记录 |
| --- | --- |
| 开工 | 编号、Owner/Reviewer、main SHA、上次查重时间、分支/PR/worktree检查结果、前置证据、文件边界、PG/端口资源 |
| 认领/创建 | 唯一在制分支、worktree绝对路径、共享claim位置、host/会话、领取时间、远程可发现记录 |
| 实现/验证 | 改动差额、RED→GREEN或复验依据、验证命令与结果、未测试项、证据等级 |
| 提交/评审 | commit/head SHA、PR URL、当前检查、评审处理、回退方式 |
| 合并/清理 | merged确认、squash SHA、main检查、成果归档、进程退出、路径核验、worktree删除结果与占用释放 |

接手者必须实际执行上述检查；不能只在回复中写“已检查”，也不能用本清单初始快照代替实时仓库状态。
