# 爆款视频（C4 重启）进度与后续验证

> 2026-09-06；分支 `codex/frontend-v1.4`。接口和算法正本见《爆款视频TikHub接入-需求理解-2026-09-06.md》，同日追加用户指令见该文档 §9。

## 本轮实现

- **数据库复用**：迁移 062 新建 `viral_videos`、`viral_fetch_state`。两平台结果先落库再返回，平台+视频 ID 去重，历史记录保留。列表 1 小时缓存，分类独立刷新，失败保留成功数据。无需配置源密钥也能读取已有库。
- **统计补采**：新增 `/api/viral/videos/statistics`，可见视频号卡片批量补齐真实点赞、评论、转发、收藏，最多 3 个并发请求。成功缓存 24 小时，失败冷却 10 分钟；空字段显示 `—`，不伪造 0。
- **原位播放**：两平台统一通过服务端媒体缓存取得播放地址。保留原生暂停/继续和进度控件，同页只播放一个视频，切换立即暂停上一条，慢请求不抢播。首次准备允许 120 秒超时。
- **播放链路修复**：抖音排除不支持的 ByteVC 档位并隔离旧媒体副本；视频号本地对象路径解码后签名，修复 `=` 被重复编码导致的文件错误。
- **封面修复**：含 `/` 的视频号 ID 原先路由 404；改为路径参数并校验真实数据库记录。封面缺失时可恢复主存储副本。对库中 132 条封面复查，全部返回有效图片。
- **搜索提速与过滤**：四个分类独立并行，同一视频号分类的 cursor 页仍顺序获取；庭院词改为“农村庭院设计”，过滤游戏内容。
- **密钥与文案**：数据源配置仍由服务端加密保存；客户端响应不含供应商名称或内部缓存标记，日志不输出上游响应正文。没有新增依赖、ORM 或 Redis。

## 收尾与边界

1. 在只包含 C4 的隔离快照验证新增回归及全量门禁，提交时只暂存本轮文件/片段，保留并行首页、素材与人物会话改动。
2. 所有 head 断言与本次提交迁移 062 同步；工作区另有 063 及以后迁移，不混入本轮提交，不修改历史迁移。
3. 浏览器复验两平台暂停/继续、单播放切换和统计回填；记录最终证据。
4. 推送当前分支并运行 CI 三门禁；不将本地测试等同于 CI 或生产验收。
5. 现有互斥针对单桌面服务进程。多实例部署需增加数据库协调，不能声称跨实例绝不重复付费。
6. 上游 `exportId` 和媒体链接可能过期；统计失败会冷却重试，搜索 TTL 刷新最新源信息。上游仍不提供的字段保持缺失。
7. 解密按既有 ISAAC64 已知向量实现；本轮未改密码算法。
