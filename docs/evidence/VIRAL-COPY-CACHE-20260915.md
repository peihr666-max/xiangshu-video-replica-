# 爆款视频文案服务器缓存与逐请求计费

## 目标与边界

用户要求按视频 ID 关联提取文案，首次转写后在服务器持久保存；再次提取直接检索，用户每次独立成功提取仍按现行售价付费。缓存主键为 `platform + video_id`，跨用户共享原始转写文本，不共享用户二创草稿。

独立任务 `VIRAL-COPY-CACHE-20260915`，分支 `feat/viral-copy-cache-20260915`，基于更新后的 `origin/main@d8acbdf`。开工核对远程 PR（#110/#111）、本地/远程分支、worktree、共享 claim，未发现重复任务；既有浏览器媒体缓存和下载修复不在本次实现分支中。

## 实现

- 新增 PostgreSQL 表 `viral_script_cache`，平台与视频 ID 组成复合主键；保存原始文案、确认时长、语言和首次生产任务引用。没有按项目删除的级联关系，成功文案在原项目删除后仍可复用。
- 从服务端成功的 `viral_import_tasks` 关联源资产识别视频；不信任客户端传入的视频身份或资产自定义元数据，不把私人上传混入公共视频缓存。
- 每个接受的新提取请求保留自己的任务、用户、价格快照和账务操作。命中缓存直接成功结算，不创建新的供应商调用记录，不复制首次任务的价格或成本。轮询及同幂等键重放不收费；同项目已有任务时，新键明确拒绝，避免静默合并成免费请求。
- 多实例通过数据库行锁和持久生产任务引用共享首次转写。其他用户的请求等待结果，再独立结算。租约恢复复用原生产任务；无回执的不确定任务、提交后结果不明、生产任务丢失都不会自动再次调用供应商。
- 缓存只接受非空文案与有限正数时长。旧成功任务按可信导入关系惰性复用；升级前的在途或不确定任务同样阻止重复转写。网络请求与转写仍在原有短事务外执行。
- 缓存返回前保留项目/资产授权及余额检查；成功任务、缓存发布和对应结算在同一事务中提交，迟到 Worker 必须通过原有租约条件。

## 验收口径与回退

实现及测试使用假 ASR、独立 PostgreSQL，不新增真实收费调用，不改变用户钱包。现有识别失败及无回执不确定结果仍按原业务恢复规则处理；成功缓存未设置自动过期，以符合只需首次识别的需求。

回退应用代码可停止使用新缓存，追加表保留不会影响旧逻辑；如确需降级迁移，先停止新提取请求并备份缓存表。旧迁移文件保持原字节，新增迁移只创建/删除本表。本文不代表生产部署或真实支付验收完成。
