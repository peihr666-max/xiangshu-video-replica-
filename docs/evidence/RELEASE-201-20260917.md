# 2.0.1 服务端与桌面升级

用户授权将当前主线服务部署到既有宝塔服务器，并生成可覆盖旧版的桌面安装包。代码基线为 `58e147dc`（含 #126–#131 已合并成果），发布分支仅统一版本为 2.0.1，不调整应用标识、产品名称、可执行文件名称或 NSIS currentUser 安装模式。

## 升级合同

- 原版本：2.0.0；目标：2.0.1，版本递增，`allowDowngrades=false` 保持。
- 标识：`com.xiangshu.video-replica.customer`，凭据命名空间保持。
- 产品：短视频复刻客户云工作台，NSIS 通过既有注册项识别安装目录；保留用户自定义路径。
- 本轮不修改卸载/旧版迁移钩子，不清除本机应用数据。
- 签名渠道与实际安装结果记录在最终交付清单；没有证书时不将未签名包冒称正式签名发行。

## 发布边界

- 用户在确认项后回复“允许”，本次按授权清理无引用旧视频应用镜像和可再生构建缓存，保留在用镜像、最近回退镜像、数据库卷与备份，并沿用旧版未签名交付方式。
- `e57e1d81` 的全部 CI 门禁已通过。上传采用 Git 增量 bundle，服务器导入后核对完整 SHA；发布脚本通过进程级 Git URL 映射读取已验证的本地对象，仓库 canonical origin 保留 GitHub URL，避免服务器到 GitHub 的 TLS 故障。
- 首次基础镜像实测发现 Debian 登录式 Shell 重置 PATH，`sh -lc 'alembic heads'` 报找不到 Alembic。基础镜像构建入口现补充 `/etc/profile.d/video-replica-venv.sh`，恢复与 ENV PATH 相同的虚拟环境；实际镜像中 `sh -lc` 下 Alembic head 与应用导入均成功。该环境修正不改变 `server/app` 或桌面制品内容。
- 修正后的 shell 语法检查通过；交付拓扑合同 12 项覆盖通过（Windows 一项初次因默认 GBK 读取 UTF-8 文档失败，显式 UTF-8 复验通过）。既有服务器拓扑已增补 `worker-publish` 和 `worker-viral`，经 Compose 解析逐项核对原服务、网络和卷配置不变。

- 源码已上传至宝塔既有候选环境；发布前检查通过，数据库、站点、配置已备份，数据库备份清单可读取。
