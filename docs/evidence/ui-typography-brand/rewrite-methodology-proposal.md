## 建议采用的统一方法

原文事实与观点 + 人物长期定位（可选）+ 本次目标与要求 → 重组表达 → 事实与口播检查 → 可编辑草稿 → 用户确认终稿。

这是基于调研提出的产品方案，不是声称同行公开了同一内部实现。各阶段是逻辑职责，不必为每阶段分别调用一次模型；第一版可在一次生成请求中使用结构化上下文和规则检查，后续依据质量评估决定是否拆分。

1. 输入：只从视频提取并核对后的原文开始。保留原始提取内容，允许另存纠错版本；不得把提取文本预填成已经生成的二创结果。
2. 内容约束：识别主旨、关键事实、数字、地点、人称经历及待核实说法。原视频里的判断或预测不能自动升级为已证实事实。
3. 改写：按用户目的选择开头、组织信息、调整句长和说话方式；允许重组信息，不以逐句换同义词为目标。
4. 校验：是否遗漏核心信息、添加无依据数字/资质/案例/承诺、挪用他人的第一人称经历；是否遵守本次长度与表达要求。自动检查不能保证事实正确。
5. 用户定稿：显示可编辑结果、字数及必要的待核实提示；保留上一版，重新生成不直接覆盖人工修改内容。生成前没有结果编辑框和终稿操作。

## 两个入口的边界

### 按人物 IP 二创

自动读取已保存的人物姓名、身份、服务范围、目标人群、表达特点。建议后续增加几段用户认可的口播样本、真实案例资料与禁用表达；这些不是第一版必填。

页面默认只需要“选人物”；可选“本次目标/长度”和“补充要求”。人物外貌、照片和声音本身不能推导真实经历或专业资质。档案资料不足时给出补充提示，不虚构人物背景。

示例：身份=乡墅设计师，受众=准备回乡建房的家庭，表达=直接、朴实、有条理。本次要求=重点讲预算规划，结尾邀请评论，不添加报价。

### 按要求二创（建议替代含糊的“自定义”标签）

不强制选择人物。提供可选的目的、表达方式、目标字数，以及一个自然语言要求框。用户写一句要求即可生成；不要求学习提示词。

建议快捷项：更口语化、精简内容、知识讲解、调整开头。保留核心事实是默认规则，不能将“更有冲击力”解释成允许编造信息。

示例要求：改成面向准备回乡建房的家庭的口播，约 200 字，语气朴实，先讲问题再给建议，不编造数据，不做报价承诺。

两种入口共用同一生成服务。“按 IP”也允许本次补充要求；档案中的默认语气和默认长度可被本次要求覆盖，真实事实和已确认禁用项不可被随意覆盖。

## 页面顺序建议

保留用户已同意的上下结构：

1. 原文文案：视频来源、已提取原文、核对/纠错入口；文本框右下角可拖动调整高度。
2. 设置二创：选择“按人物 IP / 按要求”，按选择显示所需字段，再点击“生成二创文案”。分析和检查不要求用户单独点击。
3. 二创结果：生成前显示简短空状态；成功后出现编辑框、重新生成/调整按钮、保存与确认终稿。已有人工编辑时，新结果作为候选稿供替换。

默认先生成一版，避免一开始展示多个长稿增加比较负担；可再生成其他版本。是否同时提供多个开头可留待后续验证。

## 本项目现状与需调整点

依据当前隔离工作区 `server/app/script_rewrite.py` 和 `client/src/studio/PeoplePages.tsx` 只读核对：

- 已有姓名、身份、服务范围、目标人群、表达特点及人物档案快照；应复用，不另建重复人物系统。
- 当前请求模型没有独立的本次改写要求字段。需单独传递、保存并纳入任务重试一致性校验，不能拼入原文污染来源记录。
- 当前固定提示词要求总字数与原文相差不超过 20%。建议改为：用户未设置长度时尽量接近原文；设置长度时按用户目标生成并显示实际字数。
- 当前“避免连续 8 字以上相同”只能是表达层面的粗糙规则，不宜作为质量或原创性判定。专业词汇、地名和必须准确的事实不能为了差异而改错。
- 当前“开头 3 秒必须有新钩子”缺少实际语速依据。建议表述为“开头一至两句突出主题与观看价值”，不自动承诺精确时长。
- 口播长度估算和视频生成计费时长属于不同概念；本方案不改视频时长和计费逻辑。

## 拟确认的第一版范围

- 两个入口：“按人物 IP”与“按要求”，均支持本次补充要求。
- 复用人物档案，先实现来源保真、人物适配、可选长度和自然语言要求。
- 系统内部进行内容检查，用户只操作“核对原文—设置二创—编辑定稿”。
- 生成前不出现伪造的二创结果；保留人工修改和历史版本。
- 先不增加样本学习、独立知识库、复杂多模型链或大量高级参数。

等待用户确认上述方法后再改接口、提示词和交互逻辑。
