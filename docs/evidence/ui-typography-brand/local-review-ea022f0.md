## 本地评审发现

### 1. [P2] 侧栏 Logo 缺少生产构建资源

位置：`client/vite.config.ts:42`、`:63`、`:107`；引用位置 `client/src/studio/StudioWorkspace.tsx:1852`。

侧栏使用字符串路径 `/studio/logo-mark.svg`，构建关闭 `copyPublicDir`，自定义复制只包含 `studio/brand.png`，没有复制新图形。开发预览能访问 public 文件，但正式网页/桌面包将缺少此资源。浏览器 favicon 有单独复制，不受此遗漏影响。

验证：执行实际 `customer-public-assets.writeBundle`，mock 文件复制并断言 logo-mark.svg 被复制；断言失败。见 `review-second-assets.log`。此项没有执行完整生产构建。

建议：将图形加入生产资源复制或使用打包器的资源导入；补齐客户包静态资源契约检查。

### 2. [P2] 较旧的云端 pending 覆盖本地已受理任务，刷新后无法恢复

位置：`client/src/studio/CreationPages.tsx:412`。

`draft.pendingRewrite ?? readPendingRewrite(user.id)` 无条件优先选草稿记录。若服务端已受理任务、sessionStorage 已存 taskId，但云端草稿仍是提交前无 taskId 的 pending，刷新恢复时旧草稿会覆盖较新的本地状态。后面的恢复条件因此不调用任务查询，成功生成的结果可能无法在页面恢复。

验证：模拟提交受理并保存 session taskId，再用相同 scope、缺少 taskId 的旧草稿重新挂载页面；期望调用 getScriptRewriteTask，实际调用0次。见 `review-second-reproduction.log`。

建议：按 scope 合并 pending，优先保留已受理 taskId，并使用版本/时间顺序防止旧草稿回退；保留现有跨账号和跨来源隔离。

### 3. [P2] 240秒 socket 超时不保证五分钟任务租约内结束

位置：`server/app/script_rewrite.py:41`、`:43`、`:705`、`:1035`；工作执行路径 `server/app/generation_worker.py:1432`。

urlopen(timeout=240) 后直接 response.read()，没有请求总截止时间；文案生成阻塞期间没有对应租约续期。供应商持续返回保活数据时，请求总时间可能超过五分钟。其他 worker 随后会把已发送请求的过期任务标为 SUBMISSION_UNCERTAIN，后续返回的成功结果不能正常落入已失去租约的任务，存在请求已消耗但用户拿不到结果的风险。

[DeepSeek 官方说明](https://api-docs.deepseek.com/quick_start/rate_limit/#request-keep-alive-mechanism)明确描述非流式响应可能持续返回空行，且排队十分钟未开始推理才关闭连接。官方资料支持保活行为，任务租约影响来自本仓库代码分析。

建议：实现真正的请求总截止时间并与租约协调，或提供有上限的租约续期及可靠结果回收；不能仅增加 socket timeout。更正之前“240秒保留一分钟租约余量”的表述。

### 4. [P2] 全部文本 AI 统一 DeepSeek 尚未完成

位置：`server/app/analysis.py:298`；`server/app/script_rewrite.py:978`、`:1110`。

视频拆解的 JSON 修复仅输入文本，仍调用 ApilioGemini 的 self._complete。新的 request_deepseek_text 虽允许 rewrite/analysis/title/prompt，但实际生产调用方仅接入 rewrite。通用参数存在不能等同于各文本业务已接通。

建议：盘点并切换所有现有纯文本调用，包括 JSON 修复；逐个核实文案分析、标题、视频提示词优化的实际入口和路由。视觉视频分析保留视觉模型是合理的，不属于本问题。
