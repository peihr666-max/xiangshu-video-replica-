# 定时采集、人工精选与共享云媒体

状态：CODE_PRESENT；专项复验、独立终审及完整门禁进行中。

## 最终业务流程

1. 管理员在“爆款视频”运行控制中设置平台、分类、关键词和每词最大数量。最多 20 个关键词、每词 1–50 条；搜索接口实际返回不足时以返回数量为准。空关键词配置不会发起采集。
2. 管理员选择“每天”或“每周”。独立 `worker-viral` 以 PostgreSQL 时间检查到期日；首次配置启动首轮，之后每 1/7 天一轮。多个进程通过单例行锁只建立一组任务；每批冻结关键词配置。更改周期时重新计算下次执行时间，开关切换不重置周期。
3. 每个关键词的搜索结果去重写入 PG，保存标题、作者、时长、互动统计、发布时间、分类、源 ID 等首页数据。单关键词失败继续其他关键词，成功步骤记录 checkpoint。
4. 服务端转存封面；视频号详情补齐统计并取得解密参数，分块解密到临时文件，再上传管理员配置的主存储。PG 保存已验证的永久 storage_uri；不保存会过期的下载签名作为唯一播放依据。
5. 全平台批次完成才发布普通爆款列表并更新固定七日内容窗口。失败保留上轮列表，15 分钟后最多续做两次；下个周期开始新批次。不存在可用旧批次时普通列表保持空并显示采集状态。
6. 管理员在独立“爆款视频库”页面查看全部采集记录（含待转存/失败记录）、统计、云存储地址及云端预览，按平台和标题/作者/ID 搜索、分页。新记录 `homepage_featured=0`，经过人工筛选并确认才显示在首页；人工选中的已归档旧视频可以继续展示，不被定时批次替换。取消精选即时影响后续首页读取。
7. 删除采用 PG tombstone；管理列表、前台列表/收藏/详情/播放/新导入均不可见，后续 upsert 保留删除状态，不重复转存。已有项目独立副本和共享存储对象保留；每次精选/取消/删除通过管理员写契约、CSRF、原因、幂等及审计。已签发短期下载地址依原有效期到期。
8. 首页、列表、统计和点击播放读取数据库；播放对已存对象生成新签名，封面走已归档对象。缺素材返回可重试状态，不因点击偷偷调用源接口。列表不发布未转存的视频或封面。
9. “用于复刻/提取文案”从共享成品生成用户项目独立副本。跨用户、跨进程共享下载/解密结果；项目副本包含导入 attempt，迟到清理不会删除新副本。
10. 用户主动粘贴链接解析是单独业务，保留原计费契约。媒体准备失败完成失败凭证与退款，重放不重复请求。云存储和已入库列表读取不向用户扣分；后台供应商调用进入现有平台成本记录。

## 部署入口

默认客户 compose 增加 `worker-viral`，普通四个生成 Worker 不认领采集任务。开发入口为 `npm run dev:viral-collection`；既有 PG/bootstrap 与生产安全检查保持生效。新增进程后连接池预算 60 ≤ 120。正常 rollout 更新采集进程；回滚停止采集进程，防止旧镜像不识别新参数，后续成功发布再恢复。

本任务只修改交付代码，没有启动真实采集服务，没有接触联合调试运行中的容器、用户数据库或真实 COS。上线后需使用已配置的主存储和数据源、启动独立采集进程并配置关键词。

## 实现与评审

- 下载与上传使用分块文件流；本机仅服务端临时文件，完成或异常即清理。媒体前缀仅缓存 128 KiB，视频最大 512 MiB；封面限制 10 MiB。
- 媒体对象按存储命名空间、处理版本及 attempt 隔离；PG 租约续期、条件更新发布、过期接管。已完成对象的认领使用读取快照 CAS，防止完成瞬间重复下载。
- 发布结果以云端 HEAD 的长度和 SHA256 校验；写数据库结果不确定时保留不可变对象，避免删掉已发布素材。不设置共享媒体自动删除策略。
- 保留既有 URL/重定向/固定 DNS 地址/SSRF 检查、Windows ffprobe 文件关闭规则。
- 独立评审逐项修复：完成瞬间重复认领、媒体异常漏退款、未准备视频进入列表、采集占用生成 Worker、关键词失败阻断后续项、暂停后新发详情请求。
- 追加需求评审修复：checkpoint 仅在事务成功后替换内存状态；首页精选独立保存到 homepageVideos，普通榜单/解析与首页异步响应不会相互覆盖；本地管理预览转换成签名 HTTP；管理列表仅含定时采集支持的抖音/视频号；隐藏视频不能误设置为首页展示。
