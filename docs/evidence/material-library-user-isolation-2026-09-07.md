# 素材库前后端联动与用户隔离修复证据（2026-09-07）

## 结论

素材库的列表、按 ID 恢复、上传、完成上传、修改、隐藏、下载和音频口播复用已经按用户身份在服务端执行权限判断。普通 `employee` / `customer` 只能看到并使用自己的素材；用户偏好记录不能扩大素材访问范围。前端同时按角色和服务端返回的动作收起无权入口，但前端隐藏不是安全边界。

代码与自动化证据达到 `AUTOMATED_VERIFIED`。本分支尚未部署到生产，真实客户 bearer 会话下的浏览器预览、COS CORS 和付费口播生成仍需部署后 UAT。

## 角色矩阵

| 角色 | 列表与恢复 | 修改与隐藏 | 上传内容与完成 | 下载私有对象 | 用音频生成口播 |
|---|---|---|---|---|---|
| `employee` / `customer` | 仅本人 owner；外国 ID 返回 unavailable/404 | 仅本人 | 仅上传任务创建者 | 仅本人授权资产 | 仅本人项目音频或本人上传音频 |
| `admin` | 可跨用户监管 | 可写管理员自己的显示偏好，不改变素材 owner 的视图 | 不能替他人写入或完成 | 保留监管下载能力 | 不能使用他人音频生成 |
| `auditor` | 可读审计范围元数据；历史 DIRECT 可预览 | 禁止 | 禁止 | 禁止 | 禁止创建口播任务 |

## 修复内容

- `server/app/materials.py`
  - `allowed_actions` 按 actor 角色生成，避免审计员拿到后端实际拒绝的按钮声明。
  - `allowed_uses` 只保留已有真实消费接口的 `oral_audio`；图片原画面、首帧、尾帧和参考生视频仍属于独立创作接口 C2。
  - 项目音频必须同时具备有效大小与 SHA256 才标记为 ready。
  - 本地内容 PUT 与上传完成都严格校验 `created_by_user_id == actor.id`，管理员也不能代完成。
  - 上传地址只写用户目录下的 `upload.*` 临时对象；服务端校验后固化到带内容哈希的 `original-<sha256>.*`，数据库以条件更新只接受一个完成结果。重复完成直接返回既有结果，未获胜请求清理自己的正式对象，旧上传地址或并发完成请求不能覆盖另一份正式内容。
- `server/app/oral.py`
  - 服务层禁止审计员创建口播任务。
  - AUDIO 模式按项目 owner 或无项目资产 creator 校验；管理员/审计员的全局读取权不能转化为生成使用权。
- `client/src/studio/ContentPages.tsx`
  - 当前页最多 6 条素材加载真实签名预览，卡片与详情复用同一个在途请求；签名请求失败后可重试，媒体地址失效时自动刷新一次。
  - 审计员不显示上传、下载、修改、隐藏和复用操作。
  - 隐藏末页唯一素材后自动回到有效页。
  - 删除没有后端提交链路的图片/视频复用按钮。
  - 通用口播音频不再用空 `personId` 清除当前人物和分身。
- `client/src/studio/state.ts`、`CreationPages.tsx`、`StudioWorkspace.tsx`
  - 音频选择器、页面就绪状态、确认前和真正提交前统一要求素材已保存且包含 `oral_audio`。
- `server/app/media_routes.py`、`storage.py`
  - 私有对象代理支持单段 HTTP Range；COS 只读取请求的字节区间，响应包含 `206`、`Content-Range`、`Content-Length` 和 `Accept-Ranges`，返回长度不符时按存储故障拒绝响应。
