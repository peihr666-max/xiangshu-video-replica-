## 请求与范围

用户要求抖音、小红书和视频号在现有用户中心显示二维码，扫码确认后账号显示在对应平台标签下。独立分支 `fix/publish-inline-qr-20260916`、worktree `.worktrees/PUBLISH-INLINE-QR-20260916`，基线 `origin/main@f0b45b2b2558487adb8981635153cc7afb5da925`。旧扫码任务已通过 #117 合入；开工核对远程 heads、本地分支、worktree 和共享 claim，认证 GitHub API 返回开放 PR 为空。

## 实现

- 空平台点击即开始扫码，已有账号的平台点击只切换列表，可继续用“扫码添加账号”添加更多账号；审核用户不能发起扫码。
- 三个平台共用扫码面板，正常路径不显示“打开官方窗口”；额外验证或连续检测失败时保留手动入口。
- Windows 登录窗口默认隐藏、无焦点、无任务栏项；主动打开已有账号执行发布仍显示官方窗口，清理资料窗口保持隐藏。
- 顶层二维码由 Rust 每次轮询主动读取，视频号通过限定来源、窗口和 URL 的消息主动刷新官方 iframe，减少隐藏窗口计时器节流导致旧状态的问题。首次导航短暂无响应给予 45 秒加载窗口，持续失败仍显示重试入口，原 5 分钟会话限制保留。
- 平台返回验证后的账号信息即更新当前平台列表，不依赖额外列表请求。切换平台只展示该平台账号；重新登录按账号 ID 更新，取消、解绑、用户隔离和原存储机制保持。
