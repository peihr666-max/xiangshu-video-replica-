## 二、每个新任务必须执行的开工检查

### A. 刷新实况，确认任务值得做

- [ ] **更新远程基线**：核对remote确为本项目，执行git fetch origin --prune，记录origin/main完整SHA和核查时间。不在他人目录pull、reset或切分支。
- [ ] **阅读正本**：最新AGENTS、任务账本§18、本任务DoD/规格、文件映射、排班、认领登记及前置证据；历史快照只作线索。
- [ ] **查已有实现**：读取代码、测试、已合并PR和证据，明确已具备能力、本任务剩余差额与不适用项；不把“账本未勾选”直接当作需要重写。
- [ ] **核对范围决定**：游客不启用、支持平台、数据路线、pre-GA/GA边界等采用已签认且适用的记录；未合并PR不当作main已具备的实现。

### B. 查重与核对前置

- [ ] **查执行占用**：交叉检查用户已说明的在制任务、认领登记、共享claim、本地/远程同编号分支、开放PR/Draft PR、近期合并PR、git worktree list及相关目录git status。查询失败或工作区无未提交修改都不能证明无人开发。
- [ ] **处理已有占用**：存在Owner、开放PR、独有提交或不明WIP时，继续既有授权交接或改选任务；不新开重复分支，不因记录过期自动抢占。
- [ ] **核对全部适用前置**：每项记录合入main的SHA、验收证据和剩余限制。PR closed不等于merged，功能分支有代码不等于main具备；前置未合入main时等待。
- [ ] **核对main与测试可信度**：记录相关CI检查的head、实际执行步骤及结果；核对分片清单和当前测试全集。源码文件数、已收集用例数和实际执行数分开，不固定抄“113”。路径过滤跳过不等于通过全部业务测试。
- [ ] **明确失败影响**：相关main检查失败或覆盖缺失，要注明与本任务的关系及承接Owner；依赖受影响成果的实现/验收等待处理，其他独立工作照常推进。修复该问题本身的任务可从main开展。

### C. 划清任务与验证边界

- [ ] **写清可验收结果**：目标、要改的行为、不包含的范围、失败场景、对应测试、证据等级和回退方式。
- [ ] **明确文件与接口归属**：主改文件、新文件登记、共享文件Owner、API/DTO、迁移head、配置和公共账本回填人。先解决共享写入冲突，再并行实现。
- [ ] **确认Owner与Reviewer来源**：登记实际执行者和评审安排；尚未分配Reviewer时如实记待分配，在正式评审前落实，不编造已完成独立评审。
- [ ] **准备验证路径**：业务任务先红后绿，开发期跑专项，收尾按最新AGENTS执行本地/CI门禁；纯文档做对应静态核对与秘密扫描。不为“开工检查”在每轮重复跑全量。
- [ ] **隔离环境资源**：确认本任务所需依赖、PG、库、端口、容器名、卷和PID归属。只改DSN或端口并不一定隔离固定库/容器；脚本固定共享名字时应排串行，不能因worktree不同直接并发全量。
- [ ] **确认实际操作授权**：普通开发、检查、提交按已授权范围推进；真实支付/付费Provider、生产数据/COS、发码、灰度、公网发布只在需要该动作时核对已有明确授权。已获授权不重复询问。

### D. 认领，然后从main建立独立worktree

- [ ] **串行认领并再次查重**：创建前重查分支、PR、worktree和claim，登记Owner、host/会话、文件边界、测试资源及查重结果；跨设备由集成人协调。
- [ ] **取得本机唯一认领**：在git公共目录下创建codex-task-claims/任务编号/。用New-Item -ItemType Directory -ErrorAction Stop，不带-Force；已存在即读取归属并停止重复认领。本机锁不能代替跨设备检查。
- [ ] **再次更新main**：fetch后记录实际创建基线；main有相关变化时重新核对前置与文件边界。
- [ ] **从最新origin/main创建新分支和独立worktree**：任务号、分支名、目标绝对路径均未占用。不从功能分支、未合并PR、其他任务快照派生；没有CW号的维护任务使用明确维护ID，不自造CW号。
- [ ] **核对创建结果**：确认当前目录、分支、HEAD、工作区状态与登记一致；后续命令固定在本任务worktree。已有任务续做使用原登记目录。
- [ ] **检查upstream**：由origin/main创建时Git可能自动跟踪origin/main；如发生，取消此自动跟踪。首次推送显式git push -u origin 本任务分支，不能裸push到main。
- [ ] **记录开工结论**：适用项均有证据则READY；存在未满足的前置/占用/资源则WAITING，并写清具体原因、承接人及可继续的独立工作。WAITING不代表已经创建实现分支。

## 三、创建分支的操作模板

先完成上面的查重、前置和认领；下面是占位模板，不可把尖括号文字直接执行。

    git fetch origin --prune
    git rev-parse origin/main
    git worktree add -b feat/customer-v3-cwNNN-description <独立绝对路径> origin/main
    git -C <独立绝对路径> branch --show-current
    git -C <独立绝对路径> rev-parse HEAD
    git -C <独立绝对路径> status --short

若新分支自动跟踪origin/main，在新worktree中取消该upstream，再在首次推送时显式设置同名远端分支：

    git -C <独立绝对路径> branch --unset-upstream
    git -C <独立绝对路径> push -u origin feat/customer-v3-cwNNN-description

取消upstream不会改变分支的main起点。只有确认自动跟踪存在时才执行取消命令。首次push应包含本任务认领或交付记录，便于其他设备发现占用；一个任务一个PR。
