# 发布账号扫码部署与验收

个人中心 → 发布账号 → 点击抖音、视频号或小红书 → 当前面板显示官方二维码 → 手机确认 → 平台返回账号 ID 和昵称后保存并显示在对应标签下。已有账号的平台点击后只查看该平台账号，使用“扫码添加账号”可连接更多账号。

## 两种运行方式

| 环境 | 二维码来源 | 登录状态保存 |
| --- | --- | --- |
| Windows 客户端 | 后台隐藏的官方 WebView2 窗口，二维码显示于用户中心 | 原有逐用户、逐账号独立的本机 WebView2 资料目录 |
| 网页端 / macOS 客户端 | 服务器隔离 Chromium 中的官方页面 | PostgreSQL `publish_browser_accounts.storage_state_enc`，Fernet 加密 |

Windows 本机账号保留独立 WebView2 资料目录，并在连接成功后按下节流程同步服务端；网页端与 macOS 客户端直接使用云端账号列表。网页端无须安装客户端。云端扫码流只返回账号标识、昵称、验证时间及短期二维码，不返回 Cookie、localStorage 或 IndexedDB。解绑删除对应登录状态。

## 服务端部署

1. 先备份数据库，按现有流程执行新增 Alembic revision `20260915T1200_browser_accounts`，不修改历史迁移。新增两个表，旧手动凭据和发布任务表保留。
2. 按锁文件安装 Python 依赖；设置既有 `VIDEO_REPLICA_SETTINGS_KEY`（实际环境变量定义见 `app/settings.py` 的 `SETTINGS_KEY_ENV`），使用服务端密钥管理保存 Fernet 密钥；变更/丢失该密钥会导致旧状态无法解密。
3. 运行 `uv run --project server --locked python -m playwright install --with-deps chromium`。浏览器目录必须由 API 进程用户可读，使用统一 `PLAYWRIGHT_BROWSERS_PATH`。
4. `deploy/customer/bootstrap-base-image.sh` 已加入 Chromium 与系统库安装。本次改变 Python 依赖，现有 `customer-git-rollout.sh` 会要求先发布依赖基础镜像；保留该检查，不应直接绕过。
5. 沿用 HTTPS 同源入口和认证头。扫码 POST 返回 NDJSON 流，响应带 `X-Accel-Buffering: no` 和 `Cache-Control: no-store`。现有 Nginx `/api/` 300 秒读取超时满足心跳流；上游 CDN 不应缓存或缓冲这条接口，也不能重试 POST。
6. API 主机需可访问三个平台官网及其官方登录/CDN域名。每个账号扫描最多 5 分钟；全服务最多 4 个同时扫描，每个用户最多 1 个，使用 PostgreSQL 协调，无需负载均衡粘性会话。断线/取消关闭浏览器，进程异常残留的名额在过期后回收。
7. 抖音进入官方创作者后台但尚未识别账号时，每 3 秒通过同一浏览器上下文的官方身份接口主动复核，单次超时 5 秒且禁止重定向。只有返回有效账号 ID 和昵称才保存；后台 URL 本身不代表登录成功。此逻辑在 API 服务内，更新 Mac 安装包不能替代服务端更新。

浏览器平台登录可能出现手机验证或额外验证。Windows 在额外验证或持续读取失败时提供“打开官方窗口”入口；打开成功后自动恢复已暂停的结果检测，识别账号后沿用既有保存和关窗流程。正常扫码无需弹窗。网页端与 macOS 云端扫码会显示验证提示并允许重新获取，不提供 Windows 专用的本地官方窗口。没有实现验证码绕过，平台额外验证能否完成需在实际部署网络和账号上验收。桌面代码修复需要重新构建客户端，不能只替换服务器网页资源。

## 验收步骤

分别在 Windows、macOS 客户端和网页端对三个平台执行：显示二维码 → 手机扫描并确认 → 个人中心出现正确平台账号和昵称 → 刷新页面/重启后仍能列出 → 验证或重新登录可读取对应状态 → 解绑后不再列出。

同时验证连续三次检测失败后打开官方窗口能自动恢复、取消或切换账号后的迟到开窗结果不恢复旧扫码、过期重取、取消后无迟到账号写入、断线后可重试、另一工作台用户不能查看或删除账号、扫码期间工作台会话被替换后不能保存。

只提取到二维码不等于真实登录成功。当前自动化覆盖账号保存和隔离；手机确认与真实登录状态复用必须由账号持有人完成。此变更处理扫码添加/验证/解绑；发布投递读取的正是这里保存的登录态（见下节）。

## 发布投递与桌面登录态上传（PUBLISH-DELIVERY-20260917）

- 服务端新增 `worker-publish`（`python -m app.publish_worker --idle-seconds 3`）：投递 `publish_records` 队列（立即或到 `scheduled_at` 时刻）并继续承担账号探针。基础镜像需 Node.js（抖音签名）；`VIDEO_REPLICA_PUBLISH_BROWSER_FALLBACK=0` 可关闭浏览器兜底（PR-B 实装前该路径为不可用桩）。
- Windows 客户端扫码成功时，WebView2 profile 的 cookies + localStorage 会以 Playwright `storage_state` 形状一次性导出，由工作台调用 `POST /api/studio/publish/browser/accounts/import` 加密写入 `publish_browser_accounts`（`source='desktop'`）；本机 profile 仍保留用于「前往官方发布」。个人中心账号行显示「已同步服务端 / 服务端未同步 / 登录态失效」，未同步可点「同步到服务端」重试（隐藏窗口重新读取身份后导出）。
- 验收补充：桌面扫码后 `SELECT source, status FROM publish_browser_accounts` 出现 `desktop, connected`；发布页选择该账号「立即发布」后记录进入 `queued → publishing → published/failed`；平台拒绝登录态时账号转 `invalid` 且个人中心提示重新扫码。真实平台发布须持有人授权后进行。

## 回滚

回退应用版本前停止新的扫码并等待现有流结束。旧应用可保留新增表而忽略它们；只有明确允许删除云端扫码账号时才执行 downgrade，降级会删除新增账号密文和扫描名额。不能以数据库恢复代替密钥备份。
