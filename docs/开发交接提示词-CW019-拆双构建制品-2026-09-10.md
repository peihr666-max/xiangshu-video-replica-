### 5.1 总体方案：Vite MPA 双入口 + 双 outDir 物理分离

不用「同一 dist 内两个 html」、不用「懒加载隐藏」、不用「env 条件动态 import」。理由：验收底线明确要求「不是用懒加载留管理 chunk」且「生产构建依赖图及解包文件均无管理/内部入口」，只有物理分离的两个 outDir 能被产物清单/哈希直接证明。

## 8. 必踩的坑（已在上游会话验证过同类问题）

1. **Node 版本**：见 §2，忘加 PATH 前缀 → vitest 全部 worker 崩溃且报 `bad option: --no-experimental-webstorage`，看起来像「没有测试」而不是报错，极易误判为通过。
2. **`tsconfig.node.json` 的 include**：新增 `vite.admin.config.ts` 不加进去 → `tsc -b` 静默不检查该文件，biome 也可能漏；加了之后若配置里有类型错误会立刻暴露。
3. **Vite 自动扫描 html**：Vite 8 在 `rollupOptions.input` 缺省时以 `index.html` 为入口，但**必须显式钉住**，否则后续任何人加 html 都会被卷进客户包，破坏本任务的核心断言。
4. **`base: "/admin/"` 的副作用**：管理产物里的资源路径带 `/admin/` 前缀，直接用 `file://` 或根路径打开会 404。验证时要按 §6.7 检查路径前缀，不要当成 bug 去改回 `/`。
5. **`emptyOutDir`**：`dist-admin` 是新目录，Vite 对 `outDir` 在 `root` 之外或新建时会交互式确认；必须显式 `emptyOutDir: true`，否则 CI 非交互环境会挂住或跳过清空导致陈旧产物混入。
6. **Tauri `frontendDist: "../dist"`**：客户 outDir 名字**不能改**。若为了「更清晰」把客户产物改成 `dist-customer`，内部 NSIS + 客户云 NSIS 两条 CI 门禁会同时断，且 Windows 门禁本地跑不到（只在 CI 执行），会在 push 后才发现。
7. **本地跑不到的四项**：`cargo test`、`npm audit`、客户浏览器 E2E（`npm run test:customer-e2e`）、`npm run build` 的 CI 侧完整链路中，Rust/构建/依赖类问题**以 CI 结果为准**；本地 `npm run check` 不含这四项。
8. **`npm run check` 末尾含服务端全量 pytest**（1446+ 用例，21–30 分钟），每任务只跑一次，在收尾时跑；开发期只跑受影响专项。跑之前必须 `scripts/pg-fixture.sh start`（Docker PG16，端口 5433；脚本必须带子命令）。**严禁两个全量 pytest 实例同时打同一个 PG fixture**（5 个文件共享 `customer_v3_test`，并发互踩造成假性失败）。
