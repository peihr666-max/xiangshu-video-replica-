# 视频复刻：参考生视频（Ref2VA）方案与提示词修改意见（2026-09-16）

> 回答三个问题：
> 1. 同行的"视频复刻"是怎么做的？我们该采用什么方案？
> 2. 我们现在的提示词和后续步骤，逐项对比后要改什么？
> 3. 多人视频如何做到"换掉其中一个人 / 换掉几个人"？界面上文生视频、参考生视频为什么不可用，怎么解决？
>
> 代码事实全部来自主线 `xiangshu-video-replica-/`（含未提交的 v7 改动）；外部依据来自 MiniMax 官方 H3 提示词规范与同行公开资料，出处见文末。

## 0. 结论摘要

**动作不准、提示词不够细，根因有三个，都不是"再把中文写得更详细"能解决的：**

| # | 根因 | 代码位置 | 后果 |
|---|---|---|---|
| 1 | **动作靠文字转述**：原视频 → Gemini 拆解成枚举（WALKING / toward_camera …）→ 代码映射成中文句子 → H3 凭句子想象动作。两次有损转换，H3 从没"看过"原视频 | `analysis.py::analysis_instruction`、`generation.py::render_shot_motion_clause` | 步态、手势时机、转身幅度、走位路径全靠猜；这就是"人物动作不够准确"的直接原因 |
| 2 | **提示词格式是自创的，不是 H3 官方结构**：官方要求 `[Shot N] At MM:SS.mmm`、`(S1)` 说话人、`<d>[Chinese] …</d>` 台词、`overall_soundscape` / `non_diegetic_music` 分段、I2V 首行固定对齐语；我们是"intro / continuity / style / shot / script / audio / narration_sync"七段中文 | `generation.py::H3_PROMPT_TEMPLATE_SPEC`（v7） | 模型对非官方结构的遵循度明显低（官方 GitHub issue 也指出"raw one-line prompts under-perform"）；台词没有说话人 ID，配音与镜头对不上 |
| 3 | **时间轴被强行缩放**：客户只能选 4 或 15 秒，`timeline_scale = 输出时长 / 源时长` 把每个镜头的起止时间等比拉伸/压缩，台词却不变 | `generation.py::compile_prompt_text` L7172、`CUSTOMER_DURATION_OPTIONS = {4, 15}` | 12 秒的源视频被拉成 15 秒或压成 4 秒，动作节奏与口播必然失真；>15 秒的源视频根本无法 1:1 复刻 |

**同行的共同做法**（Vidu 参考生 Pro、即梦 Seedance 2.0、可灵动作控制、Runway Act-Two、Wan-Animate）：**把原视频直接作为"动作 + 运镜 + 节奏"参考喂给模型，人物图作为"身份"参考，文字只负责说明"谁是谁、保留什么、替换什么"**。MiniMax H3 自己也走这条路：Ref2VA 模式支持 ≤9 图 + ≤3 视频 + ≤3 音频，官方示例原话就是"人物参考视频1的动作，表演街舞，人物参考图1图2"、"水豚必须严格遵循原视频的运动轨迹"。

**推荐方案（一句话）**：复刻主链路从 **I2V（首帧置换 + 文字描述动作）** 切换为 **Ref2VA（原视频片段 = `<Video 1>` 动作/运镜/切点参考，角色库人物 = `<Subject N>` 身份参考，拆解结果只用来写 subject_definitions / retention_analysis / detailed_description）**。多人视频每个人一个 `<Subject N>`，用户逐个决定"保留"或"替换成某角色"。

**图生视频 / 文生视频的提示词**（复刻流 I2V 与独立创作页 T2V / I2V / 首尾帧）单独展开在 §9：复刻流 I2V 给出完整编译示例与 v7→v8 逐段改法；独立页用户只有"一张图 + 一句话"，必须加一个看图的提示词助手把它扩成官方 I2VA 结构，系统提示词已写好。

**T2V / R2V 界面不可用不是 bug**：是管理端总开关 `runtime_settings.h3_extended_modes_enabled` 默认 `FALSE`（migration 075），设计上要等"供应商付费探针 4a"跑通后由管理员手动打开。解决 = 跑 3 次真实付费探针 → 修 2 个协议风险 → 管理端开关打开（§6）。

## 1. 同行"视频复刻"做法调研

| 产品 / 模型 | 复刻方式 | 输入 | 动作准确度的来源 | 对我们的启示 |
|---|---|---|---|---|
| **MiniMax H3 官方（我们的供应商）** | Ref2VA 全参考模式 | ≤9 图 + ≤3 视频（每段 2–15s，合计 ≤15s）+ ≤3 音频，总 ≤12 文件 | 参考视频直接提供动作、运镜、切点；用 `retention_analysis` 声明 `attribute_transfer`（把原视频人物的动作转移到参考图人物） | 我们已经付费接入的模型本身就支持，不用换供应商 |
| **Vidu Q2 参考生 Pro** | "万物可参考" | 4 图 + 2 视频 | 上传原视频保持动作，用图替换主体 / 背景 | 与 H3 Ref2VA 同构 |
| **即梦 Seedance 2.0** | 多模态参考 | ≤12 参考文件（图/视频/音频/文） | 自动学习构图、人物特征、动作风格 | 界面形态：素材槽 + 每个素材标注用途 |
| **可灵 Motion Control / 动作控制** | 动作模仿 | 1 张人物图 + 1 段动作视频 | 逐帧跟随动作视频的骨架 | 单人换身份的最强路线，但只做"一人一视频" |
| **Runway Act-Two / Wan2.2-Animate** | 表演迁移 | 参考人物图 + 驱动视频 | 面部表情 + 身体动作逐帧驱动 | 同上，多人需分层 |
| **通用方法论（掘金等社区）** | 拆成"主体 + 动作 + 运镜 + 风格"四要素再重组 | — | — | 我们的拆解已经是这个结构，缺的是让模型"看"到动作 |

**共识**：动作准确度来自"视频参考"，不是来自"文字描述"。文字描述动作只在没有参考视频时兜底。

## 2. H3 官方提示词规范 vs 我们的 v7 提示词

官方规范来自 MiniMax-H3 仓库 `skills/h3-prompt-writing/references/base-en.txt`（T2VA/I2VA/FL2VA/L2VA）与 `ref-en.txt`（Ref2VA）。

### 2.1 I2V（我们当前用的模式）

| 维度 | 官方要求 | 我们 v7 | 差距 |
|---|---|---|---|
| 首行 | 固定句 `For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.` + 空行 | `生成一条 {duration} 秒、{resolution}、写实短视频，从提供的首帧自然开始；…` | 缺官方对齐语；分辨率/时长写进正文是冗余（API 参数已有） |
| 字段结构 | `integrated_multimodal_description:` / `overall_soundscape:` / `non_diegetic_music:` 三个命名字段 | 七段无字段名的自然段 | 完全不同 |
| 镜头标记 | `[Shot 1]` 无时间戳；`[Shot N] At MM:SS.mmm, the shot cuts to …` 只标切入时刻 | `[00:00.000-00:03.200] 近景，人物居中，固定机位；…` 标起止区间 | 格式不同；官方不标结束时间 |
| 风格 | 在 `[Shot 1]` 开头一句：`Live-action, cinematic, a medium shot frames …` | 独立 style 段 `整体视觉风格：…；主色调：…` | 位置不同，可合并 |
| 运镜词表 | 固定英文词表：Push In / Pull Out / Truck / Pan / Tilt / Pedestal / Arc Shot / Tracking Shot / Static Shot / Zoom / Shake / POV / Roll + `with small/large amplitude` + `at slow/fast speed`，写成自然句子 | 12 个枚举 → 中文标签（"手持平稳跟拍"） | 缺幅度和速度两个维度；`HANDHELD_TRACKING` 应拆成 `Tracking Shot` + `Shake Slightly` |
| 说话人 | 稳定 ID `(S1)`、`(S2)`，首次出现要给音色/语速描述；台词 `<d>[Chinese] 原文</d>`；旁白用 `says in an off-screen voiceover` + 嘴闭合说明 | `口播意图：{spoken}`，无说话人 ID，无语言标签 | 缺失。这是"配音脱离时间轴"和多人对话必然乱的原因，`narration_sync` 段是在补这个洞 |
| 跨镜头台词 | `<scenetrans>` / `<cutoff>` 标记 | 无 | 缺失 |
| 画面文字 | 英文双引号原样保留 | 无 | 缺失（爆款视频大量有字幕/标题） |
| 环境音 | `overall_soundscape:` 1–4 句，只写环境/动作声，不重复台词 | audio 段拼接各镜头 `ambient_sound` | 结构可对齐 |
| 配乐 | `non_diegetic_music:` 写乐器/速度/动态，禁止抽象情绪词；无则 `N/A` | `配乐风格：轻电子，节奏偏快` | 可对齐 |
| 语言 | 结构性文本英文，台词/歌词/画面文字保留原语言 | 全中文 | **需 A/B 验证**：H3 是中文公司模型，官方中文示例也存在；但官方 Skill 明确要求结构文本英文。建议先按官方结构 + 中文内容跑一版，再做英文结构 A/B |
| 身份锁定 | `preserving her appearance, clothing, seat position, and the carriage layout`（一句，随首帧描述） | continuity 段 60 字强约束 + 每镜头重复"主体：已确认首帧中的人物" | 我们更啰嗦；官方靠首行对齐语 + 首镜头描述即可 |
| 长度 | 生成任务 `detailed_description` 350–500 英文词；≤7000 字符 | 未控制 | 需要给编译器加预算 |

### 2.2 Ref2VA（推荐切换的模式）

官方六段固定顺序，标签在六段中含义不变：

```
subject_definitions:   定义 <Subject N> / <Picture N> / <Video N> / <Audio N>
summary:               [任务类型前缀] 一段话概括目标视频与参考关系
retention_analysis:    每个标签一行：fully_preserved / partially_preserved / attribute_transfer / weak_reference
detailed_description:  风格一句 + [Shot N] 逐镜头（同 base 格式，插入标签）
overall_soundscape:    环境音
non_diegetic_music:    配乐 / N/A
```

我们目前 **没有** 任何 Ref2VA 模板；独立创作页的 R2V 只做了 `@N → <Picture N>/<Video N>/<Audio N>` 的标签替换（`independent.py` L410），提示词正文由用户手写。

## 3. 现有复刻链路逐步骤对比与修改意见

```
上传原视频 → Gemini 拆解 → 源帧抽取 → 首帧人物置换 → Prompt 编译 → H3 I2V 请求 → 轮询归档 → 质检
```

| 步骤 | 现状 | 问题 | 修改意见 |
|---|---|---|---|
| ① 拆解 `analysis_instruction()` v3 + v7 增补 | 15+5 个 shot 字段；person_count 只是"数人头"；台词是每镜头一段 `spoken_text` | 没有"人物表"（谁是谁），没有"每个人各自的动作"，没有说话人绑定，没有画面文字，运镜缺幅度/速度 | 升到 v4：新增顶层 `persons[]`（P1/P2… 稳定编号 + 外观 + 是否说话）、镜头内 `person_actions[]`（按人分动作）、`speakers[]`（P 编号 + 台词 + 起止）、`on_screen_text`、camera_motion 加 `amplitude` / `speed`。详见 §5.1 |
| ② 源帧抽取 + 首帧置换 | 单人硬门禁 `MULTI_PERSON_VIDEO_UNSUPPORTED`（`first_frames.py` L1565）；GPT-Image-2 整人重构 | 多人直接拒绝；置换后的首帧是 I2V 唯一身份来源，一旦置换有瑕疵整条视频跟着错 | Ref2VA 下首帧变成**可选锚点**（作为 `<Picture 1>` 传 `reference_image`，标注 "is the first frame of [Shot 1]"），身份主要靠角色五视图 + 原照片；多人门禁改为"每个人有映射即放行" |
| ③ Prompt 编译 `compile_prompt_text()` v7 | 中文七段 | 见 §2.1 全部差距 | 新增 Ref2VA 编译器 `compile_reference_prompt_text()` 输出官方六段（§5.2）；I2V 编译器改为官方 base 结构作为兜底（§5.3） |
| ④ H3 请求 `build_h3_request()` | 复刻流固定 `generation_mode = "I2V"`，只传 text + first_frame | 原视频从未进入 H3 | 复刻流走 R2V 分支：`reference_videos=[原视频片段]`，`reference_images=[角色图…, 可选首帧]`；去掉自定义 `name` 字段（官方 schema 无此字段，探针前是风险点） |
| ⑤ 时长 | 客户 4/15 二选一，`timeline_scale` 等比缩放 | 节奏失真；>15s 无解 | 复刻流输出时长 = 片段实际时长四舍五入到 4–15 整数秒；源视频 >15s 按拆解 `segment` 切成 ≤15s 片段逐段生成再 ffmpeg 拼接（P0 文档明确排除过"逐镜头调用后拼接"，这是需要你拍板的范围变更） |
| ⑥ 质检 | 人物数量 / 身份分 / 服装分 …（针对首帧图） | 没有对成片做"动作一致性"检查 | 增加成片抽帧 vs 原视频同时刻抽帧的 Gemini 对比打分（姿态/走位/手势三项），低于阈值提示重生成 |
| ⑦ 计费 | 按 I2V 一次付费 | Ref2VA 每段一次付费、参考视频上传 COS | 计价表加 R2V 条目；分段数 × 单价，提交前展示 |

## 4. 目标方案：参考生视频复刻（Ref2VA）

### 4.1 输入编排（单人）

| H3 content 元素 | role | 标签 | 来源 | 说明 |
|---|---|---|---|---|
| text | — | — | `compile_reference_prompt_text()` | 官方六段 |
| video_url | `reference_video` | `<Video 1>` | 原视频片段（≤15s，**建议 `ffmpeg -an` 去掉音轨**） | 提供动作、运镜、切点、节奏。去音轨是为了不把原作者声音送进模型（肖像/声音权），台词由 `<d>` 重新表演 |
| image_url | `reference_image` | `<Picture 1>` | 角色五视图接触表 | 身份：脸、发型、体型 |
| image_url | `reference_image` | `<Picture 2>` | 角色原始照片 | 面部最权威依据 |
| image_url | `reference_image` | `<Picture 3>`（可选） | 已确认置换首帧 | 首镜头构图/服装锚点；有则写 "the shot begins from <Picture 3>" |
| audio_url | `reference_audio` | `<Audio 1>`（可选，默认不传） | 原视频音轨 | 只在客户明确要"原声节奏"时用 `reference`（非 copy） |

H3 互斥规则：R2V 不能携带 `first_frame` / `last_frame` role（`build_h3_request` 已校验），所以首帧只能以 `reference_image` 身份进入。

### 4.2 多人身份更换

**数据模型**（新表，名字待按代码开发清单冻结）：

```
project_subject_mappings
  project_id
  person_id          -- 拆解 persons[] 的稳定编号 P1/P2/…
  appearance_text    -- 拆解给出的外观描述（用于 subject_definitions）
  mode               -- KEEP | REPLACE
  character_version_id  -- mode=REPLACE 时的角色库人物
  reference_asset_ids   -- 该角色用于 Ref2VA 的图（接触表 + 照片）
```

**编排规则**：

- 每个 `KEEP` 的人 → `<Subject k> is the person Pk in <Video 1>, …外观…`；retention `fully_preserved`。
- 每个 `REPLACE` 的人 → `<Subject k> is the character whose appearance comes from <Picture a> and <Picture b>, and whose motion, position and timing come from person Pk in <Video 1>`；retention `attribute_transfer`。
- 参考图上限 9 张：每个替换角色 2 张 + 可选首帧 1 张 → 最多同时替换 4 人；超出时提示用户减少替换人数或每人只传接触表。
- `speakers[]` 里的 P 编号映射到 `(S1)`、`(S2)`…，替换后的人说原来那个人的台词，写法 `<Subject k> (Sx) says: <d>[Chinese] …</d>`。
- 首帧置换（可选）：现有多人提示词已经写了"只重构这一名主要人物，其他人物保持不变"，改为按映射表**逐人迭代置换**（每次一个人，上一次的输出作下一次的源帧），或直接跳过首帧。

**UI**：拆解完成后新增"人物映射"卡：列出 P1/P2…（缩略图 = 该人首次出现镜头的抽帧裁切 + 外观描述），每行一个选择：`保留原人` / `替换为 → 角色库人物`。至少一人替换才允许生成。

### 4.3 分段与时长

- 拆解已有 `segment_kind` / 可执行时间段；按"累计 ≤15s 且尽量在 SHOT_CUT 处断开"聚合成片段。
- 每段：`ffmpeg -ss -to -an` 切片上传 COS → 一次 Ref2VA → 输出时长 = 片段时长四舍五入（4–15）。
- 段间连续性：把上一段成片的最后一帧作为下一段的 `<Picture N>`（"the shot begins from <Picture N>"），并在 `summary` 里写 `[reference generation + keyframe completion]`。
- 最终 ffmpeg concat。任务中心展示"第 k/n 段"。
- 4 秒短片、单段 ≤15s 的源视频不受影响，直接一段。

### 4.4 兜底

- Ref2VA 探针未通过 / 供应商不支持 reference_video 时，仍走 I2V，但 I2V 模板也按官方 base 结构重写（§5.3），并取消 timeline_scale 缩放。

## 5. 提示词修改意见（可直接落代码）

### 5.1 拆解提示词 v4 —— 在 v3 + v7 增补的基础上新增

```text
顶层新增 persons：数组，列出全片出现的每一位真人，字段：
- person_id（P1、P2… 按首次出现顺序，全片稳定不变）；
- appearance（中文，服装/发型/体型/配饰等可辨识特征，用于区分不同人，不要评价长相）；
- role（主讲人 / 配角 / 路人）；
- speaks（true/false，全片是否有开口说话）；
- first_shot_id（首次出现的镜头）。

shots 内每个镜头新增：
- person_ids（本镜头可见的人物编号数组；person_count 必须等于其长度）；
- person_actions（数组，每个可见人物一条：person_id、action、hand_action、
  subject_motion_state、subject_direction、subject_displacement；单人时也用数组）；
- speakers（数组：person_id、text、start_time、end_time；旁白用 person_id="VO"；
  text 逐字照抄原话，不改写、不合并；同一句话跨镜头时两个镜头都写并标 crosses_cut=true）；
- on_screen_text（画面中实际出现的字幕/标题/标识原文，无则空数组）；
- motion.camera_motion 保持枚举，另增 camera_amplitude（SMALL/MEDIUM/LARGE）
  与 camera_speed（SLOW/NORMAL/FAST）；HANDHELD_TRACKING 额外给 camera_shake（SLIGHT/STRONG）。

规则追加：
5. person_actions 必须逐人描述，禁止把两个人的动作合写成一句；
   两人有互动（递物、握手、对视）时双方各自写清自己那一侧的动作。
6. speakers.text 与 original_script 必须逐字一致，original_script 按 speakers 顺序拼接。
```

同时把现有 `spoken_text` 保留为 speakers 文本的拼接（兼容旧 UI）。

### 5.2 生成模板 v8 —— Ref2VA（新编译器 `compile_reference_prompt_text()`）

模板骨架（`{}` 为代码填充；结构文本先用中文内容 + 官方英文标签/字段名，英文结构版留作 A/B）：

```text
subject_definitions:
<Subject 1> is the character whose identity, face, hairstyle, skin tone and body proportion come from <Picture 1> (five-view contact sheet) and <Picture 2> (original photo){, whose outfit follows <Picture 3>}; whose full-body motion, position in frame, gesture timing and walking path come from person P1 in <Video 1>.

<Video 1> is the source video providing the complete action timeline, camera movement, cut points and pacing of the target video.
{<Picture 3> is the first frame of [Shot 1], showing <Subject 1> in the opening composition.}

summary:
[reference generation{ + keyframe completion}] The target video re-performs <Video 1> shot for shot: every body movement, gesture, walking direction, camera movement and cut time of person P1 is transferred onto <Subject 1> with identical timing; {<Subject 2> and }the environment are preserved. {The first shot begins from <Picture 3>.}

retention_analysis:
<Subject 1> (appears in {shot list}): fully_preserved - identity, face, hair, skin tone, body proportion{, outfit from <Picture 3>} are retained throughout; the original person's face, body and clothing from <Video 1> are not retained.
{<Subject 2> (appears in {shot list}): fully_preserved - {appearance_P2} is retained.}
<Subject {k}> (appears in all shots): fully_preserved - {scene_dressing} and lighting are retained.
<Video 1> (action, camera and cut structure): attribute_transfer - the full-body motion, gesture timing, walking path, camera movement, amplitude, speed and cut times of person P1 are transferred onto <Subject 1> at the same timestamps.
{<Picture 3> ([Shot 1] first frame): fully_preserved - composition, pose and framing of the opening frame are retained.}

detailed_description:
The target video is a live-action realistic short video, {visual_style}, {color_tone}, {pace}.
[Shot 1] {shot_type}, {composition}{, the shot begins from <Picture 3>}. <Subject 1> {(S1)} {person_actions[P1].action}; {hand_action}; {displacement}; the motion follows person P1 in <Video 1> from 00:00.000 to {end}. The camera {camera_motion_en} {with small/large amplitude} {at slow/fast speed}. {<Subject 1> (S1), {voice_desc}, says: <d>[Chinese] {speakers.text}</d>} {A caption reading "{on_screen_text}" is visible.}
[Shot 2] At {MM:SS.mmm}, the shot cuts to {shot_type}, {composition}, following the cut in <Video 1>. …
…

overall_soundscape:
{ambient_sound 汇总，1–4 句；无则 Quiet room tone continues throughout.}

non_diegetic_music:
{music_style_hint 用乐器/速度/动态改写；无则 N/A}
```

**编译规则**：
- 时间戳全部来自片段内的相对时间，不做 timeline_scale 缩放。
- `camera_motion_en` 映射表（新增，替代中文标签）：STATIC→`holds a static shot`，PUSH_IN→`pushes in`，PULL_BACK→`pulls out`，PAN→`pans left/right`（方向来自 subject_direction 或新增字段），TILT→`tilts up/down`，FOLLOW→`follows the subject in a tracking shot`，HANDHELD_TRACKING→`follows in a tracking shot and shakes slightly`，ORBIT→`arcs around the subject`，CRANE_UP/DOWN→`pedestals up/down`，ZOOM_IN/OUT→`zooms in/out`。
- 说话人：按 `speakers[]` 出现顺序分配 S1、S2…，同一 person_id 全片同 ID；`VO` 用 `says in an off-screen voiceover … while {subject}'s lips remain completely closed`。
- 跨镜头台词：两侧都插 `<scenetrans>`，加 `continues seamlessly across the cut`。
- 长度预算：`detailed_description` 目标 350–500 词等价（中文约 600–900 字），超出时先砍 scene_dressing 重复，再砍 hand_action，永不砍台词与时间戳；总长 ≤7000 字符（现有 `MAX_GENERATION_PROMPT_CHARS`）。
- `H3_PROMPT_TEMPLATE_VERSION = "h3.prompt.v8-ref"`，I2V 兜底模板单独版本号 `"h3.prompt.v8-i2v"`，快照里记录 `generation_mode`。

## 6. 文生视频 / 参考生视频"不可用"的原因与解决

### 6.1 原因链（确认无误，不是前端 bug）

```
CreationPages.tsx L2949 "文生视频当前未开放" / L2871 "参考生视频当前未开放"
  ← videoCapabilities.t2v_enabled / r2v_enabled === false
  ← GET /api/independent/capabilities
  ← independent.py L117-119: t2v_enabled = r2v_enabled = last_frame_enabled = extended
  ← runtime_settings.h3_extended_modes_enabled（migration 075 默认 FALSE）
  ← CW-063 只交付了管理端开关（读写端点 + H3ExtendedModesSection.tsx），
     开启前置"缺口 4a：供应商 H3 扩展模式付费探针"从未执行
```

I2V 单独 `i2v_enabled=True`，所以只有带首帧的图生视频能用。

### 6.2 解决步骤

**步骤 1：先修两个协议风险（探针前，避免白花钱）**

1. `build_h3_request()` 给 `reference_image` 元素加了自定义 `"name": "ref-N"`，官方 v2 schema 里 **没有** `name` 字段。秘塔是否透传/是否被 MiniMax 拒绝未知。建议：provider 载荷去掉 `name`，只在我们自己的批次快照里保留映射（引用靠 `<Picture N>` 顺序，官方就是这么做的）。同步改 `_validate_h3_reference_request` 与 `test_independent_creation.py` 的断言。
2. 独立创作页的提示词只做了 `@N → <Picture N>` 替换，没有官方六段结构。在 textarea 下方加"按官方结构生成提示词"按钮：调用 §5.2 的编译器（无拆解结果时用用户填的一句话 + 参考素材列表生成 subject_definitions 骨架），用户再编辑。

**步骤 2：执行付费探针 4a（人工授权动作，需真实秘塔 key + 预算）**

三次真实调用，每次 4 秒 768P 最小成本：

| # | 模式 | content | 验证点 |
|---|---|---|---|
| a | T2V | text | 任务创建 + 查询 + 结果下载全链路 |
| b | I2V + last_frame | text + first_frame + last_frame | 尾帧 role 被接受 |
| c | R2V | text + 1 reference_image + 1 reference_video（≤5s，去音轨） | reference_video 被秘塔接受；成片是否跟随参考视频动作 |

写一个 `scripts/probe_h3_extended_modes.py`：复用 `MetasoH3Provider` 与 `build_h3_request`，从环境变量读 key，依次提交、轮询、把三份请求/响应 JSON 和成片落到 `docs/evidence/H3-EXTENDED-PROBE-<日期>.md`。这一步按账本 §15 必须人工授权，我不会替你跑。

**步骤 3：管理端打开开关**

探针通过 → 管理端「H3 扩展模式」→ 填写 reason（引用探针证据文件）→ confirm → `h3_extended_modes_enabled = TRUE` → 客户端「刷新开放状态」即恢复。

**步骤 4（可选，与探针解耦）**：把一个总开关拆成 `t2v_enabled / r2v_enabled / last_frame_enabled` 三个独立列，哪个探针过了开哪个，避免 R2V 因为尾帧探针没做而一起被锁。

## 9. 图生视频与文生视频的提示词（复刻流 I2V + 独立创作页 T2V / I2V / 首尾帧）

§5.3 只给了 I2V 兜底骨架，这一章把 **图生视频（重点）** 和 **文生视频** 展开到可直接落代码的程度。两条链路都要覆盖：

| 链路 | 现状 | 谁写提示词 | 问题 |
|---|---|---|---|
| 复刻流 I2V | `compile_prompt_text()` v7 中文七段 | 代码从拆解结果编译 | 格式非官方（§2.1） |
| 独立创作页「文/图生视频」 | [independent.py:415-422](../../server/app/independent.py) 把用户 textarea 原文**原样**发给 H3；`prompt_text max_length=4000` | 用户手写，placeholder 只有"描述镜头、场景、运动与光线" | 没有首行对齐语、没有结构、没有说话人/台词标记；用户一句话进去，H3 只能自由发挥；4000 上限低于 H3 的 7000；「导入提示词」导进来的是复刻 UI 的中文可读文本（`buildReplicaPromptText`），不是 H3 格式 |

### 9.1 官方 I2VA 结构逐条说明（为什么每条都影响效果）

官方 `base-en.txt` 的 I2VA 结构只有 4 块，但每块都有明确职责：

```text
For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.
                                                  ← ① 首行对齐语：告诉模型首帧=0.00 秒、属于 Shot 1、全量参考。固定句式，不改字。
(空行)
integrated_multimodal_description: [Shot 1] Live-action, cinematic, {首帧里的人/物/构图/场景锚点} … {动作起点} … {连续发展} … {结果/反应} [Shot 2] At 00:05.000, the shot cuts to …
                                                  ← ② 主体字段：推荐结构「首帧锚点 → 动作起点 → 连续发展 → 结果」；说话人 (S1) + <d>[语言] 台词</d>；运镜写成自然句子（类型+幅度+速度）。
overall_soundscape: …                             ← ③ 环境音/动作声/非语言人声，1–4 句，不重复台词。
non_diegetic_music: …                             ← ④ 观众才听得到的配乐：乐器/速度/动态；没有写 N/A。
```

关键要点（也是我们 v7 缺的）：

1. **首帧锚点必须"复述"图里的内容**，不是只说"从首帧开始"。官方示例：`the young woman shown in <Picture 1> remains beside the rain-covered train window, preserving her appearance, clothing, seat position, and the carriage layout`。模型靠这句把图和文对上，身份锁定也是靠这句 + `preserving …`，不需要我们 continuity 段那 60 个字。
2. **动作要写成"起点 → 过程 → 结果"的连续句**，不是枚举标签。`lifts her gaze from the folded letter toward the passing city lights … folds the letter along its existing crease`。我们的 `人物保持站位，动作限于口播与手势，双脚位置不变` 是约束句不是动作句，模型拿到的是"不要做什么"。
3. **切镜只标切入时刻** `[Shot 2] At 00:05.000`，不标区间；首镜头不标时间。
4. **说话人 ID 在首次出现时带音色描述**：`the quiet, breathy young woman (S1) says: <d>[Chinese] …</d>`；旁白固定句 `says in an off-screen voiceover` 并声明嘴闭合。
5. **运镜三维度**：`The camera trucks right with small amplitude at slow speed`；幅度/速度是中等时省略。
6. **画面文字**用英文双引号原文：`A red neon sign reading "营业中" glows`。
7. **不写分辨率、时长、"写实短视频"这类 API 参数或抽象词**（cinematic 这种风格词只在 Shot 1 开头写一次）。

| intro 段（时长/分辨率/"从首帧开始"） | 官方首行对齐语 | 删 intro，加常量 `I2V_ALIGNMENT_LINE` |
| continuity 段 60 字 | Shot 1 里一句 `全程保持 <Picture 1> 中该人物的…不变` | 合并进 Shot 1 渲染 |
| style 段 | Shot 1 开头 `Live-action, {visual_style}, {color_tone}` | `build_style_clause` 改为返回前缀 |
| `[00:00.000-00:04.200] 中景，…` | `[Shot 1]` 无时间 / `[Shot 2] At 00:04.200, the shot cuts to` | 时间戳只渲染切入点，来自 `start_time`，**不缩放** |
| `人物动作：{motion_clause}`（约束句） | 起点→过程→结果的动作句，`SUBJECT_MOTION_STATE_CLAUSES` 只保留"每一步脚掌落地、重心自然转移"这类**正向物理细节**作为补语 | 重写 `render_shot_motion_clause`：`action` 在前，枚举补语在后，去掉"不得僵立原地"类否定句 |
| `{camera_motion}` 中文标签 | `The camera … with … amplitude at … speed` 英文自然句 | 新 `CAMERA_MOTION_SENTENCES` 映射 + 幅度/速度/抖动后缀 |
| `口播意图：{spoken}` | `{说话人描述} (S1) says: <d>[Chinese] {text}</d>`，首镜头带音色 | 从 `speakers[]` 渲染；无 speakers 时回退 `spoken_text` 也套 `<d>` |
| script 段（整篇口播稿再贴一次） | 删除（台词已逐镜头在 `<d>` 里，官方明确不重复） | 删 |
| audio 段 + outro 常量 | `overall_soundscape:` / `non_diegetic_music:` 两个命名字段 | `build_audio_clause` 拆成两个函数 |
| narration_sync 段 | 删除（说话人 ID + 逐镜头 `<d>` 已经把台词钉在时间轴上） | 删 |
| 无 | 画面文字 `"…"` | 从 `on_screen_text[]` 渲染 |
| 无 | 尾镜头结束状态（"说完嘴自然闭合"）| 最后一个镜头追加 `<cutoff>`（若台词被截断）或闭嘴句 |

**长度预算**：每镜头约 120–180 字中文（或 80–120 英文词）；`MAX_GENERATION_PROMPT_CHARS = 7000` 不变；超预算先砍 `scene_dressing`（Shot 2 起不重复），再砍 `hand_action`，台词和时间戳不砍。

### 9.3 独立创作页「图生视频」：用户只有一张图 + 一句话

这是最需要补的场景。用户在独立页上传首帧，textarea 里写"她转身走向窗边说这套房采光很好"，H3 收到的就是这 20 个字。要达到 9.2 的深度，必须有一个**提示词助手**在提交前把"图 + 一句话"扩成官方结构。

**架构**：新增 `POST /api/independent/prompt-assist`（复用 `script_rewrite.py` 的 DeepSeek 客户端骨架，但要看图，所以 provider 用 Apilio Gemini，与拆解同一个网关）。输入：`mode`（T2V / I2V / FL2VA / L2VA）、`user_intent`、`first_frame_asset_id?`、`last_frame_asset_id?`、`duration_seconds`、`ratio`。输出：官方结构文本 + 结构化 JSON（便于 UI 分块编辑）。计费按一次 Gemini 图片分析计。

**助手系统提示词（I2VA）**：

```text
你是 MiniMax H3 视频提示词改写器。用户会给你一张首帧图和一句创作意图，你要输出 H3 官方 I2VA 结构的最终提示词。

硬性规则：
1. 第一行固定为：For the target video, at 0.00 seconds into the target video, <Picture 1> (from [Shot 1]) is fully referenced.
   然后空一行。
2. 之后只有三个字段，字段名原样保留、顺序不变：
   integrated_multimodal_description: / overall_soundscape: / non_diegetic_music:
3. integrated_multimodal_description 以 [Shot 1] 开头，先用一句写风格（Live-action / 2D-animated / 3D CG 等，从图里判断），
   再复述首帧里可见的主体外观（服装、发型、持物）、位置、构图、场景与光线，并写明这些在全片保持不变；
   然后按"动作起点 → 连续过程 → 结果或反应"写用户意图里的动作，动作必须是可见的物理过程（谁的哪只手、朝哪个方向、多大幅度），不写心理或形容词。
4. 切镜用 [Shot N] At MM:SS.mmm, the shot cuts to …；第一镜头不写时间；所有时间必须落在视频时长 {duration} 秒内，最后一个动作要在时长结束前完成或用 <cutoff> 标记。
   {duration} ≤ 6 秒时只用一个镜头；用户没要求切镜时最多两个镜头。
5. 运镜写成自然句：The camera pushes in / pulls out / pans left|right / trucks left|right / tilts up|down / pedestals up|down / arcs around the subject /
   follows the subject in a tracking shot / holds a static shot / zooms in|out / shakes slightly|strongly，需要时追加 with small|large amplitude 与 at slow|fast speed。
6. 有人说话时：首次出现给稳定 ID 和音色描述，例如 "the presenter, a warm mid-pitched female voice (S1) says: <d>[Chinese] 原话</d>"；
   台词一字不改、不翻译、保留标点；旁白用 says in an off-screen voiceover 并写明画中人嘴保持闭合；用户没给台词就不要编台词，写明人物不说话、嘴自然闭合。
7. 画面里实际出现的文字用英文双引号原样写出；用户没要求就不要加任何文字或字幕。
8. overall_soundscape 写 1–4 句环境音与动作声，不重复台词；non_diegetic_music 写乐器、速度、动态，用户没要配乐时写 N/A。
9. 不写分辨率、帧率、时长数字、"高清""4K""大片感"这类词；不写否定清单（"不要变形"等）。
10. 结构性文本用{中文|英文}，台词保持原语言。总长 ≤ 6000 字符，其中 integrated_multimodal_description 约 300–600 字。

输出格式：先输出最终提示词纯文本；然后另起一行 ---JSON--- ，再输出同内容的 JSON：
{"alignment_line": "...", "shots": [{"index": 1, "cut_at": null|"MM:SS.mmm", "text": "..."}], "overall_soundscape": "...", "non_diegetic_music": "..."}
```

**首尾帧（FL2VA）变体**：首行换成官方句 `How the reference pictures align with the target video — Picture 1 (from Shot 1) aligns with the 0.00-second mark of the target video; Picture 2 (from Shot 1) aligns with the {S.SS}-second mark of the target video.`（`{S.SS}` = 时长两位小数）；正文规则改为"只写连接两张图的运动路径：首帧状态 → 可观察的中间变化 → 差异逐渐收窄 → 尾帧状态；默认单镜头；不要分别复述两张静态图"。

**仅尾帧（L2VA）变体**：首行 `How the reference pictures align with the target video — <Picture 1> (from [Shot N]) aligns with the {S.SS}-second mark of the target video.`；正文"先推断一个合理的起始状态，再写动作与转场路径，最后一镜头逐渐收敛到 <Picture 1>"。当前 UI 只有"首帧（选填）+ 尾帧（可选）"，允许只传尾帧时后端 `build_h3_request` 需要新增 `last_frame` 单独分支（现在没有首帧就走 T2V）。

**UI 改动**：
- textarea 上方加「一句话意图」输入 + 「生成结构化提示词」按钮；生成后 textarea 显示完整提示词，允许编辑；右侧按 `shots[]` 分块预览。
- placeholder 改为示例骨架（首行对齐语 + `integrated_multimodal_description: [Shot 1] …`）。
- 提交前校验（前端 + `independent.py`）：I2V 模式下若文本不含首行对齐语，自动补上并提示；不含 `integrated_multimodal_description:` 时给黄色警告"未使用官方结构，效果可能不稳定"，允许继续。
- `prompt_text max_length` 4000 → 7000，与 `MAX_GENERATION_PROMPT_CHARS` 对齐。
- 「导入提示词」导入复刻 UI 文本时，先经 §9.2 的编译器转换（需要镜头卡 ID，而不是纯文本）；纯文本保存的自定义提示词按原样导入并走上面的校验。

### 9.4 独立创作页「文生视频」

T2VA 没有首行对齐语，直接三个字段。用户输入通常是一句话，扩写助手规则与 9.3 相同，差别是：

- 风格、主体外观、场景全部要由助手"补全并固定"：Shot 1 开头写风格，接着用一句把主体外观定死（服装颜色、发型、持物），后续镜头用"the same {主体} from Shot 1"回指，否则 T2V 跨镜头人物会变。
- 默认一个镜头；`{duration}` ≥ 8 秒且用户意图里有明显的"然后/接着/切到"才拆第二镜头。
- 用户意图含品牌/产品名时，只作为画面文字用双引号写出，不做视觉发挥。

**示例**（用户输入："一个女销售站在别墅大门口，对着镜头介绍这栋房子的花园，8 秒，竖屏"）：

```text
integrated_multimodal_description: [Shot 1] Live-action, natural daylight, vertical phone-style presenter video. A medium shot frames a woman in her thirties with shoulder-length black hair, a white shirt and a beige blazer, standing centered in front of the open iron gate of a modern villa, a hedge-lined garden and a lawn visible behind her under soft afternoon light; her appearance and the gate-and-garden layout stay fixed throughout. She looks into the lens, lifts her right hand palm-up and sweeps it toward the garden behind her, then steps half a pace to her left so the lawn is more visible, her left hand resting at her side. The camera pushes in with small amplitude at slow speed. The presenter, a warm, clear mid-pitched female voice (S1), says: <d>[Chinese] 这栋房子最难得的是这片私家花园，三百平，南北通透。</d> She closes her lips and gives a small nod as the shot ends.

overall_soundscape: Light outdoor ambience with faint birdsong and a soft breeze through the hedge; one quiet footstep on the stone path as she steps aside.

non_diegetic_music: N/A
```

（中文结构版同 9.2 的做法，字段名与标签保留英文。）

### 9.5 三种模式共用的编译/校验规则（落到一个模块 `h3_prompt_format.py`）

| 规则 | 实现 |
|---|---|
| 首行对齐语 | 按模式选常量：I2VA / FL2VA / L2VA 三句；T2VA 无 |
| 镜头标记 | `[Shot 1]` 无时间；`[Shot N] At {MM:SS.mmm}, the shot cuts to` |
| 运镜句 | `CAMERA_MOTION_SENTENCES` 映射 + `amplitude` / `speed` / `shake` 后缀 |
| 说话人 | 按出现顺序分配 S1、S2…；同一 person_id 全片同 ID；首次带音色描述；`VO` 走旁白固定句 |
| 台词 | `<d>[Chinese] …</d>`，原文不改；跨镜头 `<scenetrans>`；片尾截断 `<cutoff>` |
| 画面文字 | 英文双引号原文 |
| 身份锁定 | Shot 1 一句 `preserving …`；后续镜头 `the same … from <Picture 1>` |
| 禁用词 | 编译器不输出：分辨率、时长数字、"写实短视频"、"高清"、否定清单（"不得…"）——否定约束改为正向物理描述 |
| 长度 | 总 ≤7000；主体字段目标 300–600 中文字 / 350–500 英文词；超限按 9.2 顺序裁剪 |
| 版本快照 | `template_version` 分别为 `h3.prompt.v8-i2v` / `v8-t2v` / `v8-fl2v` / `v8-ref`；`generation_mode` 一并写入批次快照 |
| 校验 | 提交前检查：首行对齐语与模式匹配、`[Shot N]` 时间递增且 < 时长、`<d>` 成对、总长 ≤7000 |

### 9.6 与 §7 批次的对应

- 批次 A 追加：9.2 的 v8-i2v 编译器（替换 v7）、9.5 的公共模块、`max_length` 4000→7000、UI 校验与 placeholder。
- 批次 A′（可与探针并行，不依赖开关）：9.3 / 9.4 的提示词助手端点 + 「生成结构化提示词」按钮。助手本身不调用 H3，只调用 Gemini，所以在 T2V/R2V 开关打开前就能先上线给 I2V 用。
- Golden Sample 增加 5 条独立页用例：单图口播、单图走动+指物、首尾帧开门、纯文字户外介绍、纯文字两镜头。
