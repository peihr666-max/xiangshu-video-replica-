# 提示词 AI 优化：现有代码审查与最小改造方案

日期：2026-09-16。配套规范：[多模式提示词与 AI 优化开发规范](./MiniMaxH3多模式提示词与AI优化开发规范-2026-09-16.md)。

用户确认修订：默认在一次拆解中同时输出分镜与 H3 提示词，AI 优化仅作可选工具。以下“现有代码”证据保留原审查事实，“修改建议”已按此更新。拆解指令见[开发替换稿 v4.1](./视频拆解提示词v4-开发替换稿-2026-09-16.md)。

审查基线：`xiangshu-video-replica-` 本地 HEAD `f0b45b2b2558487adb8981635153cc7afb5da925`，包含尚未提交的 `analysis.py`、`generation.py` v7 修改。结论适用于本次读到的工作区，不等同生产运行状态。只读审查并运行了限定范围的现有前端测试；本轮未修改业务代码、未调用付费模型。

## 1. 按用户最新要求冻结流程

上传视频/导入爆款素材 → 一次拆解得到结构化分镜与对应模式的 H3 提示词 → 校验通过后可直接生成，也可手改或点击右上角 AI 优化 → 当前提示词连同所选素材提交视频生成。

独立文生视频、图生视频、首尾帧和参考生视频共用同一个优化入口与服务。

这里有三条产品规则：

1. 模式和生成素材齐全时，拆解默认输出 H3 结构；素材未齐时仍保存事实分析并提示缺项，不能伪造引用。用户手写/导入普通文本仍可走可选优化。
2. AI 优化是主动触发、可撤销的编辑操作；不是提交视频前的隐藏步骤，也不是必须经过的审批。
3. 当前提示词框是最终文字意图的真源。提交时只能校验和处理已明确展示的素材别名，不能用另一个模板覆盖框内文本。

用户所说的“最精简”落实到提示词子系统：保留有价值的上传、分析、素材、队列、计费和归档，重写提示词编辑与提交衔接。不为了换一个编辑逻辑重建整个视频系统。

## 2. 现有流程实际如何工作

### 2.1 来源和拆解已有，不需从零建设

- `CreationPages.tsx::ReplicaPage.handleUpload` 上传来源并写入 `projectId/sourceAssetId`。
- `MainPages.tsx` 的素材导入流程拿到 `projectId/sourceAssetId/canAnalyze` 后，可转入复刻页；`viral_import.py` 已承担媒体归档与项目关联。
- `ReplicaPage.startAnalysis` 调用分析任务，读取分析版本，再保存/复用 shot-card 版本。
- `analysis.py::ApilioGemini.analyze` 发送视频和分析指令，产出结构化分析。

因此，“来源视频归一化后拆解”这部分应复用。不同爆款页入口近期有过调整，本需求不应重新给所有卡片增加复刻按钮；已导入的来源素材进入同一分析流程即可。

### 2.2 目前存在两种提示词和两种提交方式

| 环节 | 当前行为 |
|---|---|
| 复刻页显示 | `state.ts::buildReplicaPromptText` 把镜头卡拼成中文文本 |
| 后台编译 | `generation.py::compile_prompt_text` 从脚本和镜头卡生成 v7 七段文本 |
| 复刻页生成 | `live.ts::runReplicaGeneration` 存稿 → 编译 → 条件性 revise → 锁定 → 建批 |
| 独立创作生成 | `StudioWorkspace.tsx` 直接发送 `draft.prompt`；`independent.py` 对 R2V 进行 `@N` 别名替换 |
| 保存自定义提示词 | 保存为 `saved_prompt`，是模板库条目，不是当前项目 `h3_prompt` 版本 |

现状的自然语言拆解文本需要升级为默认直出 H3。除此之外，生成时不透明的覆盖逻辑、不同入口缺少共享编辑/优化/校验契约，也需要一起修复。

## 3. 已确认的问题及优先级

### P1-01：已确认文案会使提示词框内容不被采用

证据：`client/src/studio/live.ts:1506`。

```ts
const finalPrompt =
  !input.confirmedScriptText?.trim() &&
  input.promptText.trim() &&
  input.promptText !== compiledText
    ? await reviseGenerationPrompt(...)
    : compiled;
```

只要有已确认文案，人工修改或 AI 优化结果就不会进入 revise 分支。旧逻辑是为防止“旧提示词覆盖新口播稿”，但它会连用户最新的优化结果一起忽略。

现有 `live.test.ts:1578` 甚至明确断言该情形“不调用 revise”，因此不是新增一个图标就能修复的问题，必须同时修改业务规则和测试。

同类问题还存在于 `ProjectDetailFlow.tsx:517`，条件是 `revisedPromptText && !scriptWasEdited`。

修改：提示词框内容始终是最终文本；更新口播稿后提示“提示词可能仍含旧台词”，由用户同步/编辑/优化。不得再以“文案确认状态”决定悄悄换用另一份文本。

### P1-02：自动生成的中文草稿也可能覆盖后台编译结果

证据：`state.ts:558`、`CreationPages.tsx:1328`、`live.ts:1506`。

后台判断的是“框内文本是否与编译文本不同”，不是“用户是否编辑过”。自然语言草稿通常天然不同于 v7，因此即使用户没编辑，仍可能创建修订版本，把刚刚编译的内容覆盖掉。

后果：两套提示词相互覆盖，后台身份约束、时间缩放等处理不一定真正进入请求；不能仅凭改好了 v7 就判断用户拿到了新效果。

修改：新流程直接提交框内文本；后台不先生成一份临时文本再让另一份覆盖它。

### P1-03：重复拆解可能显示“新分镜 + 旧提示词”

证据：`CreationPages.tsx:1328–1332`，只有当前框为空才回填新拆解草稿。

同一项目再次拆解时，分镜会更新，但已有文本不会更新；界面仍提示“分镜与 Prompt 已生成”。这是保护人工输入的意图，但没有区分“旧自动草稿”和“用户编辑”。

修改：用草稿来源与分析版本判断。旧自动草稿且无人工修改可替换；用户改过的文本保留，同时提供“应用本次拆解草稿”。任何迟到结果都不能覆盖新编辑。

### P1-04：保存到提示词库，与恢复当前提示词不是同一个真源

证据：`CreationPages.tsx:1356` 写 saved prompt，成功后 `1375` 清理 edited 标志；恢复逻辑 `983–1021` 优先读 `getLatestGenerationPrompt`，不是刚保存的库条目。

按代码路径：保存为模板之后，重新挂载页面时若本地不再标记 edited，可能恢复旧的项目提示词或重新拼接草稿。云草稿虽然保存了文本，但“是否保护该文本”的标志又被模板保存操作清掉。此处为静态路径发现，本轮未做浏览器重载复现。

修改：把“当前草稿”“已提交快照”“模板库”三个概念分清。存入模板库不得改变当前编辑内容的权威性，也不应清除草稿来源/版本。恢复优先当前草稿；旧版本只用于用户主动载入。

### P1-05：直接复用 AI 文案改写会改掉原台词

证据：`script_rewrite.py:51` 要求“全新的二创口播稿”“避免连续 8 字相同”“开头必须有新的钩子”，请求温度在 `950` 为 1.3。

这是内容二创，不是格式优化。该接口还强依赖项目、身份画像和自己的异步任务，独立 T2V 没有项目时也不适配。

修改：新增一个专用提示词优化操作。复用已配置的 Apilio 传输、权限、计量和 worker；不使用二创系统指令，也不复制一套 DeepSeek 业务逻辑。

### P1-06：素材引用只替换编号，没有稳定的优化上下文

证据：`independent.py:370–422`、`CreationPages.tsx:2407`、`StudioDraft`。

当前 R2V 把混合素材编号 `@N` 转为每种媒体单独编号。优化结果若已含 `<Picture 1>`，换图或调整参考列表后，同一标签可能指向另一张图；保存/导入目前又只传提示词文字，缺少素材语义与上下文校验。

修改：优化、保存、生成共享同一份素材清单；绑定资产 ID、类型、顺序和用途。优化结果保存上下文指纹。素材发生变化时保留文字，标记需重新确认，不允许悄悄重新解释标签。

### P2-07：不同入口长度限制不一致

证据：`IndependentVideoRequest.prompt_text` 限 4000；`PromptRevisionRequest`、`SavedPromptRequest` 限 7000；新工作台 textarea 未体现同等限制。

可能出现“优化/保存成功，但独立创作提交失败”。统一产品上限为 7000 个 Unicode 码点，服务端为准；前端计数不能简单把 UTF-16 长度当相同字符数。AI 输出超长应返回错误或用户可处理的提示，不截断台词。

7000 是当前项目的产品限制，不把它写成已经核实的供应商通用上限。

### P2-08：缺少模式识别和 H3 格式校验

证据：`state.ts:549` 根据有没有首帧决定 T2V/I2V；尾帧不参与解析。`build_h3_request()` 无首帧时直接返回 T2V，`validate_h3_request()` 也没有单尾帧分支。

修改：统一推导 T2VA/I2VA/FL2VA/L2VA/Ref2VA。仅尾帧如果纳入交付，前端、请求构造、请求校验和能力开关必须一起补齐；不能只输出 L2VA 提示词却仍发送 T2V。

官方当前支持仅尾帧组合；供应商网关是否支持、当前产品是否开放，仍由实际能力配置决定。[MiniMax API](https://platform.minimax.io/docs/api-reference/video-generation-v2-create)

### P2-09：镜头类型、时间、风格等上下文被自然语言草稿丢掉

`buildReplicaPromptText` 只接收 shots 和 originalScript，不接收全片 visual_style、color_tone；也没有输出 structured motion、scene_dressing、ambient_sound、segment_kind 等信息。全部可执行时间段都叫“镜头”。

修改：分析单次返回原事实与目标 H3 文本，提示词框直接展示通过校验的文本；真实切镜与动作阶段在分析与 H3 中保持对应。轻量中文渲染仅用于事实卡和旧数据回退。AI 优化读取已有分析，避免重新猜测已存在事实；无需立即重建人物跟踪、语音对齐或复杂时间轴数据库。

### P2-10：手工修订还继承旧模板元数据和缩放说明

`revise_prompt_version()` 把编译 payload 复制后只替换文本；`template_version/hash` 和 `timeline_policy=linear_scale_to_output.v1` 仍保留。

`version_stale_reasons()` 又依据当前 v7 模板版本判过期。任意手写/H3 优化后的文本可能被误标为 v7 产物，或因 v7 升级而失效。

修改：拆开生成来源、优化规则版本和兼容性校验状态。手写文本不冒充模板产物；升级优化器不自动废弃用户已确认的文本。素材或实际模式不匹配才触发对应上下文复核。

### P2-11：旧入口仍有实际挂载，不能整批当死代码删除

`LiveWorkspacePanel.tsx` 仍挂载 `AnalysisWorkspace`、`ProjectDetailFlow`；`AnalysisWorkspace` 使用 `GenerationComposer → GenerationLauncher → useGenerationDrafts`。

因此新按钮至少覆盖：新复刻页、新文图/参考页、旧生成面板、旧详情提示词编辑。全部使用同一编辑组件及优化服务，或完成入口迁移后再删旧提示词面板；不能删除包含人物库、项目和任务功能的整个旧工作区。

### P2-12：只有 UI 按钮不足以形成可靠 AI 操作

代码搜索未发现提示词优化端点。当前计费目录也没有 `prompt_optimize`。`meter_call()` 没有绑定业务 operation 时，不会自动替新功能完成全套成本和幂等记账。

修改：增加一种优化任务、一个专用计费科目，复用现有 PG/worker/账务处理。重复点击、任务超时、切项目、请求已送达但结果未知都要有明确行为。无需新 Redis、新队列框架或重新搭通用 Agent 平台。

## 4. 精简边界：删什么、留什么、重写什么

| 分类 | 内容 | 本次建议 |
|---|---|---|
| 保留并扩展 | 上传、爆款媒体导入、素材归档、分析任务和原事实 schema | 增加目标上下文及 analysis-h3.v1 响应包装，单次返回事实和 H3 文本 |
| 保留 | 权限、租户隔离、签名 URL、云草稿队列 | 优化走同一权限体系，不能信任客户端任意 URL |
| 保留 | H3 请求构造、队列、轮询、归档、计费、幂等 | 做必要的模式/校验接入，不重写 |
| 重写 | 提示词框 UI | 一个共享编辑组件，右上角一个优化图标，成功回填、支持撤销 |
| 重写 | 提示词优化逻辑 | 一个服务 + 公共系统指令 + 五种模式规则；返回最终文本与诊断 |
| 删除 | 提交时先编译再覆盖的流程 | 改为冻结并提交当前文本 |
| 删除 | 确认文案就跳过当前提示词的条件 | 改为显式提示脚本冲突/上下文变化 |
| 收敛 | 多处 prompt/local/ref 状态同步 | 父层一个草稿状态，组件只持有请求状态和一次撤销文本 |
| 退出新链路 | v7 七段语义编译器 | 不再参与新模式生成；无在用调用方后删除相关模板与拼接辅助函数 |
| 暂留兼容 | 旧 compile/revise/lock 端点、历史版本读取 | 同步迁移在用 UI；外部/旧客户端兼容确认后再删接口，历史结果保持可读 |
| 暂不建设 | 新分镜数据库、多人跟踪、长片自动拼接、口型修复 | 不作为此次“提示词编辑 + AI 优化”交付的前置 |

文件长、函数多不等于冗余。此次简化的核心是减少互相覆盖的内容真源和重复业务流程，而不是删除保护用户输入、资产权限和避免重复扣费的代码。

## 5. 最小目标结构

```text
源视频 + 目标模式/素材 → 单次分析 → 结构化分镜 + H3 提示词 → 校验
通过校验的 H3 文本 / 用户直接输入 / 导入模板 → 当前可编辑提示词

主流程：当前可编辑提示词 → 冻结当前文本和实际素材 → 既有生成服务
可选操作：点击 AI 优化 → 文本 + 模式 + 素材 + 上下文 → 单一优化服务
          → H3 文本 + 校验结果 → 回填当前框，可继续编辑/撤销
```

不再增加“优化完又编译一遍”“用户可读稿和最终请求稿各自自动变化”的阶段。R2V 历史 `@N` 仅作为明确的兼容别名转换；转换后的官方标签应在提交预览可见。

### 5.1 前端最小改动

新增建议名 `PromptEditor.tsx`，统一标题、textarea、计数、右上角图标、忙碌状态、诊断和撤销。网络流程单独一个 `usePromptOptimization`，避免四个页面各写一套竞态保护。

扩展现有草稿 JSON 即可，无需新增提示词草稿表。保存 `promptSource`、`sourceAnalysisVersionId`、`optimizedContextHash`、`promptMode`；最终文本仍只有一个字段。

新复刻页仍可在首帧生成前编辑草稿；点击按 I2V 优化而尚未选首帧时，给出缺少素材提示。用户可继续手改草稿，不要求必须先完成人物置换才能看到/保存提示词。

若分析时已有目标首帧与明确模式，直接产出 H3 文本；若没有，标记 NEEDS_CONTEXT 而非 READY。前端需要允许在分析前带入已有生成素材，或在分析后明确补齐/适配。正常 READY 路径不能暗中追加优化调用。

### 5.2 后端最小改动

新增建议模块 `prompt_optimization.py`，集中请求 schema、上下文解析、模式规则、AI 调用和输出校验；任务队列仍用当前 `generation_worker.py`。无需新建通用编译器框架。

新增 `prompt_optimization_tasks` 一张小表存操作输入/结果与状态，project_id 可空，满足无项目独立创作。复用现有租约和不确定提交处理模式，但不把该任务塞进口播二创表：后者的项目、IP 画像与业务语义均不同。

同一张表、同一条处理流程覆盖所有模式。计费记录复用 `usage_billing`，不再创建第二套钱包或结算表。表名、迁移编号和文件名需在实施时登记到代码清单；此文不占用新的正式任务编号。

### 5.3 当前文本直接建批，保留历史版本兼容

推荐扩展现有 `GenerationBatchRequest`，新增 `prompt_text` 和必要的来源版本上下文；`prompt_text` 与 `prompt_version_id` 必须二选一。

- 新 UI 发 `prompt_text`：服务端先查幂等重放，再检查项目、素材与来源版本，在建批同一事务里冻结文本、建立现有 h3_prompt 版本和 USED 快照、创建任务、预扣。复用已有审计与防重复消费能力。
- 旧客户端发 `prompt_version_id`：保留原 LOCKED 版本路径，避免突然破坏在用入口。
- 新 UI 不再为了视频提交额外存一份脚本、编译、修订、锁定；最终文字已经由用户确认，不应再由编译器重新推导。
- 原稿/目标脚本仍在文案功能中保存；版本作为可选来源证据，不能再次覆盖 prompt_text。
- `idempotency_request_hash` 纳入当前文本、来源版本、实际素材和参数；同 key 不同内容返回冲突。
- 复刻当前 I2V 的确认首帧和人物来源检查保留。Ref2VA 文字优化与“把复刻提交改为 R2V”是两个不同改动；本次先复用独立参考页现有 R2V 生成能力，不把整条复刻路线迁移作为按钮前置。

独立创作已直接发文本，继续使用现有接口，仅补统一长度、引用校验、上下文和优化元数据。

## 7. 实施顺序与验收

1. 先改“当前文本就是最终文本”规则，新增回归测试；冻结并验证新文本建批路径。
2. 分析接入目标模式/素材，同次输出事实和 H3 文本；统一编辑器、来源元数据、模式解析和草稿恢复；保持 AI 按钮服务未就绪时可手动编辑。
3. 接一个优化服务，完成纯文字、图片、参考素材上下文与五模式规则。
4. 接入在用旧入口；删掉新流程不再需要的模板/编译分支，再做调用方检查决定物理删除范围。
5. 跑前后端专项、项目要求的质量门；真实供应商验证单独记录，不能以 mock 通过声称模型效果通过。

核心验收必须包括：

- 用户输入或 AI 结果，在“有/无已确认文案”两种状态下都原样进入最终 H3 请求（允许事先展示的别名转换和首尾空白规范化）。
- AI 优化不调用 H3 视频生成，不创建 generation batch，不触发视频预扣。
- 首次分析上下文齐全时只调用一次模型，同时返回分镜与 H3 文本；READY 不点击 AI 优化即可生成。缺素材、格式错或事实不一致必须明确标记，不能偷偷二次修复。
- 非 H3 格式文本可以继续手动编辑和提交；格式建议不被当成强制优化门禁。
- 再次拆解、切项目、换账号、用户等待时继续输入，迟到结果不覆盖当前文本。
- 保存模板后返回/刷新仍保留当前草稿；模板导入时验证当前模式与素材关系。
- T2VA、I2VA、FL2VA、Ref2VA 输出对应结构；L2VA 补齐真实提交能力后再开放，不能伪装支持。
- `@1` 是视频、`@2` 是图时，正确绑定为 Video 1、Picture 1；重排/删除素材不偷换角色。
- 4001–7000 字内容在编辑、保存、优化、生成四层行为一致。
- 多次点击/刷新轮询不会重复执行同一次优化或重复记账；未知提交不会自动重发。
