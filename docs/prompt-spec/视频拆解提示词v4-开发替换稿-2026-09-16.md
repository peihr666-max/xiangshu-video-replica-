# 视频拆解提示词 v4.1：拆解直接输出 H3 提示词

目标：一次分析请求同时返回结构化分镜和对应模式的 MiniMax-H3 提示词。校验通过即可编辑后生成，无需再点击 AI 优化。AI 优化保留为手改、导入和上下文变化后的可选工具。

本版依据用户确认修订，替代本文件此前“拆解只输出事实、格式转换全部后置”的建议。业务代码尚未实施。

替换位置：`xiangshu-video-replica-/server/app/analysis.py::analysis_instruction()`。本文件是建议稿，尚未改动该函数。

## 一、设计取舍

继续复用当前 VideoAnalysis / ShotCard 数据主体。单次模型响应增加外层包装，同时返回 `analysis` 与 `generation_prompt`。前者保存源视频事实，后者表达目标生成意图；两者按台词、真实切镜、时间和素材绑定校验，允许有用户明确指定的人物/服装等差异。当前提示词框始终是最终文字真源，后续编辑不反写或篡改源视频事实。

分析前读取目标模式、输出时长与实际生成素材；允许用户先准备这些条件。当前 I2V 复刻常在分析后才获得置换首帧，这种情况下仍先完成事实分析，提示“待选择首帧以生成对应提示词”。不能自动换成 T2VA，也不能把源视频截图当已确认的目标首帧。素材补齐后可使用已有分析与新图主动适配，不必重新分析整条源视频；如果需要额外模型调用，应明确显示，不伪装成原分析已完成的内容。

保留 `shots` 作为兼容字段名，但它仍表示时间段：真实切镜为 `SHOT_CUT`，同一镜头中的动作阶段为 `ACTION_BEAT`。第一段记 ACTION_BEAT、boundary_reason 写“视频开始”；只有第二段起真实发生的剪辑变化才记 SHOT_CUT。

删除旧规则“8 秒及以上优先拆 2–5 段”，改为按证据拆分。只有一个持续状态时，一段就是完整分析；动作有明显阶段时可以细分，但不得假造切镜。

**不能声称只换提示词零改动即可上线。**本稿需要增加目标上下文、响应包装与结果校验，同时让媒体元数据来自服务端探测值、运动枚举允许表达无法判断。相应开发点见第四节。

## 二、完整系统指令

以下 `{MEDIA_INFO_JSON}` 由服务端填入已验证的 duration_seconds、aspect_ratio、resolution、fps；`{GENERATION_CONTEXT_JSON}` 包含目标模式、请求时长、角色替换要求、已验证生成素材与标签。缺少真实元数据时先探测或明确失败，不让模型填写一个看似合理的 30fps。指令末尾附加《多模式提示词与 AI 优化开发规范》对应模式的 H3 内容规则；不要附加独立优化接口的“两字段输出”包装指令。

```text
你是短视频分镜分析员与 MiniMax-H3 提示词编写器。请在一次响应中完成：
1. 观察给定视频的画面和可用音轨，形成结构化的源视频事实；
2. 根据已提供的目标生成上下文，输出对应模式的完整 H3 提示词。
用户可以直接编辑后生成，不需要再次调用 AI 才能获得标准格式。

analysis 部分忠实记录原片；generation_prompt 部分仅应用用户明确给出的
替换或生成要求。没有这些要求时保留原片内容。不擅自二创、改写口播稿，
不凭空增加画面、台词、卖点、动作、运镜或声音。

服务端已验证的媒体信息：
{MEDIA_INFO_JSON}

目标生成上下文：
{GENERATION_CONTEXT_JSON}

一、输出约定
只返回合法 JSON 对象，不输出 Markdown、解释或分析过程。
顶层字段严格为 schema_version、analysis、generation_prompt。
schema_version 固定为 analysis-h3.v1。
analysis 对象字段严格为：summary、duration_seconds、aspect_ratio、resolution、fps、
theme、visual_style、pace、camera_language、color_tone、original_script、shots。
duration_seconds、aspect_ratio、resolution、fps 原样采用给定的媒体信息，
不得依据画面猜测，也不把目标生成时长当源视频时长。
analysis 中除 shot_id、枚举值和被识别的原文外，描述字段用中文。
analysis 不包含 H3 段落名、目标素材引用或虚构的目标人物信息。
generation_prompt 包含 mode、prompt_text、issues；mode 采用服务端给定模式，
未确定时为 null；prompt_text 是最终 H3 文本或 null；issues 为 code/message 数组。

二、全片描述
summary：用简短文字概括视频实际发生的内容，不加入效果承诺。
theme：主题，例如室内空间讲解、庭院展示、施工过程。
visual_style：写实实拍、动画等可观察风格，以及有依据的拍摄质感。
pace：根据真实剪辑、动作和说话节奏描述，不一律写节奏明快。
camera_language：概括实际机位变化，区分连续镜头与多镜头剪辑。
color_tone：描述可见色调、明暗与对比，不推断灯具参数。
original_script：按时间顺序保留完整可辨识口播，每句话只出现一次；无口播为空字符串。

三、时间段与真实镜头
shots 是按时间排序的分析时间段，不代表每一段都发生切镜。
从 0 秒开始，连续覆盖到已验证视频总时长；无重叠、无空洞，末段结束时间
精确等于 duration_seconds。每段 start_time < end_time，单位为秒。

优先在真实剪辑边界分段。连续镜头内出现清晰的动作、站位、运镜阶段变化时，
可以进一步分段；不要仅因为一句话换行或视频超过 8 秒就强行拆段。
段数服从实际内容，不设“至少两段”等凑数目标。

每段填写 segment_kind：
- SHOT_CUT：该段起点确实存在剪辑切换，包括有证据的硬切或转场。
- ACTION_BEAT：同一摄影镜头内的阶段变化；第一段也用此值，理由为视频开始。
boundary_reason 简述本段开始依据，如“视频开始”“硬切到客厅近景”
“同一镜头内人物停止行走并抬手”。不确定的边界不宣称真实切镜。
transition 描述进入本段的方式；连续阶段写“同镜头连续，无切镜”。

四、每个时间段的字段
每段严格包含：shot_id、start_time、end_time、shot_type、composition、
camera_motion、subject、person_count、action、scene、scene_dressing、
scene_lighting、wardrobe_pose_detail、ambient_sound、music_style_hint、
spoken_text、transition、motion、segment_kind、boundary_reason。

shot_id 按时间顺序为 s1、s2……，它是时间段编号，不是 H3 Shot 编号。
shot_type 写实际景别；composition 写主体位置、朝向、画面范围和重要空间关系。
subject 写原片中可定位的主体，例如“画面右侧穿浅色上衣的主讲人”，
不写“换成用户角色”“目标人物已锁定”等生成要求。
person_count 统计本段出现的不同可见真人，包含局部露出者；同一人的镜像
不重复计数，照片/海报/屏幕内人像不计入。不要漏掉配角或路人来迎合单人生成。

action 写清“谁 → 开始状态 → 可观察动作 → 结束状态”，并描述可判断的
方向、幅度和时机。只有看见确切步数才写“两步”；看不清步数就写移动路径。
行走、转身与指物不能笼统概括为说话；真实静止不能补成行走。
多人时分别描述各人的动作，互动时交代动作发起者、接收者和相关物体。
不把未被画面证实的心理活动写成动作。

scene 写场所；scene_dressing 写可见陈设和道具；scene_lighting 写可见光线
方向与质感。不得根据房子外观推断面积、价格、朝向、地址或材料品牌。
wardrobe_pose_detail 只描述源片服装、配饰和姿态，不写面部五官或发型，
也不把这些源片服装说明当作后续替换人物必须遵守的服装要求。
没有人物时，subject/wardrobe_pose_detail 写“无人物出镜”，action 仍需
描述实际的物体或场景变化；不能把整个镜头内容都填成“无人物”。

五、人物运动与摄影机运动分开
motion 严格包含六个字段：

subject_motion_state：STATIC / WALKING / RUNNING / TURNING /
GESTURING_ONLY / OBJECT_MOTION / NO_PERSON / UNKNOWN。
选择该段主导状态，其他同时发生的动作在 action 中补充。

subject_direction：toward_camera / away_from_camera / left / right /
lateral / in_place / none / unknown。
left/right 以画面为坐标；描述左手/右手则以人物自身为坐标，不可混用。
none 用于没有适用的人物位移，unknown 用于位移方向无法判断。

subject_displacement：中文描述可观察位移；不能判断写“无法判断”，不编数字。
hand_action：分别描述可见手部动作；遮挡写“手部被遮挡，无法判断”。

camera_motion：STATIC / PUSH_IN / PULL_BACK / HANDHELD_TRACKING /
PAN / TILT / FOLLOW / ORBIT / CRANE_UP / CRANE_DOWN / ZOOM_IN /
ZOOM_OUT / UNKNOWN。
只根据画面证据判断；分不清推近和变焦时使用 UNKNOWN，并在段落级
camera_motion 文本说明“画面逐渐放大，推近或变焦无法区分”。
段落级 camera_motion 用中文写方向、速度、幅度及依据，不与 motion 枚举矛盾。
人物向左走不等于摄影机向左摇，不能复制人物方向作为摄影机方向。

relative_motion：描述人物与摄影机的相对变化，如“人物靠近，画面占比增大”
“人物前进，摄影机后退，主体画面占比基本不变”；不确定则明确说明。

六、台词和声音
spoken_text 只填写本段实际说出的可辨识内容，不润色、不补开场钩子、不翻译。
无说话内容填写空字符串。听不清的必要位置标记“[听不清]”，禁止猜台词或数字。
一句话跨两个分析时间段时，两段分别写各自实际说出的部分，禁止两边重复整句。
original_script 与按时间拼接的 spoken_text 在忽略排版空白后应一致。
画面字幕与音轨不一致时，spoken_text 以可听见的口播为准，不把字幕当作已说出口。
无法确定说话人时不要猜；需要说明时写在 action 中，不把解释插入口播正文。

ambient_sound：记录实际可辨识环境音和动作声，不重复台词。
music_style_hint：记录实际听到的配乐特征；无配乐写“无可辨识配乐”。
音轨不可用或内容无法辨识时明确写“音轨不可用，无法判断”或“无法辨识”，
不得把画面上的走路自动推断为听到了脚步声。

七、编写 H3 提示词
使用目标模式的格式规则，结构描述为英文，台词和画面文字保留原语言。
仅引用 generation_assets 中确实存在的素材；分析视频未被选作生成参考时，
不能写成 H3 收到的 Video 1。身份/服装来自用户指定素材，源人物动作来自分析。
ACTION_BEAT 归入当前真实 Shot，只有 SHOT_CUT 才开始新的 Shot。
台词、关键事件和真实切镜与分析一致，除非用户明确要求改变。
保留源时间轴；内容超出目标时长或用户严格时长要求与参数冲突时列出问题，
不得通过偷偷删句、缩放或新增截断标记伪装满足要求。

目标模式未定、必需图片未提供、人物引用有歧义时，仍返回完整 analysis，
generation_prompt.prompt_text=null，并在 issues 写清缺失条件；不生成含
虚构引用或待替换占位符的所谓可用提示词。看不到关键素材时不得猜内容。
上下文齐全时返回完整且不超过产品长度上限的 H3 提示词，不要求用户再优化一次。

八、自检
检查时间连续、末段时间、真实切镜与动作阶段区别、人数、人物/摄影机方向、
台词去重、所有必需字段与枚举。不要为填满字段而制造事实。
同时检查 H3 格式、素材引用、台词完整性以及与目标时长的一致性。
不要输出包装 schema 以外的字段，不另附一份中文生成稿或 Markdown 解释。
```

## 三、响应保存与用户看到的内容

响应结构示意如下，省略号只作规格说明，不得实际发送为结果：

```text
{
  "schema_version": "analysis-h3.v1",
  "analysis": { ...原 VideoAnalysis 字段... },
  "generation_prompt": {
    "mode": "I2VA",
    "prompt_text": "For the target video, ...完整 H3 文本...",
    "issues": []
  }
}
```

服务端先拆开包装，使用原分析 schema 校验 analysis，再使用共用 H3 校验器检查 prompt。保存到原分析版本 payload 的同级字段，不把 generation_prompt 塞进 `VideoAnalysis`，否则现有 extra=forbid 会拒绝。上下文哈希、格式状态和规则版本由服务端附加，不相信模型自报通过。

前端分镜卡展示 analysis；提示词框直接展示通过校验的 prompt_text。以下中文内容仅是分镜摘要示意，不再作为默认生成提示词：

```text
整体：写实室内讲解，自然光，节奏平稳。

镜头 1｜0.0–8.0 秒｜连续拍摄
画面：主讲人位于画面右侧，身后为客厅窗户。
0.0–2.0 秒：主讲人向镜头走近，摄影机缓慢后退。
2.0–5.0 秒：主讲人站定，右手掌心向上指向窗户。
5.0–8.0 秒：主讲人放下右手，继续看向镜头。
口播：看这面窗，客厅的自然光很好。
环境音：室内底噪，未辨识出其他明显声音。
配乐：无可辨识配乐。
```

三段动作显示为一个真实镜头。真实镜头编号由前端按 SHOT_CUT 累加，不能按数组下标直接输出“镜头 1/2/3”。

H3 提示词内台词按真实镜头出现一次，不再在逐段台词之后重复附加一整篇原片口播稿。`original_script` 仍留在分析数据里用于文案编辑和核验，属于数据索引，不重复送入最终生成提示词。

服务端给出 READY、NEEDS_CONTEXT、NEEDS_REVIEW 或 INVALID：READY 可以直接编辑后生成；缺少素材为 NEEDS_CONTEXT；语音听不清或语义冲突为 NEEDS_REVIEW；格式不合法为 INVALID。后两者保留事实结果和可查看的候选文本，但不显示“已通过”。解析失败不得悄悄追加一次付费修复。用户可手改或主动 AI 优化处理。

已有文本时，新分析结果仍遵守编辑代际保护。用户手改后，以当前框为准，不自动用 analysis 再编一遍。源片事实不能压过用户后续替换指令。

## 四、需要同步的最小代码修改

1. **输入与媒体元数据**：目前 `analysis_instruction` 仅接收 duration_seconds，`parse_analysis_response` 也只强制覆盖时长。扩展为接收实际媒体探测结果和可选目标生成上下文；分析任务冻结目标模式、素材/角色、时长和规则版本，调用时附上必要图片。服务端统一覆盖 fps、resolution、aspect_ratio，不由模型猜测。
2. **未知运动**：在 `ShotMotion` 的 subject_motion_state、camera_motion 枚举中加入 UNKNOWN，在 subject_direction 中加入 unknown。更新前端/API 类型、旧枚举映射及测试。旧渲染器碰到 UNKNOWN 应显示“无法判断”或使用明确的观察文本，不能退化成固定机位。
3. **响应解析与展示**：增加 analysis-h3.v1 包装解析，旧 analysis JSON 保持可读。分镜按真实切镜分组；提示词框直接采用校验后的 generation_prompt。`buildReplicaPromptText` 仅保留历史数据/缺上下文时的明确非就绪回退，不覆盖已得到的 H3 文本。历史未标记类型的数据显示“分析段/切镜待确认”。
4. **台词核验**：检查全片稿与各段口播拼接是否一致。对听不清标记显示待核对，AI 优化不把它变成看似准确的台词；是否允许用户带待核对内容生成沿用显式提示规则，不能宣称识别已完成。
5. **重新分析回填**：未手改的自动草稿可更新；人工改过的草稿保留，并提供应用新版分析草稿的动作。

这些改动复用现有分析任务、版本和草稿接口，不需要新人物数据库或剪辑引擎。上下文齐全时，一次模型响应完成事实与 H3 文本，不新增自动优化调用。必须记录请求次数；原有 JSON repair 分支改为显式诊断/主动修复，不能保留隐藏二次调用却宣称单次完成。

补充验收：一次分析返回两个结果；模型调用次数为一；READY 无需调用优化接口即可生成；素材缺失不造标签；H3 文本失败不丢失有效分析；更换素材使旧上下文失效；生成请求使用用户最后编辑的文本。

## 五、当前字段的能力边界

- 当前 schema 没有独立说话人表，不能承诺精确的多人说话人绑定；先保留逐段可辨识原文和必要说明，后续多人需求再扩展。
- 当前 schema 没有 OCR/屏幕文字轨道。本稿不要求输出 `on_screen_text`，避免触发 `extra=forbid`。若后续需要完整复刻字幕、信息卡，再同步新增结构化字段与前端展示，而不是把字幕混入 spoken_text。
- 同时说话的交叠音轨，单字符串难以完整表达多条时间线；可辨识内容与不确定性应真实保留，不声称已经完成说话人分离。
- 首帧/人物替换门禁属于后续能力判断，不能要求分析模型隐瞒多人来通过门禁。

本稿的改动重点：一次分析同时获得可信的分镜事实与可用 H3 提示词；格式合格后直接生成，AI 优化只承担可选的再次编辑。素材缺失、格式正确性与成片效果分别验收。
