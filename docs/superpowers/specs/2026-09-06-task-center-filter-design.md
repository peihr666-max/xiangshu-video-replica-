# 任务中心筛选优化（方案 A：单行工具栏）设计文档

日期：2026-09-06 · 分支：`codex/frontend-v1.4` · 状态：已确认（用户拍板方案 A）

## 背景与问题

任务中心当前用上下两排同质化的分段 Tabs 做筛选（状态行 + 类型行，均复用 `Tabs` 组件），
与 V1.4 效果图一致，但体验上有四个问题：

1. 状态（高频）与类型（低频）视觉权重相同，两排各有一个"全部"，维度主次不分；
2. 两排按钮占据约 130px 头部高度，低频的类型筛选撑不起这个权重；
3. 筛选后无结果计数，空结果无"清除筛选"出口；
4. 计数不一致（状态行有、类型行无）。

同行（即梦/剪映创作记录、可灵、HeyGen、Runway）收敛出的共同模式：
高频维度做单排主 Tabs 带计数，低频维度收进右侧下拉，非默认筛选有明确高亮，
配结果计数与空态兜底。

## 方案（已确认）

单行筛选工具栏：状态 Tabs 居左原样保留，类型筛选改为同一行右侧的下拉筛选器。

```
 [全部] [进行中 2] [待处理 1] [已完成]        类型：全部类型 ▾
 共 3 条任务
 ┌ 表格 ────────────────────────────────────────────────┐
```

### 组件与文件

- `client/src/studio/ui.tsx`：新增 `FilterSelect` 组件（与 `Tabs`/`Button` 同居共享 UI 模块）。
  - 触发按钮显示 `类型：{当前值}`，`aria-haspopup="listbox"` + `aria-expanded`；
  - 弹出菜单 `role="listbox"`，选项 `role="option"` + `aria-selected`，选中项带 ✓，右侧显示计数；
  - 首项视为默认项（"全部类型"），选中非默认项时触发按钮加 `is-active` 金色高亮；
  - 交互对齐既有 `RunningRowMenu` 模式：`pointerdown` 点外关闭 + Escape 关闭。
- `client/src/studio/MainPages.tsx` `TasksPage`：
  - 两个 `Tabs` 换成 `<div className="studio-filter-bar">` 单行容器（Tabs 居左 + FilterSelect 居右，窄屏 wrap）；
  - 类型选项仍为 全部/视频复刻/视频生成/数字人口播/人物置换，展示名"全部"→"全部类型"；
  - 下拉计数与状态筛选联动（分类面交互：类型计数 = 当前状态下该类型任务数；"全部类型"计数 = 当前状态任务总数）；
  - 表格上方新增 `共 N 条任务` 结果计数（`role="status"`）；
  - 空结果时沿用既有"当前筛选下暂无任务"空态，并追加"清除筛选"按钮（仅在状态或类型非默认时出现，一键重置两个维度）。
- `client/src/studio/studio.css`：新增 `.studio-filter-bar`、`.studio-filter-select-*`、`.studio-result-count` 样式；
  容器内 `.studio-tabs` 外边距归零；菜单视觉复用 `.studio-row-menu-list` 的深色浮层语言。

### 不变的部分（红线）

- 状态 Tabs 的四个选项、金色激活样式与计数文案（`进行中 2`/`待处理 1` 有测试锁定，`role="tab"` 不变）；
- 表格列结构、行操作（取消任务/查看详情/查看结果）、"新建创作"与"历史任务与下载"动作；
- 类型筛选的业务取值不变（仍是"视频复刻"等中文值），仅控件形态变化；
- 客户侧不出现 API 供应商名称（红线沿用）。

### 测试口径

- 新增（`MainPages.test.tsx` 任务中心 describe 内）：
  1. 类型筛选收进下拉：旧类型行 `role="tab"` 消失；下拉展开可见五个选项并带联动计数；
  2. 选择类型后表格过滤、触发按钮 `is-active` 高亮、结果计数更新；
  3. 无结果组合出现"清除筛选"，点击后两个维度复位、列表恢复；
  4. Escape 与点选外部可关闭下拉。
- 回归：`cd client && npm run check`（biome + tsc + 全量前端 vitest）。
