## 用户端与管理后台分工

| 用户端可以看到/操作 | 仅管理后台配置或处理 |
| --- | --- |
| 抖音、视频号平台切换 | 关键词及关键词组合、任务启停 |
| 视频封面、标题、作者、时长 | API 地址、鉴权、请求/响应字段映射 |
| 接口实际提供的互动信息 | 采集周期、分页、排序与限额 |
| 查看视频、查看来源 | 存储空间、上传策略、访问权限、保留期限 |
| 收藏、用于复刻 | 去重、云端归档、失败重试、采集日志 |
| 简单内容更新时间 | 发布到前端的审核、可见性及素材使用权限 |

不在用户端显示“管理关键词、立即采集、采集记录、每日采集时间、接口状态、云端同步、重试失败项”等运营控件。更新时间只是内容的新鲜度提示，不能更改任务频率。我的收藏是用户个人内容操作，不是采集配置。

## 30 条的展示口径

- 每个平台最多 30 条，分别显示、分别计数，不是两个平台合计 30 条。
- 30 条是本轮的产品展示上限，不推断接口单页数量或全平台排名能力。
- 视觉示例按 6 条/页、共 5 页显示。少于 30 条时用真实数量计算分页，不补假数据。
- 关键词组合、排序与更新批次在后台统一定义。前端不展示接口返回顺序等技术参数。
- 图中展示的是两个平台各有 30 条内容的示例。实际数据字段、排序含义、返回上限及可预览方式，在用户提供接口文档后确认。
- 更新成功后读取已发布的云端内容。后台某次同步失败不让普通用户处理：保留上一批有效内容，由后台解决；没有可展示内容时显示简单空态。

## 视频内容与复刻

列表卡片突出封面、标题、来源与基本互动信息；未返回的指标隐藏或标记“暂无数据”，不伪造为 0，也不据此声称支持某个平台指标。

详情页重点是视频预览、作者和原始来源、简介，以及收藏/用于复刻。正式接入时仅对允许预览的原视频提供内嵌播放；不支持内嵌时保留查看原视频的可用入口。权限验证由后台及服务端完成，普通用户不需要管理存储授权。

“用于复刻”将选定素材带入视频创作流程，仍须走原有的素材授权及人工确认边界，不直接发起付费生成。本图展示可用素材的设计状态，未证明任何真实视频已获得使用许可。

## 后台处理与前端回显关系（方案，不是已实现状态）

管理员配置用户提供的 API 与关键词 → 后台拉取并去重 → 保存视频资料及许可范围内的媒体 → 审核并发布可见内容 → 用户端按平台读取和展示。

资料索引和批次关系用于分页检索；需归档的资料快照、封面及原视频可按许可保存到对象存储。私有文件通过服务端提供的临时地址展示，不把 API 密钥或存储凭证发到浏览器。具体接口和字段等待用户提供后再做映射，本轮不冻结后端 API 结构、不改真实业务代码。

## 审核边界

已交付的是可浏览、可填写审核意见的效果图图册，不是可操作的视频产品前端。未调用真实采集接口；未运行抖音/视频号抓取；未上传真实云存储；未创建定时任务；未调用付费视频生成；未发布或部署业务系统。

接口参数以用户提供为准。本轮不交付管理后台效果图，仅明确其职责；后续可以沿用本分工设计后台。
