# 成本计费与功能扩展需求分析（2026-09-04）

> 来源：所有者 2026-09-04 口头需求（参照众墅之家工作台风格截图与 metaso.cn/minimax-h3 介绍）。
> 本文为需求理解与差距分析；立项时按仓库流程接续 T 编号、测试先行。
> 关键事实依据：`docs/METASO-H3查询真实响应样本.md`（H3 响应含 `usage.output_seconds`；秘塔价 2K 0.15 元/秒、768P 0.09 元/秒）、`server/app/generation.py`（SUPPORTED_RESOLUTIONS、build_h3_request 硬锁 ratio=adaptive）、迁移 022（wallet_transactions 形状 CHECK 锁 RESERVE=-1/+1）。

## 需求 0 · 软件风格 / Logo / 名称对齐参照截图

**理解**：参照"众墅之家 AI 即创"工作台视觉（深炭黑+金色强调、图标+分组侧栏、徽标计数、KPI 卡行、管线阶段进度条"解析→文案→声音→数字人→合成→发布"、任务动态流、人物库卡片）改造我们软件的风格、logo 与名称。
**现状**：管理后台主题本就是深色+金（#131313/#c6a45f，native-style 效果图已同源）；客户端工作台（WorkspaceShell）同为暗色金强调，但导航为平铺 tab，无分组图标侧栏/徽标计数/管线进度组件。
**工作项**：① 客户端工作台改版效果图一套（参照截图布局语言）；② 导航分组+图标+徽标计数组件；③ 生成管线阶段进度组件（解析→分镜→首帧→生成→归档，复用任务状态机）；④ 品牌资产替换（名称/Logo 全局替换点盘点：client 端品牌区、桌面安装包元数据、Tauri 图标）。
**决策点（阻塞）**：新品牌名称与 Logo 素材需所有者提供；当前为"镜序 Studio"。

## 需求 1 · 每日视频成本详细统计

**理解**：管理端能看到每天的视频生成成本（按天、可下钻）。
**现状与差距**：H3 响应已返回 `usage.output_seconds`（真实样本验证），但 `generation_tasks.actual_cost` **全库无写入点**，`estimated_cost` 仅重试路径写入——成本数据当前基本缺失，界面多显示"上游未回传"。H3 不返回金额，只返回秒数。
**工作项**：① 成本落库：任务终态时 成本 = output_seconds × 每秒成本费率（按分辨率分档，来自需求 2 配置），写 `actual_cost` + 成本口径标记（CONFIG_RATE）；② 日聚合查询端点（按天×操作类型×分辨率：次数、秒数、成本；复用 042 的 created_at_utc 索引）；③ 管理端"成本统计"页（表格+趋势，样式复用）。
**依赖**：需求 2（费率配置）、需求 6（秒数口径）。

## 需求 2 · 管理员后台设置每个 API 调用的成本费用

**理解**：管理员可在后台配置每类 API 调用的上游成本单价（视频解析/次、图片生成/张、视频生成/秒 等）。
**现状与差距**：设置基础设施齐备（control settings + 写契约 confirm/reason/Idempotency-Key + 审计），但不存在成本费率配置实体；成本散落在代码估算里。
**工作项**：① "运营成本费率"设置：操作类型（VIDEO_PER_SECOND×分辨率、ANALYSIS、FIRST_FRAME_IMAGE、CHARACTER_SHEET_IMAGE、CHARACTER_VIEW_IMAGE、SOURCE_FRAME_AI_SCORE、SOURCE_FRAME_PROCESS…）→ 单价（分），支持生效时间/版本；② 读写端点（写走契约+审计，auditor 只读）；③ 服务配置页管理区；④ 需求 1/3/6 的计算点统一读此配置。
**决策点**：费率变更是否影响历史任务（建议：任务提交时快照费率，与 resolution/duration 快照同事务）。

## 需求 3 · 成本 / 毛利 / 利润统计表 + 每日对外售价录入

**理解**：管理员录入"每天视频对外生成的费用（售价）"，系统出成本、收入、毛利、利润报表。
**现状与差距**：收入侧=SETTLE 条数×客户单价（customer_unit_price 存在），但 wallet_transactions 不存金额快照，无利润报表实体；无"每日对外售价"实体；credits（条）与分（fen）两套单位需要换算口径。
**工作项**：① 每日对外售价表（date 唯一 + 价格分 + 录入人 + 写契约审计）+ 后台录入 UI；② 收入口径：日收入 = 当日 SETTLE 条数 × 当日对外售价（或按客户实付单价累计——见决策点）；③ 利润报表端点与页面：日维度 成本（需求1）/收入/毛利/利润率 + CSV 导出；④ SETTLE 时落单价快照，避免历史重算漂移。
**决策点**：收入按"每日统一对外售价"还是"客户实际单价"（两者报表可并存：标准收入 vs 实收）。

## 需求 4 · 反推提示词编辑并另存为新提示词

**理解**：AI 反推（拆解参考视频/图）得到的提示词，允许人工编辑，并保存为新的提示词（模板/版本），供后续生成选用。
**现状与差距**：拆解链路产出分镜卡与提示词；`generation_tasks.prompt_version_id` FK 到 `versions` 表、`prompt_snapshot_json` 已存在——提示词版本底座已就绪；缺编辑 UI 与"另存新版本"通道。
**工作项**：① 分析工作台/脚本编辑器内嵌提示词编辑态；② "另存为新提示词"端点（写 versions 表，带来源标记 reverse_prompt/人工修订、作者、审计）；③ 生成启动器的提示词版本选择器（我的保存 + 原始反推结果并列）。
**决策点**：无（底座现成，改动集中前端+一个写端点）。

## 需求 5 · 可设置的比例尺寸与生成数量

**理解**：生成时可设置画面比例/尺寸与一次生成的数量。
**现状与差距**：分辨率 768P/2K 已可选、时长 4–15 秒已可选；**ratio 被服务端硬锁 `adaptive`**（`build_h3_request` 非 adaptive 直接拒绝，generation.py:5553-5565）；视频生成无"一次 N 条"参数。
**工作项**：① ratio 开放：扩展支持集（16:9 / 9:16 / 1:1 / adaptive，以 H3 契约为准），请求校验与 UI 预设选择器；② 生成数量 1–N：一次提交拆 N 个任务入同一批次（逐任务独立幂等/计费/归档），批量进度展示；③ 计费与成本按 N 联动放大；④ 失败重试语义按单条任务不变。
**决策点**：数量上限（建议 ≤4，防误触与配额冲击）。

## 需求 6 · 按秒计费 + 按秒成本后台可设（参照 Metaso H3）

**理解**：计费从"每视频固定 1 条"改为按秒计费；上游每秒成本在后台可配置（对齐秘塔 H3 按秒/按分辨率计价：2K 0.15 元/秒、768P 0.09 元/秒）。
**现状与差距**：现计费=每任务预留 1 条、结算 1 条；**迁移 022 的 wallet_transactions 形状 CHECK 把 RESERVE 锁死为 available -1 / reserved +1**——按秒计费的变量条数会违反该约束；H3 响应有 `usage.output_seconds` 可作结算权威口径；时长字段前端已有（4–15s）。
**工作项**：① 费率配置：对外每秒价（分/秒，按分辨率分档）+ 上游每秒成本（需求 2 实体），后台可改；② 计费模型：预留 = 计划秒数×对外价，结算 = `usage.output_seconds`×对外价（多退少补，沿用 round/fencing/幂等机制不变）；③ **新迁移（055+）放宽 022 形状 CHECK**（RESERVE/SETTLE 允许与秒数成正比的条数；冻结迁移 025–030 不动；红线下追加修复而非篡改）；④ 任务落 duration/秒数与费率快照；⑤ 生成器显示费用预估（秒数×单价）；⑥ 客户钱包页口径文案更新。
**决策点**：切换时点与存量客户兼容（建议"费率配置化过渡"：每秒价=旧单价/标准时长，老任务按旧快照结算）；credit 最小粒度是否需要支持小数（建议保持整数条，价格档位设计成整数条）。

## 依赖与建议顺序

1. 需求 2（费率配置）先行 —— 1/3/6 的公共底座。
2. 需求 6（按秒计费）与需求 1（成本落库）同批（共享秒数口径与迁移）。
3. 需求 3（利润报表）在 1+6 后收口。
4. 需求 4、5 相互独立，可并行插队。
5. 需求 0 客户端改版：名称/Logo 定案后出效果图，再入开发。
