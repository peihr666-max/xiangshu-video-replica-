## 二、本次实现（前后端同步）

### 后端新增：`GET /api/studio/analytics?days=7|30`

- 位置：`server/app/studio_routes.py`，`studio_analytics()` + 路由；测试 `server/tests/test_studio_analytics.py`（6 例，红→绿）。
- 可见性/归属口径与 `/api/studio/stats` 完全一致（超管看全工作台；员工/客户只看本人项目；隐藏批次、被替代任务不计数）。
- 返回：`range_days / today_completed / range_completed / total_completed / daily[{day,completed}]（北京日界补零）/ kind_breakdown[{kind,completed}]（replica/independent/replacement）/ recent_works[≤20 条：task_id,batch_id,project_id,title(项目名),creation_kind,completed_at]`。
- "完成时刻"沿用 stats 的 `updated_at` 口径；双方言（SQLite/PG）可移植，无新表、无迁移。

### 前端改造

- `client/src/api.ts`：`StudioAnalytics` 类型 + `getStudioAnalytics(days)`。
- `client/src/studio/types.ts`：`StudioData` 新增 `analytics7 / analytics30`（双窗口一次拉齐，切档零请求）。
- `client/src/studio/live.ts`：`loadStudioData` 并行拉取双窗口（失败回退 null，与 stats 同模式）；导出 `CREATION_KIND_LABELS`。
- `client/src/studio/AnalyticsPage.tsx` 整页重写：
  - 指标卡：期间成片 / 今日成片 / 成片队列 / 待处理（后两项来自 stats，全部真实）；
  - 播放趋势 → **成片趋势**（整数计数、30 天横轴抽稀）；平台占比 → **任务类型占比**（三通道环图）；
  - 作品表现 → **最近成片**（作品名/类型/完成时间/查看视频跳任务详情）；
  - **删除**：播放量/互动量/收藏量、平台/人物筛选、"再次创作"（无真实数据源，红线不伪造）；
  - 生产空态改为"统计数据尚未就绪"（加载失败或无成片）；示例数据角标仅 DEV 审核模式显示。
- `client/src/studio/fixtures.ts`：审核样例 analytics（与指标卡样例同口径：今日 8、累计 156；最近成片统一指向真实存在的 `task-completed` 保证走查安全）。
- 管理端类型同步：`api.admin.ts` `DashboardSummary` 补齐 9 个缺失字段，删除 `OverviewPage.tsx` 本地补丁类型 `EconomicsSummary`。
- 顺带修复分支基线遗留的 5 个 tsc 错误（3 个测试夹具缺 `materials` 字段、1 个 `GenerationRatio` 类型收窄、1 个属本轮新增已修）。

### 验证

- 服务端：`uv run pytest tests/test_studio_analytics.py tests/test_studio_stats.py` 10 例全绿；`ruff check/format` + `mypy` 干净。
- 前端：`tsc -b` 零错误；受影响 5 个测试套 107 例全绿 + admin 9 例全绿；biome 定向 format/check 干净（唯一 warning 为 StudioWorkspace.test 存量、不门禁）。
- 收尾门禁（提 PR 前执行）：`scripts/pg-fixture.sh start` → `npm run check`（含服务端全量 pytest）→ `scripts/pg-fixture.sh stop`。
