## 2. 空白重建路径（首选恢复路径）

前提：全新隔离目录 + 空 PG16 实例 + 登记制品（镜像三标签 / compose.sha256 / BACKUP-SHA256SUMS）。

1. `deploy/customer/bootstrap-base-image.sh` 构建基底镜像（干净基底 + `uv sync --locked` + compileall + ffmpeg/ffprobe + import 检查 + 违禁实物扫描）。
2. 配置 `deploy/customer/compose.yaml` 环境面：`VIDEO_REPLICA_DATABASE_URL`（PG DSN）、`VIDEO_REPLICA_SETTINGS_KEY`（根密钥，本地 keystore 已随 CW-042-b 退役，**必须显式供给**）、私有 COS 凭据、ffprobe/ffmpeg 路径。
3. `docker compose up -d`：`migrate` 服务一次性 `alembic upgrade head`（唯一 schema DDL 角色），api/worker 以 `depends_on: service_completed_successfully` 等待后启动。
4. 首管：`provision-empty-customer --confirm-empty-database`（与实现逐字一致，见 CW-032 契约测试）。
5. 重建核验：`/health` 健康、迁移 head 与 `alembic heads` 一致、四项配置 fail-fast 未触发。

## 3. 回滚场景矩阵

### 3.1 应用回滚（代码/配置缺陷）
1. `git revert <squash-sha>` 或切回上一镜像标签；2. rollout 重建（§2 步骤 3-5，migrate 幂等无 schema 变更时直接过）；3. NSIS 桌面端回退至上一签名版本（安装器 legacy-backup 归档可恢复旧客户数据目录，凭据命名空间在安装目录外零触碰）。

### 3.2 Schema 回滚（迁移引入缺陷）
- 首选：**PITR 恢复到迁移前时点**（§4），避免链上 downgrade（多步 downgrade 受数据丢失守卫约束：026/044/083/注册凭证等迁移在有数据时拒绝降级——这是设计行为，不是故障）。
- 次选（仅空库/可弃数据）：`alembic downgrade <target>`（对称降级链见 test_postgres_migrations 的降级矩阵注释：自 head 至 025 共 19 步）。

### 3.3 数据回滚（误写/坏数据）
- PITR：`deploy/systemd/video-replica-pitr-backup.{service,timer}` 产生的 base backup + WAL 归档恢复（恢复演练脚本与 fail-fast CLI 校验面：CW-033 drill，GA 触发执行；PITR/RTO/RPO 验收归 CW-048）。
- 恢复后必跑 §5 零态核对（若恢复到空库时点）或对账核对（wallet_transactions 与 recharge_orders/wallets 差额为零）。

### 3.4 发布回滚（签名发布缺陷）
- CW-024 运行手册「回滚与恢复」节：旧版本静默重装 + legacy-backup 恢复；签名验证失败不出制品。

### 3.5 历史数据导入回滚（仅当未来启用数据批次）
- operator 制品内 `sqlite_to_postgres`（只读导入）+ `reconcile_customer_billing`（对账）；导入目标为新库，回滚 = 弃库重建（§2），原 SQLite 环境封存不写。

## 4. 备份与恢复要点

- 备份载体：PITR base backup + WAL 归档（off-site 为 GA 前置条件之一，归 CW-048 核验）。
- 恢复纪律：恢复目标库必须先隔离（独立端口/独立容器），恢复完成后先跑 `pg_checksums`/引用完整性抽查再切流；恢复过程不触碰原库。
- 密钥纪律：`VIDEO_REPLICA_SETTINGS_KEY` 丢失 = provider 配置不可解密（fail-closed）；恢复环境必须持有同一根密钥。本地 OS keystore 已退役（CW-042-b），不存在"机器本机密钥"依赖。

## 5. 新库上线零态核对（CW-038 并入项，每次空白重建/恢复后执行）

1. 无悬挂 RESERVE：`SELECT COUNT(*) FROM wallets WHERE reserved_credits <> 0` = 0（或与未完任务一一对应）。
2. 无未完任务：`generation_tasks` 无 RUNNING/PENDING 残留（或全部可归因于在途批次）。
3. 账本零差额：`wallet_transactions` 汇总（available_delta）与 `wallets.available_credits` 逐户相等。
4. 无悬挂外部回执：recharge_orders 无 PENDING 超时单（或与渠道侧对账一致）。
5. 迁移 head 唯一且等于发布基线（`alembic heads` 单头）。
